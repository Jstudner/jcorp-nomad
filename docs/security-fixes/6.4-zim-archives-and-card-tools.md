# 6.4 ZIM archives and the PC card tools

> **Read [README.md](README.md) first.** Its global power rules apply here, and its cross-workstream decisions override this doc where they differ: **D9** (this workstream implements U's map-pack path confinement and moves the card tools into `tools/card-tools/`) and **D11** (`/zimview/` is the only CORS exception).

> **Problem.** A ZIM archive is a website in one file, and Nomad runs its pages' scripts. Today those scripts run at Nomad's own address (`http://192.168.4.1`). A crafted archive can read the admin page's stored token, reach into `archive.html`, or open an iframe to `/` and call the admin APIs from there. `Origin` equals `Host`, so the cross-site guard lets those calls through. The firmware's ZIM reader also trusts numbers inside the archive. One crafted offset table reads 2 GB past a buffer and reboots the device on every request. Others serve stale PSRAM, which can hold other archives' data. A crafted MIME string injects HTTP headers, and a truncated manifest null-dereferences on every `/zimview` request. On the PC, the card tools `require()` the card's own `assets/nomad-zim.js`, so a tampered card runs code on the PC. `map_packs.py` writes server-supplied paths with no `..` check. The translation runtime and models are fetched without hashes and end up running in Nomad's origin on every phone.
> **Fix.** (1) Every `/zimview/` document gets a `Content-Security-Policy: sandbox …` header without `allow-same-origin`, and the reader's iframe loses `allow-same-origin`. Archive pages still run scripts, but in an opaque origin, where they are strangers to Nomad. `archive.html` and `assets/zim-frame.js` then talk over `postMessage`. A scoped `Access-Control-Allow-Origin: *` on `/zimview/` keeps the archives' own fetches, fonts and module scripts working. (2) `NomadZimCore.h` checks every offset in 64-bit arithmetic against the bytes actually unpacked. Mime strings are cleaned, the manifest parser is bounded, and slot unpins and archive closes can no longer be lost. A host-side test and fuzz harness carries the traced crash inputs. (3) The card tools load only their own hash-pinned `nomad-zim.js`, confine every written or deleted path to the card, and pin downloads by hash. Their source moves into the repo.
> **What users see.** Archive pages look and behave the same, but a web app's saved settings last only while the page is open. The reader's back, forward, contents and fit-to-screen work as before. A malicious archive shows a "could not be read" note instead of rebooting Nomad. The tools refuse a tampered card's script.

## 1. Scope (in / out)

**In**
- ZIM page origin isolation: `NomadZimServe.h` response headers, `archive.html` full and app mode, `assets/zim-frame.js`, `zim-sw.js`, and the ZIM-derived blob URLs and manifest numbers that `archive.html` renders.
- ZIM reader bounds in `NomadZimCore.h`: `Clusters::blob`, `unpackTo`, `rawBlob`, `clusterExtent`, `direntByIndex`, `frameScriptAt`, the frame content size cap and arena loss.
- Robustness in `NomadZimServe.h`: manifest *parsing* (`partsOf`), mime/header sanitising, lost unpin and close messages, orphaned slots, and the `lockedRead` EOF guard.
- A host-side regression and fuzz harness, `tools/zimtest/`.
- Card tools: `zim_indexer.js` loading; path confinement in `map_packs.py` and `map_build.py` (this takes over U §4.6's rules, because this workstream already edits `map_packs.py`); `translate_packs.py` pins; a pip lock; an optional ZIM integrity check; moving the tools' source into `tools/card-tools/`.

**Out**
- **6.2:** which part paths a manifest may name (`nomadZimPartsOk`), and guest writes to `/Archive/.nomad-zim`.
- **6.3:** admin token storage and session lifetime, and pdf.js/epub.js script settings in `openZimDoc`.
- **6.5:** the Host allowlist, global CORS removal, and the rule that refuses `Origin: null` writes (6.5 already specifies it; this doc only depends on it).
- **6.7:** CI wiring, reproducible zip builds and toolchain pins. **U:** where the tools and map packs are hosted.

## 2. Current behaviour (file:line)

**Isolation**
- `NomadZimServe.h:307-316` `pageHeaders()` sets only `connect-src/form-action/base-uri`. There is no `sandbox`, no `script-src` and no framing rule.
- RAW (uncompressed) entries get `pageHeaders(r, host, false)` (`:427`), so an uncompressed `text/html` page gets no CSP at all.
- `:432`: `isPage = type.startsWith("text/html") || indexOf("xhtml")` is case-sensitive, so `TEXT/HTML` and `image/svg+xml` get no CSP.
- `typeOf()` `:298-303` copies the archive's mime string into `Content-Type`. The library does not filter CR/LF (`WebResponses.cpp:171-190` `addHeader`, assembled verbatim at `:207-235`), so a mime `text/html\r\nX: y` injects headers.
- `NomadGuardWeb.h:210` adds `X-Frame-Options: SAMEORIGIN` to every response, through `DefaultHeaders`, copied in `WebResponses.cpp:82-88`. That includes `/zimview/`.
- `archive.html`:
  - Full mode `openFull()` `:2083-2107` sets `sandbox="allow-scripts allow-same-origin allow-forms allow-popups allow-modals allow-downloads"` (`:2101`).
  - App mode `setFrameApp()` `:1312-1577` sets `allow-same-origin allow-scripts allow-downloads` on a srcdoc (`:1563`).
  - The app shim calls `window.parent.__zimBridge`/`__zimOpenFile` directly (`:1409, :1542`).
  - The plain reader (`setFrame` `:1220-1300`, `blankArticleFrame` `:659-667`) uses `allow-same-origin` with no scripts and a `default-src 'none'` meta CSP. That one is safe.
  - `fullPageReady`/`onFullLoad`/`historyBack`/`buildToc`/`scrollToHeading` (`:2113-2191`) reach into `frame.contentDocument` and `contentWindow.history`.
  - `window.nomadZimFrame` (`:2109`) is called by `assets/zim-frame.js:11` through `window.parent`.
- `zim-sw.js:141-150` sets the same weak policy. `fromCard()` (`:161-181`) serves entries over 1 MB with none, and `isPage` (`:110`) is case-sensitive.
- `archive.html:489-490` puts `(a.articleCount||0).toLocaleString()` and `formatSize(a.totalSize)` from the card's manifest into `innerHTML` unescaped. A string value passes straight through.
- `docBlobUrl()` (`:828-832`), `:1028` and `:1792` make same-origin `blob:` URLs typed with the archive's mime. An `image/svg+xml` or `application/xhtml+xml` blob opened in a new tab runs script at Nomad's origin.

**Reader bounds (all reproduced on the host under ASan; see §4.2.9)**
- `NomadZimCore.h:334-369` `blob()`:
  - `unpackTo(*s, (size_t)(b + 2) * s->os)` (`:345`): `b + 2` wraps in `uint32_t`, and the product truncates in a 32-bit `size_t`. `first` (`:349`) is never checked against `s->ob.pos`: `:350` checks `(b+2)*os <= first` only.
  - `:351-352` index `t + (size_t)b*4`. With b=0x20000000, os=4, first=0xFFFFFFF8 that is buf+2 GB, giving LoadProhibited (host: SEGV at `:351`).
  - `en` is checked against `cap` (`:354`) but not against `ob.pos`. `unpackTo()` `:612-640` clamps `need` to `cap` and returns OK once the frame has ended (`:639`, "the caller checks offsets", which it doesn't). So `en` between `ob.pos` and `cap` serves stale arena bytes from earlier clusters or other archives; hookAlloc PSRAM is not zeroed (`NomadZimServe.h:129`). Host repro: a cluster that unpacks to 18 bytes but declares en=4000 returns len=3992.
- `rawBlob()` `:227-240`: `1 + e > csize` (`:237`) wraps at `e = UINT64_MAX`, so `rawSize` becomes about 2^64. The table read is not bounded by the cluster.
- `frameScriptAt()` `:741-762`: the loop `i + tl < n` (`:746`) followed by `p[i + 1 + tl]` (`:751`) reads one byte past the end.
- `open()` `:551-559` takes any declared frame content size. `place()` `:487-501` then frees the arena and both stream decoders for a buffer that could never fit, for example a 9 MB xz retry (`:562-568`) on 8 MB of PSRAM. After that PSRAM usually stays fragmented.
- `NomadZimServe.h`:
  - `~Job` (`:342-349`) sends the unpin as a queue message with a 100 ms wait. When the 192-deep unzip line is full it is dropped ("unpin lost"), and the slot stays pinned forever.
  - `closeArc()` (`:231-234`) drops the close the same way. The `Arc`, its file handles (internal RAM) and its 66 KB of PSRAM leak.
  - If a close arrives while a slot is still pinned, `forget()` (`NomadZimCore.h:396`) leaves the slot holding a deleted `Archive*`. A new `Arc` at the same address then matches `find()` (`:448-451`), so the device serves the wrong archive or touches freed memory if the slot was mid-stream.
- `partsOf()` `:196-219`: `atoi(strchr(at, ':') + 1)` (`:203`) crashes when a truncated manifest ends right after `"idx"`. That happens after a power cut during indexing, and it crashes every `/zimview` request.
- `lockedRead()` `:104` computes `fsize - pos` without checking `pos < fsize`. The current callers never do this, but the guard costs nothing.

**Guard.** `NomadGuardWeb.h:76` lets `Origin: null` writes through on the hotspot. 6.5 changes this (6.5 §4.2, decision 5).

## 3. Threat or failure being fixed (concrete scenarios)

1. **S1, admin takeover through an archive.** The owner downloads `cool-site.zim` from a forum. Its main page runs `fetch` from `parent` and reads `localStorage` for the admin token (where 6.3 has not yet moved it), or it iframes `/`. That frame has no CSP, so it calls `/auth/*` or `/settings`.
2. **S2, reboot loop.** A guest uploads a crafted ZIM where uploads are open (6.2), or a card carries one. Every visit to it crashes the zim or unzip task, so Nomad reboots under everyone.
3. **S3, cross-archive leak.** A small crafted archive's entry declares an end offset past its real data. Nomad sends whatever an earlier cluster left in the arena, for example another archive's text or a private Zimit copy.
4. **S4, header injection.** The mime string `text/html\r\nContent-Security-Policy: …` (or `Refresh:`) rewrites the response. A double CRLF puts attacker bytes in the body ahead of the real `Content-Length`.
5. **S5, slow death.** Under load the unzip queue fills, an unpin is lost, and its 2.3 MB stream slot stays pinned. With two such slots every unprepared archive answers "busy" until reboot. Lost closes leak internal RAM, which counts against the media handler's floor.
6. **S6, the PC runs card code.** Someone runs "Rebuild search index" on a card they were handed. `<card>/assets/nomad-zim.js` is `require()`d in Node with the user's rights.
7. **S7, the PC writes outside the card.** A compromised or spoofed pack index (the `--index` local folder also counts) writes a Startup-folder script on Windows, or `~/.bashrc` on Linux. `remove()` deletes `*.pmtiles` files outside the card.
8. **S8, poisoned translation runtime.** A tampered CDN response or a changed HF `main` branch puts a script onto the card, and `translate.html` imports it on every phone with Nomad's origin.

## 4. Design

### 4.1 Origin isolation: opaque origin through CSP `sandbox` (chosen)

#### 4.1.1 How it works and what changes for pages
- **Opaque origin.** A response header `Content-Security-Policy: sandbox allow-scripts …` without `allow-same-origin` gives the document an opaque origin ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox)). It works the same whichever way the page is opened (iframe, new tab, popup), and the header form is supported in every browser since 2016, which covers iOS 10+.
- **Frames inside the page.** A frame such a page creates inherits its active sandboxing flags. The HTML standard's creation flags include "the embedder's node document's active sandboxing flag set" ([HTML §7.1.5](https://html.spec.whatwg.org/multipage/browsers.html#sandboxing)). So the "iframe `/` and call the admin API" bypass gets an opaque document too. The page policy (§4.1.2) already refuses frames outside `/zimview/`, and a reader frame that navigates itself to `/` keeps the iframe's `sandbox` attribute.
- **Popups.** Popups carry the flags, because `allow-popups-to-escape-sandbox` is deliberately left out. That differs from kiwix-serve's policy ([libkiwix](https://github.com/kiwix/libkiwix/blob/main/src/server/internalServer.cpp)).
- **Fetches.** The page's fetch, XHR, fonts and module scripts to `/zimview/` become cross-origin requests with `Origin: null`, which is why `Access-Control-Allow-Origin: *` is needed (§4.1.2).
- **Storage.** `localStorage`, `sessionStorage` and `document.cookie` throw `SecurityError` in an opaque origin. `zim-frame.js` installs in-memory stand-ins (§4.1.4). This also lets Zimit 2 pages work, because their `wombat` reads `window.localStorage` at start and replaces it with its own getter ([wombat.js `initStorageOverride`](https://github.com/webrecorder/wombat/blob/main/src/wombat.js)).
- **Workers.** `new Worker('/zimview/…')` fails from an opaque origin. Archives that use one, for example a bundled pdf.js, fall back or lose that feature (§11, O2).
- **Service workers.** A service worker does not control such a page, and does not even see an `<iframe sandbox="allow-scripts">` navigation ([WPT](https://github.com/web-platform-tests/wpt/blob/master/service-workers/service-worker/sandboxed-iframe-fetch-event.https.html), [Firefox 1437773](https://bugzilla.mozilla.org/show_bug.cgi?id=1437773)). Full mode through `zim-sw.js` therefore cannot be isolated, so it stays only on the online demo (§4.1.6). Zimit 2 no longer needs a service worker ([zimit README](https://github.com/openzim/zimit/blob/main/README.md)).
- **What kiwix-serve does.** It sends `default-src 'self' …; sandbox allow-scripts allow-same-origin allow-modals allow-popups allow-popups-to-escape-sandbox allow-forms allow-downloads` on `/content` and `ACAO: *` on everything. It skips the CSP for PDFs so Chromium can show them ([libkiwix](https://github.com/kiwix/libkiwix/blob/main/src/server/internalServer.cpp), [response.cpp](https://github.com/kiwix/libkiwix/blob/main/src/server/response.cpp)). kiwix-serve has no privileged APIs on its origin, so it keeps `allow-same-origin`. Nomad has them, so it can't.

#### 4.1.2 Firmware headers on `/zimview/` (`NomadZimServe.h`)
`pageHeaders()` is replaced by `zimHeaders(r, host, kind, page)`. Every response built in `build()` (`:367-459`) calls it, including NOTE and REDIRECT. The plain `request->send(503/404, …)` replies in `onRequest()` (`:656-681`) go through the same helper.

| `nzim::mimeKind(cleanMime)` | `Content-Security-Policy` | frame script | Cache-Control |
|---|---|---|---|
| `PAGE`: `text/html`, `application/xhtml+xml` (case-insensitive, params stripped) | page policy (below) | injected (PACKED only, as now) | `no-store` |
| `DOC`: `image/svg+xml`, `text/xml`, `application/xml`, `*+xml`, `text/xsl` | page policy | no | `private, max-age=600` |
| `PDF`: `application/pdf` | none (kiwix parity; Chromium's viewer refuses sandboxed PDFs, [Chromium bug](https://groups.google.com/a/chromium.org/g/chromium-bugs/c/z5hA0H6LFws)) | no | `private, max-age=600` |
| everything else, NOTE pages, RAW of any other type | `sandbox` (no scripts, opaque) | no | as now |

Every `/zimview/` response, including 302s and errors, also gets these headers:
- `r->removeHeader("X-Frame-Options")`. The HTML standard checks `SAMEORIGIN` against the *response's* origin, which is opaque here, and against every ancestor ([HTML §7.7](https://html.spec.whatwg.org/multipage/speculative-loading.html#the-x-frame-options-header)). That would block the reader's own frame and every nested archive frame. No `frame-ancestors` rule is set either: it cannot match an opaque ancestor. Clickjacking an archive page achieves nothing.
- `Access-Control-Allow-Origin: *`, with no credentials, ever. Redirects need it too, because CORS is checked on each hop.
- RAW only: `Access-Control-Expose-Headers: Content-Range, Accept-Ranges`.
- `X-Content-Type-Options: nosniff` stays.

`Deferred` (`:463-495`) is built with the default headers, and `begin()` copies them into `_inner` (`:480`). The constructor calls `removeHeader("X-Frame-Options")` so the header can't come back that way.

**Page policy.** It is built once per Host value, on the network task only, into one 640-byte PSRAM block allocated in `nomadZimRegister()` (`g_pol` = bytes 0–575, `g_polHost` = bytes 576–639):
```cpp
// The policy every archive document gets. "sandbox" without allow-same-origin: the page's
// scripts run, but at an opaque origin, a stranger to Nomad (no storage, no reaching into
// archive.html, no same-origin reads of /api). Sources name the host outright, never 'self':
// Firefox matches 'self' against the opaque origin of a sandboxed page (bug 2019949).
static const char *zimPolicy(const String &host) {
  if (strcmp(host.c_str(), g_polHost) == 0) return g_pol;            // the usual case
  bool ok = host.length() > 0 && host.length() < 64;
  for (size_t i = 0; ok && i < host.length(); i++) ok = isalnum((uint8_t)host[i]) || strchr(".-:[]", host[i]);
  String fb;                                                       // never used once 6.5 is in
  if (!ok) fb = WiFi.isConnected() ? WiFi.localIP().toString() : WiFi.softAPIP().toString();
  const char *h = ok ? host.c_str() : fb.c_str();
  snprintf(g_pol, 576, "sandbox allow-scripts allow-forms allow-popups allow-modals allow-downloads; "
           "default-src http://%s/zimview/ http://%s/assets/zim-frame.js data: blob: 'unsafe-inline' 'unsafe-eval'; "
           "form-action http://%s/zimview/; base-uri http://%s/zimview/", h, h, h, h);
  strlcpy(g_polHost, host.c_str(), 64);
  return g_pol;
}
```
6.5's Host allowlist means `host` can only be one of Nomad's own names. The character check is defence in depth. `default-src` is limited to `/zimview/` plus the one helper script, so an archive cannot probe card files or load anything from the internet in WiFi Mode.

**Preflight.** Safari still preflights `fetch()` with a `Range` header ([WebKit 231174](https://bugs.webkit.org/show_bug.cgi?id=231174)). jQuery in an opaque page also adds `X-Requested-With`, because it thinks the request is same-domain. So the route `server.on("/zimview/*", HTTP_OPTIONS, …)` answers `204` with:
```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, HEAD, OPTIONS
Access-Control-Allow-Headers: Range, Content-Type, Accept, X-Requested-With
Access-Control-Max-Age: 600
```
6.5's `NomadFrontHandler` takes every OPTIONS. It must leave `/zimview/` to this route (§9).

**`/api/zimserve`** now returns `"v":2,"iso":1`. It also adds the counters `unpinDeferred`, `closeRetries` and `orphans` (§4.2.7). `zim-sw.js:45-46` and old UIs test `v >= 1`, so they still step aside.

**Accepted LAN exposure.** In WiFi Mode, `ACAO: *` lets a public web page that knows Nomad's IP read archive content: public material and the list of archives held. Chrome 142+ first asks the user before a public site reaches a LAN address ([Chrome LNA](https://developer.chrome.com/blog/local-network-access)). This is the only CORS left once 6.5 lands. Echoing `null` instead would be no stronger, because any site can make a `null` origin with a sandboxed frame. It would also need `Vary: Origin` to stay correct in browser caches.

#### 4.1.3 `archive.html` full mode
- **Gating.** `nomadServesZim()` (`:2053-2056`) returns the JSON, and isolated full mode is used only when `j.iso >= 1`. Otherwise `zimWorker()` is tried only on the online demo (controller `/sw.js`, `:2061`), and everywhere else the reader is the script-less one: on old firmware the isolation headers are missing, so the opaque frame would break or be unsafe. 6.6's UI manifest also sets `minfw` to the first firmware with `iso`.
- **The frame.** `openFull()` sets `sandbox="allow-scripts allow-forms allow-popups allow-modals allow-downloads"` (`allow-same-origin` removed; the demo keeps the old flags, since it is same-origin and runs on a website rather than a device). It also sets `allow="fullscreen; autoplay; picture-in-picture"` and `allowfullscreen`, because a cross-origin frame otherwise loses fullscreen for TED and YouTube videos.
- **`window.nomadZimFrame` goes.** One `message` listener replaces it:
```js
// archive pages run at an opaque origin (NomadZimServe zimHeaders), so they and this page
// talk only by message. Trust only the frame we made, only plain fields, and only as text
window.addEventListener('message', (e) => {
  const f = document.getElementById('article-frame');
  if (!_fullOn || !f || e.source !== f.contentWindow) return;
  if (e.origin !== 'null' && e.origin !== location.origin) return;   // location.origin: demo only
  const d = e.data; if (!d || d.nomadZim !== 1 || typeof d.type !== 'string') return;
  if (d.type === 'ready') { hideOverlay(); setArticleTitle(String(d.title || '').slice(0, 200));
    frameSay({ type: 'fit' }); updateHistoryButtons(); }
  else if (d.type === 'external') readerNote('That link is on the live web, not in this archive.');
  else if (d.type === 'toc' && Array.isArray(d.items)) renderToc(d.items.slice(0, 500));
  else if (d.type === 'open-doc' && /^\/zimview\/\d+\/[^?#]*$/.test(String(d.path))) openFullDoc(String(d.path));
});
// an opaque frame can't be named as a target origin; nothing sent to it is private
function frameSay(m){ try { m.nomadZim = 1; document.getElementById('article-frame').contentWindow.postMessage(m, '*'); } catch(e){} }
```
- **What else changes.**
  - `fullPageReady()`'s fit pass moves into `zim-frame.js`. `onFullLoad()` becomes `frame.onload = hideOverlay`: a cross-origin frame cannot be inspected, and a live-web link is already stopped by `zim-frame.js`.
  - When `_fullOn`, `historyBack/Forward()` call `frameSay({type:'back'|'forward'})`, `buildToc()` calls `frameSay({type:'toc'})` and `scrollToHeading(i)` calls `frameSay({type:'scroll-to', i})`. `renderToc(items)` builds rows with `escapeHtml(String(item.text))` and a level clamped to 1–4.
  - `openFullDoc(path)` does a same-origin `fetch(path)` from the parent (not sandboxed, so no CORS), then calls `openZimDoc({title, url}, {data, mimeType})`, which shows PDFs and EPUBs in Nomad's viewers (6.3 hardens those).

#### 4.1.4 `assets/zim-frame.js` (rewritten, about 4 KB)
1. **Storage stand-ins first.** These run before any page script: the firmware inserts the tag right after `<head>`.
   - For `localStorage` and `sessionStorage`: `try { window[n].length } catch { Object.defineProperty(window, n, { value: memStore(), configurable: true, writable: true }) }`. It must be `configurable`, because wombat redefines it.
   - `memStore()` implements `getItem/setItem/removeItem/clear/key/length` over an object that lives as long as the page.
   - `document.cookie` gets an in-memory jar of `name=value` pairs, defined only if reading it throws.
2. **Messages.** `const PARENT = location.origin;`. An opaque document still reports its URL's origin, which is the reader's.
   - Outgoing: `tell(m)` does `window.parent.postMessage(m, PARENT)`, only when `window.parent !== window`. A nested archive frame's parent is opaque, so `PARENT` does not match it and nothing is delivered.
   - Incoming: accept only when `e.source === window.parent && e.origin === PARENT && e.data.nomadZim === 1`.
3. **What it sends:**
   - `ready {title}` on DOMContentLoaded.
   - `external` when a live-web link is tapped. The current click logic (`:19-29`) is kept, and `_top`/`_parent` targets still become `_self`.
   - `open-doc {path}` when a tapped link resolves to `/zimview/…` and ends in `.pdf` or `.epub`. Chromium won't show a PDF inside a sandboxed frame.
   - `toc {items:[{level,text}]}`: on request, at most 500 headings, text cut at 200 characters.
4. **What it does on request:** `back`/`forward` call `history.back()`/`forward()`. `scroll-to {i}` scrolls to heading `i`. `fit` runs the fit pass copied from `archive.html` `fullPageReady` and `fitFrameWidth`, using the same `FIT_SCAN_MAX`, the same 1.5 s and 5 s timers and `load`.

#### 4.1.5 App mode (`setFrameApp`, kept, isolated)
- The srcdoc frame gets `sandbox="allow-scripts allow-downloads"`.
- The shim's `bridge(p)` becomes a promise RPC. It posts `{nomadZim:1, type:'get', id, path}` to `parent` with target `PARENT_ORIGIN`. That value is injected as a JSON literal by the parent, because a srcdoc's own origin is opaque.
- The parent answers `{nomadZim:1, type:'got', id, buf, mime}`, or `{…, err}` on failure. The buffer goes in the transfer list, so it is not copied. The parent answers only if `e.source === frame.contentWindow`.
- `__zimOpenFile` becomes `{type:'open-file', path}`.

#### 4.1.8 Rejected alternatives
- **A second port as a separate origin**, for example `:8081`.
  - Memory for the listener itself: `AsyncServer` plus an lwIP listen PCB plus an `AsyncWebServer` with a catch-all and one route is roughly 0.5–1 KB of internal RAM. This is an estimate; no ESP32 build was available to measure it.
  - Connections are the real cost. Browsers keep at most 6 HTTP/1.1 connections per connection group. Each Nomad connection is roughly 1–1.5 KB internal (pcb, `AsyncClient`, request, header Strings) plus send buffers. The firmware notes that "a page load's six connections alone can take DMA memory down to 2.5 KB" (`ino:609-610`).
  - A new port is a new group by definition: Firefox doubles the per-phone ceiling to 12. Chrome may already give an opaque frame its own pool, because pools are partitioned with a cross-site bit, but the reader page is idle while the frame loads. Measure it either way (§7).
  - It would also mean:
    - One origin shared by every archive, which can read each other's storage and DOM.
    - A second listener on the home LAN, needing 6.5's front handler and allowlist duplicated.
    - The same `postMessage` rework, since the frame is cross-origin anyway.
  - Its gains are persistent storage, workers and module scripts without CORS. It stays the fallback in owner decision O2.
- **Per-archive subdomains through Nomad's DNS:** this only works on the hotspot. In WiFi Mode the home router answers DNS.
- **Stricter CSP but same origin:** archive apps need inline scripts and `unsafe-eval`, and no CSP rule hides `parent` or `localStorage` from a same-origin page.
- **Script-less reader only:** this breaks TED, PhET, Gutenberg and Zimit, the reason full mode exists.
- **Echoing `ACAO: null`:** no stronger, and it needs `Vary` (§4.1.2).

### 4.2 Reader bounds and server robustness

All of these are host-testable. `NomadZimCore.h` builds unchanged on a PC (verified with g++ 13, `-Wall -Wextra -Werror`), as long as `<ctype.h>` and `<stdlib.h>` are included. Add both includes to the header.

#### 4.2.1 `Clusters::blob()`
This follows libzim's own rules: the first offset is aligned and at least two offsets long, `n = first/os - 1`, and offsets never decrease ([libzim cluster.cpp](https://github.com/openzim/libzim/blob/main/src/cluster.cpp)). A prototype of this code passes every vector in §7.1.
```cpp
  static const uint64_t MAX_CLUSTER = 32ull << 20;   // no libzim cluster is near this; xz's old cap
  int blob(Archive &a, uint32_t c, uint32_t b, const uint8_t *&data, size_t &len, Slot *&slot) {
    slot = nullptr;
    Slot *s = find(a, c);
    size_t need = 0;
    for (int attempt = 0; attempt < 3; attempt++) {
      if (!s) { int r = open(a, c, need, s); if (r != OK) return r; }
      s->used = ++_tick;
      const uint64_t os = s->os;
      // 1. the first offset says how long the offset table is, so how many blobs there are.
      //    Every test is on bytes actually unpacked (ob.pos), never on the buffer's size
      int r = unpackTo(*s, (size_t)os);
      if (r != OK || s->ob.pos < os) { drop(*s); return r == OK ? BAD : r; }
      const uint8_t *t = s->buf;
      const uint64_t first = os == 8 ? u64(t) : u32(t);
      if (first % os || first < 2 * os || (uint64_t)b + 2 > first / os) { drop(*s); return BAD; }
      const uint64_t tableEnd = ((uint64_t)b + 2) * os;          // <= first: blob b is in the table
      if (tableEnd > s->cap) {                                   // a table longer than the buffer
        if (tableEnd > MAX_CLUSTER) { drop(*s); return BAD; }
        if (s->pins) return BUSY;
        need = (size_t)tableEnd + 4096; drop(*s); s = nullptr; continue;
      }
      r = unpackTo(*s, (size_t)tableEnd);
      if (r == TOO_BIG && !s->pins) { need = s->cap * 2; drop(*s); s = nullptr; continue; }
      if (r != OK || s->ob.pos < tableEnd) { drop(*s); return r == OK ? BAD : r; }  // ended inside its own table
      const size_t at = (size_t)((uint64_t)b * os);              // < tableEnd <= cap: fits any size_t
      const uint64_t st = os == 8 ? u64(t + at) : u32(t + at);
      const uint64_t en = os == 8 ? u64(t + at + 8) : u32(t + at + 4);
      if (en < st || st < first) { drop(*s); return BAD; }
      if (en > s->cap) {                                         // one big script in an unprepared archive
        if (en > MAX_CLUSTER) { drop(*s); return BAD; }
        if (s->pins) return BUSY;
        need = (size_t)en + 4096; drop(*s); s = nullptr; continue;
      }
      r = unpackTo(*s, (size_t)en);
      if (r != OK || s->ob.pos < en) { drop(*s); return r == OK ? BAD : r; }   // past the cluster's end
      data = s->buf + (size_t)st; len = (size_t)(en - st);
      s->pins++; slot = s;
      return OK;
    }
    return TOO_BIG;
  }
```
`unpackTo()` keeps its behaviour. Its last comment becomes "asked past the end: OK with ob.pos short; blob() checks ob.pos". No caller may use bytes past `ob.pos`.

#### 4.2.2 `rawBlob`, `clusterExtent`, `direntByIndex`, `open`
- `rawBlob()` adds no card read: the checks are arithmetic.
```cpp
    const uint64_t os = (info & 0x10) ? 8 : 4;
    if (csize < 1 || 1 + ((uint64_t)b + 2) * os > csize) return BAD;   // the entry pair is inside the cluster
    ... read t at coff + 1 + b*os, (size_t)os * 2 ...
    if (e < s || e > csize - 1 || e - s > 0xFFFFFFFEull) return BAD;   // no wrap; a reply length is a size_t
```
- `clusterExtent()`: return `BAD` when `off >= total` or `next < off`. Clamp `next` to `total`, and return `BAD` when `size == 0`, since the info byte is needed.
- `direntByIndex()`: `if (i >= entryCount) return BAD;`.
- `open()`: when `fcs != UNKNOWN/ERROR` and `fcs > MAX_CLUSTER`, return `BAD` before `place()`.

#### 4.2.3 `frameScriptAt()`
Change the loop to `for (size_t i = 0; i + 1 + tl < n; i++)`, so `p[i + 1 + tl]` always exists. The rest of the function is unchanged.

#### 4.2.4 Mime cleaning (`NomadZimCore.h`, host-tested)
```cpp
// a mime type from the archive, safe in a header: printable ASCII only (no CR/LF: a crafted
```

#### 4.2.5 Manifest parser (moved into `NomadZimCore.h` as `nzim::manifestParts`)
- `jsonStr()` and the `partsOf()` logic move into the core and become bounded. `partsOf()` becomes a one-line wrapper over `g_manBuf/g_manLen`.
- Every search stays inside `[s, s+n)`. The buffer is already NUL-terminated at `n` (`:188`).
- `"idx"` must be followed by optional whitespace, then `:`, then a number parsed with `strtol` and an end check. If not, the parser moves on to the next `"idx"`.
- `"parts"` must lie before the next `"idx"`.
- Each `"path"` must be followed by `:` and `"`. A decoded path must be 1–255 bytes with no NUL; otherwise there are no parts.
- More than 64 parts means no parts (6.2's `NOMAD_ZIM_MAX_PARTS`).
- A manifest cut short gives "no parts", so the archive reads as missing (404 note). 6.2's `nomadZimPartsOk()` then checks the list in `getArc()`.

#### 4.2.6 The arena is never given up for nothing
- **Feasibility check.** In `place()`, before the own-buffer path frees anything (`:489`):
```cpp
    size_t could = sat_add(room(leaveBig), arenaSize());
    for (auto &o : _slots) if (&o != &s && o.a && !o.pins && o.page0 < 0) could = sat_add(could, o.cap);
    if (want > could) return TOO_BIG;     // freeing everything still wouldn't fit it: keep the arena
```
  `sat_add` saturates, because `room()` returns `SIZE_MAX` when there is no hook.
- **Taking it back.** Add `bool reclaim() { return _arena || (bigSize() == 0 && ensureArena()); }`. The unzip task calls it after each job. It costs one largest-free-block query, and only while the arena is missing.

#### 4.2.7 Unpins and closes can't be lost; orphaned slots
- **Unpin counters.** `NomadZimServe.h` keeps one counter per slot (`uint16_t[g_slots]` in PSRAM) behind a `portMUX` in internal RAM. Only plain loads and stores touch external RAM inside the critical section, never atomic read-modify-write.
  - `requestUnpin(slot)` increments the counter and sets `s_unpinAny`. It never blocks.
  - `~Job` calls it whenever it is not on the unzip task. That also removes the up-to-100 ms network-task wait at `:345`.
  - The unzip task calls `drainUnpins()` at the top of every loop pass, including the existing 10 s idle timeout, and inside `closeArcNow()`. `drainUnpins()` clears `s_unpinAny` under the lock, then swaps each counter to 0 and applies `unpin()` that many times.
  - `Clusters` gains `int slotIndex(const Slot*) const` and `Slot *slotAt(int)`. The slot vector never reallocates.
- **Closes.** `closeArc()` tries `xQueueSend(g_uq, …, 0)`. On failure it parks the `Arc*` in `g_closeLater`, a vector owned by the zim task. `task()` retries the parked closes at the top of each pass. No new timer is needed, because the existing 10 s receive timeout wakes it.
- **Orphaned slots.** `Clusters::forget(a)` handles a slot that is still pinned:
  - It sets `orphan = true` and detaches its decoder (`ctx->owner = nullptr; ctx = nullptr`).
  - `find()` skips orphans.
  - `unpin()` drops an orphan when its pins reach 0. The stale `Archive*` is never dereferenced.
- **Counters.** `s_unpinDeferred`, `s_closeRetries` and `s_orphans` are reported in `/api/zimserve`.

- `lockedRead()`: `if (pos >= fsize) { ok = false; break; }` before `k` is computed.

## 7. Tests and acceptance criteria

### 7.1 Host (`bash tools/zimtest/run.sh`, ASan+UBSan, must print 0 failures)
Each vector asserts a return code and that ASan stays silent. A prototype harness in this session confirmed the traced inputs misbehave on today's code: V1 and V3 SEGV at `NomadZimCore.h:351`, V2 returns len 3992 from 18 unpacked bytes, V4 reads uninitialised arena bytes, V5 gives size ≈2^64, and V9 is a heap over-read at `:751`. With the §4.2.1–4.2.3 code all of them return `BAD` and the good-path case still returns its blob.
- **V1:** os=4, `first=0xFFFFFFF8`, b=0x20000000 → `BAD`.
- **V2:** offsets `[8,4000]` over 18 unpacked bytes → `BAD`.
- **V3:** b=0xFFFFFFFF (the `b+2` wrap) → `BAD`.
- **V4:** `first=0x100` with 4 bytes unpacked → `BAD`.
- **V5:** rawBlob with `e=UINT64_MAX`, or a table past the cluster end, or `e-s > 4 GB` → `BAD`.
- **V6:** misaligned `first`, `first < 2·os`, `st < first`, decreasing offsets → `BAD`.
- **V7:** V1–V4 with extended (8-byte) offsets.
- **V8:** a declared frame content size of 64 MB → `BAD`, with no `place()` call.

## 8. Compatibility, rollout and rollback
- **Release together.** Firmware commits 2–7 and UI commits 8–12 go out in one release, with 6.6 `minfw` set to that firmware.
- **Mixed versions.** The `iso` gate keeps a new UI safe on old firmware. Old UI on new firmware is safe but less polished (§7.2.7).
- **Older iPhones.** iOS 10+ honours the header sandbox. iOS < 10 honours only the iframe attribute, so a `/zimview/` page opened in its own tab is same-origin there; this is a documented residual risk. `postMessage` and `Object.defineProperty` on `window` work on every supported iOS.
- **Rollback.** Reflashing the previous firmware restores the old headers, and the new UI then falls back to the plain reader. Restoring the previous UI restores the old reader. No card or NVS data changes, so both directions are clean.
- **Card tools.** The new zip is published with the release and in `SHA256SUMS` (U/6.7). Old tools keep working on new cards but stay vulnerable to S6 and S7, so the release notes advise downloading the tools again.

## 9. Dependencies on other workstreams
- **6.5:** its refusal of `Origin: null` and same-site writes is required (commit 7 lands only if 6.5 has not). `NomadFrontHandler::canHandle` must not take OPTIONS for `/zimview/`: `if (r->method() == HTTP_OPTIONS && !r->url().startsWith("/zimview/")) return true;`, with the Host check still first. 6.5's acceptance grep for "no `Access-Control-Allow-Origin` anywhere" must exempt `NomadZimServe.h`. Its Host allowlist bounds what `zimPolicy()` sees.
- **6.2:** `nomadZimPartsOk()` validates `manifestParts()` output in `getArc()`. Closing guest writes to `.nomad-zim` removes the easiest way to plant a crafted manifest or archive.
- **6.3:** token storage and session lifetime. Isolation removes archive access to storage, but any XSS in Nomad's own pages still matters. pdf.js/epub.js options in `openZimDoc`, which `open-doc` now feeds.
- **6.1:** a password-less "everyone is admin" Nomad makes blind cross-origin GETs worse. Admin GETs such as `/api/wifi-scan` rely on a password existing.
- **6.6:** `minfw` pairing, and `archive.html`/`zim-frame.js` being in the signed UI set.
- **6.7:** CI runs `tools/zimtest/run.sh`, `fuzz_zim` and `-m32`, rebuilds the tools zip reproducibly and checks it, and publishes `SHA256SUMS`.
- **U:** §4.6's map-pack rules are implemented here. Tools and map packs stay hosted where U decides.

## 10. Pushed to future fixes
- Continuous fuzzing (OSS-Fuzz style) of `NomadZimCore.h` and XZ Embedded.
- Robustness of `nomad-zim.js` (the browser and Node parser) against huge allocations or loops from crafted archives. These are DoS only, since JS is memory-safe.
- Moving the plain reader to an opaque frame. It runs no scripts today, so it is safe as it is.
- A CSP `report-to` endpoint to count broken archive pages.
- Trusted Types and a full `innerHTML` audit of every UI page for card-derived strings, beyond `archive.html` and `menu.html`.
- `fix_videos.py` runs ffmpeg on untrusted media, so ffmpeg's attack surface comes with it.
- `zim_prepare.py` decompressing untrusted clusters in Python (memory bombs).
- Persistent per-archive storage, which would need the second-port design (O2).

## 11. Open decisions for the owner (recommended default first)
- **O1. App mode:** *keep it, isolated with the postMessage bridge.* The alternative is removing it, since full mode covers apps on new firmware.
- **O2. Isolation model:** *opaque origin by CSP sandbox, with in-memory storage stand-ins.* If testing finds many archives broken (workers, persistent settings), the fallback is a second port as one shared "archives" origin, with 6.5's front handler on it.
- **O3. CORS on `/zimview/`:** *`*` in both modes.* The alternative, `*` on the hotspot only, would break full mode in WiFi Mode.
- **O4. Service-worker full mode:** *demo only.* On a device with old firmware the plain reader is used, not the old same-origin full mode.
- **O5. PDFs from archives:** *no CSP, as kiwix does, plus `open-doc` to Nomad's viewer.* The alternative is `sandbox`, after which in-frame PDFs never show in Chromium.
- **O6. Unpinned translation packs:** *refuse them.* The alternative is to warn and continue.
- **O7. `import_zim.py --verify`:** *add it, off by default, using `.sha256` or the internal MD5.*
- **O8. Tools copy on the card:** *keep shipping it, with release `SHA256SUMS` and a README line telling users to get the tools from Releases.*
