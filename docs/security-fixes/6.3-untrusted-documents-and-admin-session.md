# 6.3 Untrusted documents and the admin session

> **Problem.** Opening a PDF or EPUB can run script on Nomad's origin. The PDF reader ships pdf.js 3.11.174 with its eval font compiler on (CVE-2024-4367). The EPUB reader puts chapters in an unsandboxed same-origin frame (the CVE-2021-33040 class). Any script on the origin can read the admin token. "Keep me signed in" is ticked by default and keeps the token in `localStorage` with no expiry, so the script can send it to a guest, who can then rewrite `admin.js` through the file routes or the updater. That is permanent, and it reaches every later visitor. **Fix.** (1) The documents stop running script: pdf.js runs with `isEvalSupported:false`, EPUB chapters are cleaned and get their own CSP, and both reader pages carry a strict `<meta>` CSP without `'unsafe-eval'`. (2) The token leaves JavaScript's reach. It becomes an `HttpOnly; SameSite=Strict` cookie that counts only with an `X-Nomad-Admin` header. Kept sign-ins last 30 days at most. Changing the interface, firmware, password or WiFi needs the password again, a once-per-5-minutes HMAC check. **User-visible effect.** Every admin signs in once more after the update. "Keep me signed in" now means 30 days. A short password box appears before an interface update, a firmware install, a password or WiFi change, or an upload of pages or scripts. Readers look and behave as before.

## 1. Scope (in / out)

**In**
- PDF reader: the pdf.js eval path, error text going into `innerHTML`, and the pdf.js upgrade path for older iPhones.
- EPUB reader: script in chapters.
- A strict CSP on `pdf.html` and `epub.html`.
- An audit of the other viewers. In scope from it: the Workshop Markdown link-filter bypass; HTML and SVG under user folders running on the origin (a firmware `CSP: sandbox` header); a locked-down CSP for the pdf.js worker.
- Admin token transport and storage, session lifetimes, and a password re-check ("confirm") for dangerous actions.
- Migration of existing kept sign-ins.

**Out**
- ZIM page isolation and the card tools: **6.4**.
- Signed updates: **6.6**.
- Upload defaults and guest write rules: **6.2**.
- First run, the end of "no password = admin", and recovery: **6.1**.
- Host allowlist and CORS: **6.5**.
- Build pinning: **6.7**.
- Hosting: **U**.
- A CSP on every other page (needs `admin.html`'s 16 inline handlers refactored): §10.

## 3. Threat or failure being fixed

1. **Guest PDF to admin takeover.**
   - While uploads are on, a guest puts `menu.pdf` (CVE-2024-4367 payload) in `/Files`.
   - The owner opens it, and the script reads `localStorage.nomad_admin_token`.
   - The script posts the token into chat. Chat is a community path, writable by anyone (`NomadGuard.h:174-178`).
   - From their own phone, the guest `POST /save`s a new `/admin.js`, or runs stage+commit. Every later admin session is owned, and the kept token never expires.
2. **The same with an EPUB chapter.** `<img src=x onerror=…>`, `<svg><script>`, or a footnote link `java&#9;script:` in a Gutenberg-looking book.
3. **Riding without theft.** Even with the token hidden, a script on the origin can `fetch('/save', …)` with the admin's credentials while the page is open. That is how the permanent damage is done.
4. **Workshop readme.** `[Manual](\x01javascript:fetch(…))` slips past `workshop.html:884`. It only refuses URLs that start with a letter and have a scheme, but the URL parser strips leading C0 controls.
5. **Loose HTML or SVG.** `/Files/page.html` or `/Gallery/x.svg` copied onto the card, then linked in chat. It runs with the origin, so the token and riding are exposed again.
6. **Sniffed token reused.** On the hotspot, every guest knows the WPA2 PSK. Plain-HTTP tokens can be sniffed and replayed from another phone.

## 4. Design

### 4.1 PDF: harden 3.11.174 now; upgrade path documented

**Minimal fix (ship).** Add `isEvalSupported: false` to `getDocument`.
- [GHSA-wgrm-67xf-hhpq](https://github.com/advisories/GHSA-wgrm-67xf-hhpq) names it as the workaround.
- In 3.11 the non-eval glyph path calls `c[cmd].apply(c, args)` over worker-built commands. The command names are constants, and attacker strings become canvas number arguments, so the injection has nowhere to go.
- The flag also turns off the worker's PostScript (Type 4) function compiler.
- The CSP in §4.3 has no `'unsafe-eval'`, so even a missed path throws. pdf.js's own probe (`FeatureTest.isEvalSupported`) then reads `false`.
- Error text goes in with `textContent`.
- Other pdf.js advisories: [GHSA-hq66-cqwq-w95j / CVE-2026-16633](https://osv.dev/vulnerability/CVE-2026-16633) affects only 5.6.83 ≤ v < 6.2.108 with `enableScripting`. That is a viewer (`web/`) feature Nomad does not ship (no `pdf.sandbox.js`). The [pdf.js advisory list](https://github.com/mozilla/pdf.js/security/advisories) has no other entries.
- Cost: glyphs drawn as paths, and Type 4 shadings, are interpreted rather than compiled. That is slower only on unusual PDFs. Ordinary embedded fonts use `FontFace`.

```js
// assets/nomad-pdf-reader.js (moved from pdf.html:281-596), the getDocument call
// isEvalSupported:false: PDF.js would otherwise turn a font's numbers into JavaScript and run
// it (CVE-2024-4367: a crafted font ran any script on Nomad's address). Off, it draws the same
// glyphs without compiling them. The page's CSP has no 'unsafe-eval' as well, as a backstop.
pdfDoc = await pdfjsLib.getDocument({ range: transport, length: total, rangeChunkSize: CHUNK,
    disableAutoFetch: true, disableStream: true, isEvalSupported: false }).promise;
// ...
const p = document.createElement('p'); p.className = 'error-message'; p.textContent = failMessage(err);
pdfContainer.replaceChildren(p);
```

**Upgrade path (measured; not shipped here).** Minimum Safari for each `legacy/` build, from `ENV_TARGETS` in each tag's `gulpfile.mjs`:

| pdfjs-dist | legacy build min Safari | main + worker (bytes) | notes |
|---|---|---|---|
| 3.11.174 (now, modern) | 15.4 | 320,004 + 1,087,212 | classic `.js` |
| 4.10.38 legacy | 16.4 | 398,237 + 1,417,586 | `.mjs` only, module worker (Safari 15+); modern build needs `Promise.withResolvers` (Safari 17.4) |
| 5.4.624 legacy | 16.4 | 481,423 + 1,128,591 | below CVE-2026-16633 range |
| 6.5.438 (latest, 2026-11-01) legacy | **18** | 537,769 + 1,327,591 | [FAQ: legacy = Safari 18+](https://github.com/mozilla/pdf.js/wiki/Frequently-Asked-Questions) |

- Any upgrade drops iOS 15.x (iPhone 6s, 7, SE 1st gen) from PDF reading. Today those phones work.
- The firmware needs no change for `.mjs`.
- **Recommendation:** ship the hardened 3.11.174 as the only engine now. Later, if the owner wants upstream fixes, add **4.10.38 legacy** under `/assets/pdfjs4/` and pick the engine at load time:
  - Choose 4.10.38 when `try { new RegExp('(?<=a)b') }` succeeds (lookbehind = Safari 16.4) and `'noModule' in HTMLScriptElement.prototype`. Load it with `import('/assets/pdfjs4/pdf.min.mjs')`, which sets `globalThis.pdfjsLib`, and set `workerSrc = '/assets/pdfjs4/pdf.worker.min.mjs'`.
  - Otherwise use 3.11.174 as now. It stays the fallback.
  - The 3.11→4.10 API used here (`getDocument`, `PDFDataRangeTransport`, `getViewport`, `render({canvasContext, viewport})`) is unchanged.
  - Cost: +1.8 MB card space, and +0.4 MB on the first open on capable phones (about 0.4 s at the 8 Mbit/s air budget).
  - See §11 decision 3.

### 4.2 EPUB: clean every chapter and give it its own CSP; no sandbox attribute

**Why no `sandbox`.** epub.js must read and write the frame's DOM (pagination, CFIs, themes, our hooks), so the sandbox would have to be `allow-same-origin` without `allow-scripts`. In WebKit that combination blocks event listeners the parent attaches inside the frame. Both [WebKit 218086](https://bugs.webkit.org/show_bug.cgi?id=218086) (srcdoc, "Blocked script execution", still reported on iOS in 2025) and [WebKit 209653](https://bugs.webkit.org/show_bug.cgi?id=209653) are open. On iPhones, tapping and swiping to turn pages, chapter-link handling and epub.js's own resize listeners would all stop. The same applies to upgrading to epub.js 0.3.93 (the latest, 2022-02-16) with its default `allowScriptedContent:false`. `allow-scripts` + `allow-same-origin` is no sandbox at all ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox)).

**Design.** Keep the bundled epub.js. Right after `ePub()` (`epub.html:604`, moving to `assets/nomad-epub-reader.js`), register one hook on `book.spine.hooks.content`. It runs on the parsed chapter `Document` before epub.js serializes it into `srcdoc`, and after epub.js's own `replaceBase`, which is registered in the `Spine` constructor. The hook does two things:
1. **Scrub** what runs or embeds.
2. **Prepend a chapter CSP `<meta>`.** A srcdoc document is parsed as HTML, so a meta that is the first child of `<head>` applies to everything after it. WebKit 218086 comment 5 suggests exactly this as Safari's workaround.

Separately, the page's own CSP (§4.3) is inherited by srcdoc frames in browsers that follow [CSP3's policy-container rules](https://w3c.github.io/webappsec-csp/). That is a third layer, not relied on.

```js
/* Chapters come from whoever made the book. epub.js puts each one in a frame on Nomad's
   address (it has to reach in to lay out pages), so before a chapter becomes the frame's
   text: take out what runs or embeds, then put a CSP first in <head> so anything missed
   still can't run. No sandbox attribute: Safari then drops the page's own tap and swipe
   listeners inside the frame (WebKit bugs 218086, 209653). */
const XHTML = 'http://www.w3.org/1999/xhtml';
const CHAPTER_CSP = "script-src 'none'; object-src 'none'; frame-src 'none'; child-src 'none'; worker-src 'none'; form-action 'none'";
const DROP = ['script', 'iframe', 'frame', 'frameset', 'object', 'embed', 'applet', 'portal'];
const URL_ATTRS = ['href', 'src', 'action', 'formaction', 'data', 'poster', 'background'];
/* nomad-test: scriptUrl */
function scriptUrl(v) {          // a URL that runs script when followed or loaded
  const s = String(v).replace(/[\x00-\x20\x7f]+/g, '').toLowerCase();   // browsers ignore these
  return /^(javascript|vbscript):/.test(s) || /^data:(text\/html|application\/xhtml|image\/svg|text\/xml|application\/xml)/.test(s);
}
/* end nomad-test */
function guardChapter(doc) {
  if (!doc || !doc.documentElement || doc.querySelector && doc.querySelector('meta[data-nomad-csp]')) return;
  for (const tag of DROP) for (const el of Array.from(doc.getElementsByTagNameNS('*', tag))) el.remove();
  for (const el of Array.from(doc.getElementsByTagNameNS('*', 'meta'))) {
    const h = (el.getAttribute('http-equiv') || '').toLowerCase();
    if (h === 'refresh' || h === 'set-cookie') el.remove();
  }
  for (const el of Array.from(doc.getElementsByTagNameNS('*', '*'))) {
    const ln = el.localName;
    if ((ln === 'set' || ln === 'animate') && /href/i.test(el.getAttribute('attributeName') || '')) { el.remove(); continue; }
    for (const a of Array.from(el.attributes)) {
      const n = a.localName.toLowerCase();
      if (n.startsWith('on') || (URL_ATTRS.includes(n) && scriptUrl(a.value))) el.removeAttributeNode(a);   // covers xlink:href
    }
  }
  let head = doc.getElementsByTagNameNS('*', 'head')[0];
  if (!head) { head = doc.createElementNS(XHTML, 'head'); doc.documentElement.insertBefore(head, doc.documentElement.firstChild); }
  const m = doc.createElementNS(XHTML, 'meta');
  m.setAttribute('http-equiv', 'Content-Security-Policy');
  m.setAttribute('content', CHAPTER_CSP);
  m.setAttribute('data-nomad-csp', '1');
  head.insertBefore(m, head.firstChild);
}
// in openEpubReader, right after epubBook = ePub(url, {...}):
epubBook.spine.hooks.content.register((doc) => { try { guardChapter(doc); } catch (e) { console.warn('EPUB guard', e); } });
```

- `<base>` is left alone. epub.js rewrites its `href` to the section URL, and links depend on it. `base-uri` is therefore not restricted.
- CFIs are unaffected: the meta goes inside `<head>`, and `<body>` stays `/4`, so saved positions keep working.
- **Rejected:** DOMPurify on chapter XHTML. It adds about 22 KB, and its HTML profile can mangle `epub:type`, SVG covers and MathML. The browser-enforced CSP does the heavy lifting; the scrub covers browsers without CSP.

### 4.3 Strict CSP on the two reader pages: a `<meta>`, not a firmware header

**Steps**
1. Move each reader script into `/assets/nomad-pdf-reader.js` and `/assets/nomad-epub-reader.js`, loaded at the same position at the end of `<body>`. The `nomad-` prefix gives them `no-cache` plus ETag (`ino:6276-6278`).
2. Delete `epub.html:13-17`.
3. Keep the inline load guard, allowed by hash.
4. Put `<meta charset="utf-8">` first in `<head>`, then the CSP meta, then everything else.

**pdf.html**

```html
<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self' 'sha256-nIw4HLYOZgElmoe/w9gI4ZP6ZuHYh9V9lLDii4UH8vg=' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data: blob:; connect-src 'self'; worker-src 'self'; child-src 'self'; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'">
```

**epub.html**

```html
<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self' 'sha256-nIw4HLYOZgElmoe/w9gI4ZP6ZuHYh9V9lLDii4UH8vg=' 'unsafe-inline'; style-src 'self' 'unsafe-inline' blob: data:; img-src 'self' data: blob:; font-src 'self' data: blob:; media-src 'self' data: blob:; connect-src 'self' blob: data:; frame-src 'self' blob:; child-src 'self' blob:; worker-src 'self'; object-src 'none'; form-action 'none'">
```

**Why each part**
- No `'unsafe-eval'`. That blocks `new Function` (the pdf.js backstop).
- With a hash present, CSP2+ browsers ignore `'unsafe-inline'`, so `onerror=` and injected inline script are blocked. CSP1-only browsers (iOS ≤ 9, [caniuse CSP2](https://caniuse.com/contentsecuritypolicy2): iOS 10+) fall back to `'unsafe-inline'`. They cannot run pdf.js 3.11 anyway.
- `connect-src 'self'` stops `fetch` exfiltration.
- `child-src` covers workers on Safari < 15.5, which has no `worker-src` (BCD 8.1.10).
- `blob:` and `data:` on epub.html are for epub.js's resource replacements, which inherited srcdoc chapters load.
- `epub.html` omits `base-uri` (§4.2).
- `theme-boot.js` injects a `<style>`, and `nomad-icons.js` uses inline SVG. Both are covered by `style-src 'unsafe-inline'`.
- No `eval`, `new Function` or inline-handler strings exist in `theme-boot.js`, `theme-manager.js`, `nomad-icons.js`, `nomad-utils.js`, `nomad-marks.js`, `nomad-readaloud.js` or `jszip.min.js`. In `epub.min.js`, the only `Function("return this")` sits behind `this||` and is unreachable in browsers.

**Why `<meta>`.** It travels with the page through interface updates. Old cards keep working: a firmware header would break pages that still have inline scripts. It costs the device nothing per request. The firmware cannot cheaply know which page version is on the card.

**Rejected:** a firmware CSP header on `pdf.html` and `epub.html`. It would couple firmware and UI versions and break old cards. Hash-allowing the 18–24 KB reader scripts instead of moving them is also rejected: a hash breaks on every edit.

// Readme links: web addresses, mail, places on this page, and paths on Nomad. A control

function safeLink(u) {

**Firmware: HTML and SVG outside the interface run in a sandbox.**
- Add a pure helper to `NomadGuard.h`, so `tools/guardtest` covers it. It is fail-safe: only the exact spellings the interface links to count as trusted, and it makes no allocation.

```cpp
// A page or picture that can carry script, served from where people keep files rather than
// from the interface or the games shelf: the browser shows it on an origin of its own with no
// script (CSP sandbox), so it can't read Nomad's storage or act as the admin. Only the exact
// spellings the interface uses count as trusted; an odd spelling is sandboxed, never trusted.
static inline bool nomadDocNeedsSandbox(const String &path, bool markup) {
  if (!markup) return false;
  if (path.length() > 1 && path.indexOf('/', 1) < 0) return false;            // a root file: the interface
  return !(path.startsWith("/assets/") || path.startsWith("/EmulatorJS/") || path.startsWith("/Games/"));
}
```

- `sendSdFile` (`ino:6199`) gains a trailing `const char *csp = nullptr`. When it is set, `response->addHeader("Content-Security-Policy", csp)` runs on the 200 path only.
- The `onNotFound` file branch (`ino:7128-7130`) passes `nomadDocNeedsSandbox(filePath, mime == "text/html" || mime == "image/svg+xml") ? "sandbox" : nullptr`.
- The CSP `sandbox` directive works in headers only: Safari/iOS 7+, Chrome 25, Firefox 50 ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox), BCD).
- **pdf.js worker:** the `/assets/*` handler (`ino:6977-6987`) passes `"default-src 'none'"` for `/assets/pdf.worker.min.js` (and `.mjs`).
  - In range-transport mode the worker gets data only by `postMessage` and fetches nothing, so this structurally stops a hypothetical worker bug from making same-origin requests, which the new cookie would authorize (§4.5).
  - Browsers that apply the owner's policy to workers instead still get the page CSP. Safari's handling of worker response CSP is **not verified**: drop this line if the on-device test shows pdf.js logging "Setting up fake worker".

### 4.5 Admin session: HttpOnly cookie, header-gated, with lifetimes and confirm

**Transport.**
- A login that asks for it (`"cookie":true` in the body) gets the token only as `Set-Cookie: nomad_admin=<64 hex>; Path=/; HttpOnly; SameSite=Strict[; Max-Age=2592000]`. `Max-Age` is set only when kept. The JSON body is `{"ok":true,"kept":bool,"days":30}` and no longer carries the token.
- The firmware accepts a session when either:
  - the request has **`X-Nomad-Admin: 1` and** a valid `nomad_admin` cookie, or
  - the request has a valid legacy `X-Admin-Token` header (old pages).
- **A cookie without the header never counts.** Forms, links, `<img>`, CSS `url()`, meta refresh and chapter content cannot add headers. A cross-origin `fetch` with a custom header needs a preflight that Nomad never approves (6.5 removes CORS). The existing "no ambient authority" property therefore holds, and 6.5's "GETs carry no admin credential" reasoning stays true.
- No script can read the token, so it cannot be posted to chat or replayed from another phone.
- The cookie has no `Domain`, so it is host-only. Signing in at `nomad.local` vs `192.168.4.1` vs a captive name stays separate, exactly as `localStorage` is today.
- No `Secure` attribute (plain HTTP).
- `SameSite=Strict` needs iOS 12.2+ (BCD). Older iOS still has the header requirement and the guard.

```cpp
// NomadAuthCore.h (new, pure: tools/authtest runs it on a PC, like NomadGuard.h)
// The 32-byte token in a Cookie header ("a=1; nomad_admin=<64 hex>; b=2"), read in place.
static inline bool authCookieToken(const char *h, uint8_t out[32]) {
  static const char K[] = "nomad_admin=";
  for (const char *p = h; p && *p; p = strchr(p, ';')) {
    while (*p == ';' || *p == ' ') p++;
    if (strncmp(p, K, sizeof(K) - 1)) continue;
    const char *v = p + sizeof(K) - 1;
    bool ok = true;
    for (int i = 0; i < 32 && ok; i++) {
      const int a = authNibble(v[2 * i]), b = a < 0 ? -1 : authNibble(v[2 * i + 1]);   // never reads past a NUL
      if (b < 0) ok = false; else out[i] = (uint8_t)(a * 16 + b);
    }
    if (ok && (v[64] == 0 || v[64] == ';' || v[64] == ' ')) return true;
  }
  return false;
}
// A kept sign-in past its time (wall ms from nomadNowMs()). Issued more than a day "in the
// future" means the clock went back: expire it rather than treat it as young.
static inline bool authKeptExpired(int64_t now, int64_t issued, int64_t used, int64_t maxMs, int64_t idleMs) {
  return issued > now + 86400000LL || now - issued > maxMs || (used > 0 && now - used > idleMs);
}
```

**Session record and lifetimes** (`NomadAuth.h:26-33`). Each constant is wrapped in `#ifndef`, so tests can shorten it.

```cpp
#define AUTH_IDLE_MS        (60UL * 60 * 1000)          // not kept: unused this long (unchanged)
#define AUTH_SESSION_MAX_MS (12UL * 60 * 60 * 1000)     // not kept: at most this long at all
#define AUTH_KEPT_MAX_MS    (30LL * 24 * 3600 * 1000)   // kept: at most 30 days (Nomad's clock)
#define AUTH_KEPT_IDLE_MS   (14LL * 24 * 3600 * 1000)   // kept: unused 14 days
#define AUTH_CONFIRM_MS     (5UL * 60 * 1000)           // a typed password covers the next 5 minutes
#define AUTH_CONFIRM_CAP_MS (30UL * 60 * 1000)          // ...extended by use, never past 30 minutes
struct AuthSession {
  uint8_t hash[32];
  uint32_t lastMs, bornMs;            // millis(): idle and 12 h limits (not kept)
  uint32_t confirmUntil, confirmAt;   // millis(): the confirm window, 0 = none
  int64_t issuedWall, usedWall;       // nomadNowMs(): 30-day and 14-day limits (kept)
  uint32_t ip;                        // where it is being used this boot; 0 = not yet (restored)
  bool remember, used, cookie;        // cookie: made for a page that keeps the token as a cookie
};
```

**`authFindSession(request)` (rewrite of `:153-169`)**
- Get candidate tokens: `X-Admin-Token` first, then the cookie if `X-Nomad-Admin` is present. Hash each with `authSha` (hardware SHA-256).
- Read `who = remoteIP` and `now = nomadNowMs()` **before** taking `g_authMux`; `nomadNowMs` takes its own spinlock.
- Under the lock, a matching session:
  - **Not kept:** expired if `millis()-lastMs > AUTH_IDLE_MS || millis()-bornMs > AUTH_SESSION_MAX_MS`. Then `used=false`.
  - **Kept:** expired if `authKeptExpired(now, issuedWall, usedWall, …)`. Then `used=false`, with no write; the next load drops it.
  - **IP bind:** if `ip == 0`, set `ip = who`. Otherwise, if `ip != who`, it is *not a match*. The session is not ended, so a stranger cannot sign the owner out.
  - On success: `lastMs = millis()`. For a kept session whose `now - usedWall > 24 h`, set `usedWall = now` and a local `dirty`.
- After the lock: `if (dirty) authSaveKept();`. That is at most one small card write per kept session per day.
- No `String` is built. The header `value()` and `header()` return `const String&`, and parsing works in place.

**`sessions.json` v2.** `{"v":2,"s":[{"h":"<sha256 hex>","i":<issued ms>,"u":<last use ms>}]}`.
- `authSaveKept()` writes it through `queueConfigWrite`, as now.
- `nomadAuthLoad()` runs after `nomadClockBoot` (keep that order) and restores entries with `ip=0`, `cookie=true` and `confirmUntil=0`, dropping expired ones.
- **v1 files (bare strings) are dropped, then rewritten as an empty v2, and the log reads "[Auth] sign-ins kept by an older version ended: sign in again".** Those tokens lived in `localStorage`, which is exactly what this fixes.

**Login, setup and password (`:245-301`, `:333-359`, 6.1's `/auth/setup`)**
- One helper issues every session: `static void authIssue(AsyncWebServerRequest*, int code, bool remember, bool cookieMode, const char *extraJson)`.
- It calls `authNewSession(remember, cookieMode, who)`. That sets `bornMs`, `issuedWall = nomadNowMs()`, `usedWall = issuedWall` and `ip = who`, and starts a confirm window: `confirmAt = millis()`, `confirmUntil = confirmAt + AUTH_CONFIRM_MS`. Typing the password counts as confirming it.
- It then sends either the cookie reply or the legacy `{"token"}` reply, with `Cache-Control: no-store`.
- Before issuing, a successful login also passes the phone's time: `const double t = d["t"] | 0.0; if (t > 0) nomadClockFromPhone(who, (int64_t)t);`. A single phone only moves the clock forward (`NomadClock.h:84-120`). That keeps the 30 days close to real days.
- Use `"cookie":true`, not `1`: `d["cookie"] | false` is false for a number.

**Logout and sessions (`:303-332`)**
- Logout always adds `Set-Cookie: nomad_admin=; Path=/; HttpOnly; SameSite=Strict; Max-Age=0`.
- `/auth/sessions` adds `"cookie":true` (the feature flag) and `"me":{"kept":bool,"confirmed":<seconds left>}`.

**Confirm (step-up).** `POST /auth/confirm` with body `{"nonce","proof"}`, where `proof = HMAC-SHA256(key, nonce)`, using the same `/auth/challenge` and nonce table as login.
- For a legacy (non-v2) record it accepts `{"password"}`, checked with `authPlainMatches`.
- It needs a valid session. It is throttled through `nomadLoginWaitMs` / `nomadLoginResult` (a wrong proof counts as a wrong guess).
- On success: `confirmAt = millis(); confirmUntil = confirmAt + AUTH_CONFIRM_MS;`. The reply is `{"ok":true,"for":300}`.
- Device cost: one hardware HMAC. PBKDF2 stays on the phone.

```cpp
// The changes that would outlast this visit (the interface, the firmware, the password, who
// can join the WiFi) need the password typed in the last few minutes, not just a session.
// Sessions made for pages from before this release (X-Admin-Token) are not asked: those pages
// can't answer, and could then never install the update that can.
bool checkAdminConfirmed(AsyncWebServerRequest *r) {
  if (!isAdminAuthRequired()) return true;
  const int i = authFindSession(r);
  if (i < 0) return false;
  bool ok;
  portENTER_CRITICAL(&g_authMux);
  AuthSession &s = g_authSessions[i];
  const uint32_t now = millis();
  ok = !s.cookie || (s.confirmUntil && (int32_t)(s.confirmUntil - now) > 0);
  if (ok && s.cookie) {                                   // in use: slide, up to the cap
    const uint32_t cap = s.confirmAt + AUTH_CONFIRM_CAP_MS, next = now + AUTH_CONFIRM_MS;
    s.confirmUntil = ((int32_t)(cap - next) < 0 ? cap : next) | 1;
  }
  portEXIT_CRITICAL(&g_authMux);
  return ok;
}
static void authSendConfirm(AsyncWebServerRequest *r) { authSend(r, 403, "{\"error\":\"Confirm your password\",\"confirm\":true}"); }
```

### 4.6 Rejected alternatives (session)

- **`sessionStorage` only.** Readers open in the same tab, so a document can still read it.
- **In-memory token.** It is lost on every navigation. Admin flows span `files.html`, the upload widget and the theme iframe, so users would sign in on every page.
- **Cookie alone.** It makes forms, links and passive content admin-capable: a new scriptless CSRF surface inside documents.
- **Admin on a second origin or port.** Strong, but a large refactor: captive portal, the guest pages' admin actions, 6.5's Host rules. §10.
- **Binding kept sessions to the IP across restarts.** The hotspot's DHCP leases do not survive Nomad's restart, so every restart would end every kept sign-in. Rebinding on first use after a restart is used instead.
- **TLS.** Not on the device.

### 4.7 Migration of existing cards and devices

- **First boot of the new firmware.** v1 kept sessions are dropped (§4.5) and `sessions.json` is rewritten as v2. That is one write.
- **New UI loaded.** It deletes `localStorage.nomad_admin_token` on every page.
- **Old UI on new firmware.** Legacy header mode, no confirm. It keeps working and can install the update.
- **New UI on old firmware.** The login reply carries `token` (`sessionStorage` only, no "keep"). `X-Nomad-Admin` is ignored.
- **Browser caches.** A browser may keep serving a cached pre-update `/Files/x.html` 200 without the sandbox header for up to its `max-age=86400` (`ino:6273`).

- **6.1.** `/auth/setup` and the firmware `/setup` page issue sessions through `authIssue(..., cookieMode=true)`. Recovery (BOOT button) calls `authEndAll()`. Removing "no password = admin" makes confirm meaningful everywhere; until then `checkAdminConfirmed` returns true without a password.
- **6.2.** Visitor upload defaults. `NomadUI.authHeaders()` and `canUpload()` delegate to `NomadAdmin.headers()`. `isActiveContent` stays the admin-only rule that `nomadWriteNeedsConfirm` builds on.
- **6.4.** The cookie and confirm also limit what a script in a ZIM page could do. ZIM isolation is still needed.
- **6.5.**
  - Its "GETs carry no admin credential" holds: the cookie counts only with `X-Nomad-Admin`, which needs a preflight Nomad never grants.
  - IP binding (§4.5) answers its suggestion. WiFi Mode could use a shorter `AUTH_IDLE_MS` (§11).
  - `GET /settings` returns the **hotspot** password (`settings.wifiPassword`) to an admin (`JcorpNomadProject.ino:7559`). It never returns the home-WiFi password: `GET /api/wifi-mode` only says `staPasswordSet`. A script riding an admin session could still read the hotspot password. Consider returning it only to a confirmed session (`checkAdminConfirmed`) or only on an explicit "show password" request. This is low priority, because anyone on the hotspot already knows that password.
  - If its CORS removal lands first, adjust the `sendSdFile` signature (step 5).
- **6.6.** Gate its commit with `checkAdminConfirmed`. Its signed-manifest staging closes the "stage extra files, wait for the owner's commit" case; until then, stage is gated too. The file-route persistence 6.6 leaves open is closed here by `nomadWriteNeedsConfirm`.
- **6.7.** Add `tools/authtest` and `tools/pagetest` to CI. Pin pdf.js and epub.js by hash.
- **U.** Ship the three new `/assets/` files in the interface release. Write the release note.

## 11. Open decisions for the owner

1. **Kept sign-in lifetime.** Recommended: 30 days absolute and 14 days unused. Alternatives: 7 or 90 days.
2. **End existing kept sign-ins at upgrade.** Recommended: yes. Those tokens sat in script-readable storage.
3. **pdf.js.** Recommended: harden 3.11.174 now (keeps iOS 15.4+). Later options: the 4.10.38-legacy dual engine, or dropping iOS 15 entirely.
4. **Confirm window and list.** Recommended: 5 min sliding, capped at 30 min, for the §4.5 table. Alternative: also gate `/delete` of any folder.
5. **Bind sessions to the phone's address this boot.** Recommended: yes (`NOMAD_AUTH_BIND_IP 1`).
6. **Sandbox HTML and SVG outside the interface and `/Games`.** Recommended: yes. Saved web pages then show without their scripts.
7. **Non-kept absolute cap.** Recommended: 12 h. Optionally 15 min idle in WiFi Mode (6.5).
