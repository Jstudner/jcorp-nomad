# 6.2 Guest write policy

> **Summary.** Today a visitor on the hotspot can create, overwrite, rename and delete files in every media folder by default. The template's `/.system-ui.json` ships `"uploadsDisabled":false`, and the firmware also treats a missing or unreadable config as "uploads on". The guard is a denylist, so files the firmware and pages trust as metadata are ordinary media paths to it. The worst result is a HIGH chain: a visitor `/save`s `/Archive/.nomad-zim/manifest.json` with `/config/settings.json` listed as an archive "part", and `GET /zimview/…` then serves the hotspot password, the home WiFi password and the stored admin key (which `/auth/login` accepts as the credential).
>
> This design does four things:
> 1. The archive server opens only ZIM files directly under `/Archive`, whatever the manifest says.
> 2. The guard becomes an **allowlist**. Visitors may only *add* files to Gallery and Files, write and remove *recipes* in Cookbook, and write their own *live-whiteboard layer* (size- and count-capped). Everything else needs a signed-in admin.
> 3. Visitor writes are **off by default**: for new cards, for a missing or broken config, and (once, with a notice in the admin panel) for existing cards.
> 4. Every path spelling SdFat accepts maps to the same per-page switch.
>
> **User-visible effect.** Upload buttons are hidden for visitors until the admin turns them on. A signed-in admin still sees them. Chat, the whiteboard, the cookbook editor and the admin file browser keep working.

## 1. Scope (in / out)

**In**
- Default for visitor writes: new cards, missing or unreadable config, migration of existing cards.
- The write policy for every file route:
  - `/upload`, `/upload-status`, `/upload-cancel`, `/save`, `/mkdir`, `/rename`, `/delete`.
  - The middleware and upload hook in `NomadGuardWeb.h`, and the pure rules in `NomadGuard.h`.
- An inventory of every card file the firmware or the web UI trusts, with a decision for each.
- Validation of ZIM manifest part paths in the firmware (`NomadZimServe.h`).
- Bounds on the whiteboard, and protection of the config-writer queue from visitor saves.
- Host tests for every new rule.

**Out**
- ZIM page origin isolation, ZIM parser bounds and the robustness of the manifest *parser* (6.4).
- pdf.js/epub.js and the Markdown renderers (6.3).
- Where the admin token is stored (6.3).
- What "no admin password" means (6.1). This design keeps today's `checkAdminAuth()` meaning for the interface and system files.
- Cross-site and Host checks in WiFi Mode (6.5).
- The interface updater's write set (6.6). `isInterfacePath()` is deliberately left unchanged.

## 2. Current behaviour (file:line)

**Defaults**
- `firmware/JcorpNomadProject/JcorpNomadProject.ino:2306`: `String g_uiConfigJson = "{}"`.
- `:2314`: `volatile bool g_guestWritesOff = false`.
- `loadUiConfigFromSD()` `:2395-2406` returns early if the file is missing. It also ignores a file that is empty or 4096 bytes or larger, and the flags stay "on".
  - It stores unparseable text as `g_uiConfigJson`, and `refreshUiFlags()` (`:2339-2352`) returns on a parse error without touching the flags.
  - Result: missing, unreadable or corrupt config means **uploads on**.
- `refreshUiFlags` reads `doc["uploadsDisabled"] | false`. The POST `/api/ui-config` (`:7492-7545`) writes `in["uploadsDisabled"] | false`, so a POST that leaves the key out turns uploads on.
- The template is `SD_Card_Template/.system-ui.json`: `{"hiddenPages":[…],"downloadsDisabled":false,"uploadsDisabled":false,"motd":""}`. It has no `"v"` and no `dlOff`, `ulOff`, `watchOff` or `marksOff`. An admin-panel save writes `"v":1` plus all of those keys.

**Per-page switches**
- `kMenuPages` / `pageBit()` (`:2311-2325`).
- `pageBitForPath()` (`:2327-2336`) takes the first component *as typed*. So `//Files/x`, `/Files./x` and `/ Files/x` (all of which SdFat opens as `/Files/x`) map to no page.
- As a result `guestWritesOffFor()` (`:2337`) does not see a per-page switch for those spellings. That is a per-page bypass while the master switch is on. `downloadsOffFor()` (`:2338`) has the same flaw.
- The admin UI offers per-page upload boxes only for `gallery`, `files` and `cookbook` (`SD_Card_Template/admin.js:1632` `UL_PAGES`). The firmware, however, applies "uploads on" to *every* folder.

**Guard**
- `NomadGuard.h:279-289` `nomadWriteVerdict(raw, isAdmin, guestWritesOff)` is a denylist:
  - NEVER: the root and `/config`.
  - Admin-only: system dotfiles, 8.3 aliases, interface files, active content, root entries.
  - Everything else is allowed unless the switch is off, and community paths ignore the switch.
- `isCommunityPath()` `:172-179` covers `/.chat`, `/.whiteboard` and `/.search-index.json`. There are no name, size or count limits.
- `NomadGuardWeb.h:52-60` lists the write routes (`/delete`, `/rename`, `/mkdir`, `/save`, `/upload-cancel`) and `:90-129` is the middleware.
- `:134-144` `nomadUploadAllowed()` is called from `nomadUploadTarget()` (`ino:6452-6480`) on the first chunk of each file, and from `/upload-status` (`ino:7150`).
- The hook is installed at `ino:8397-8404`. `guestWritesOff` is computed as `guestWritesOffFor(path) && !(isAdminAuthRequired() && checkAdminAuth(request))`.
- `checkAdminAuth()` (`NomadAuth.h:178-181`) is true for everyone when no password is set.

**Handlers**
- `/save` (`ino:7435-7478`):
  - Body up to 256 KB (`NomadLimitHandler`, `ino:4613-4627`).
  - Queued on the 8-slot config writer (`queueConfigWrite`, `ino:2276`), which settings, sessions and the UI config also use.
  - Uses a 2000 ms card wait on the network task (should be `NOMAD_NET_CARD_WAIT_MS`).
- `/mkdir` `ino:7368-7425`. `/upload` `ino:7193-7367`.
  - `/upload` refuses an existing name (409) and creates the parent folder.
  - A visitor who first `/delete`s or `/rename`s a file can therefore replace it.
- `handleRename` `ino:4356-4489` and `handleDelete` `ino:4630-4652` check only `/config` themselves.
- `handleMkdir` `ino:5183-5205` is dead code (never registered). If it were ever registered, it would bypass the guard's route list.

**ZIM**
- `NomadZimServe.h:34` `MANIFEST = "/Archive/.nomad-zim/manifest.json"`.
- `checkManifest()` `:172-193` reloads it when its size changes (looked at no more than every 30 s, and only while `/zimview` is being used).
- `partsOf()` `:196-218` returns whatever `"path"` strings the manifest has.
- `getArc()` `:236-272` opens each with `NomadFile64::open()`. That is plain SdFat (`NomadSD.cpp:362-367`, no decoding), on the "zim" task, where no request URL names the file.
- The card tools only ever write `"/Archive/<name>"` with `<name>` ending `.zim` or `.zimaa`–`.zimzz` (`Nomad-Card-Tools/zim/zim_indexer.js:88-117`, `zim_prepare.py:851`).

**Chat and whiteboard**
- Chat now goes through `/api/chat` (`NomadChat.h:322-389`). The firmware appends to `/.chat/log.jsonl` itself and reads it back at boot (`:203-218`).
- `chat.html:331-334` writes `/.chat/chat_<id>.json` only on firmware without `/api/chat`.
- `menu.html` no longer writes `/.search-index.json` (the cache is in memory, `menu.html:970`).
- The whiteboard (`SD_Card_Template/Games/Whiteboard.html:85-88, 333-372, 460-472`):
  - Writes `/.whiteboard/wb_<6 chars>.json` (at most 24000 characters, checked by the page) and `/mkdir /.whiteboard`.
  - "Clear board" `/delete`s every `wb_*.json`.

## 3. Threat or failure being fixed (concrete scenarios)

1. **HIGH: secrets leak through the ZIM manifest.** On default settings a visitor does the following:
   - `POST /save filename=/Archive/.nomad-zim/manifest.json`, with an archive `{"idx":0,"parts":[{"path":"/Archive/crafted.zim"},{"path":"/config/settings.json"}]}`.
   - Uploads `crafted.zim`, whose raw cluster runs past the end of part 1.
   - Requests `GET /zimview/0/…`.
   - The request URL never mentions `/config`, so `nomadReadBlocked()` never fires, and `settings.json` (hotspot password, home WiFi password, admin key record) is served.
   - With the key, the attacker becomes admin (the login proof is an HMAC over the stored key, `NomadAuth.h:~282`).
   - The same works via `/rename` of an uploaded file into `.nomad-zim/`.
2. **Vandalism.** A visitor deletes or renames films, music and archives (or replaces them via delete + upload), even when an admin password is set.
3. **Poisoned trusted metadata**, with UI- or tool-side effects:
   - `/Gallery/.previews/index.json` (wrong previews).
   - `/Translate/runtime/ort-wasm-simd.wasm`: a WASM module that `translate.html` loads into the Nomad origin. Whether a crafted module can reach arbitrary JS through onnxruntime's Emscripten imports is **not verified**. Treat it as code.
   - `/Translate/manifest.json`: parsed with `JsonDocument` every 30 s by `menuTranslatePacks()`, `ino:4016-4026`, so a huge file means heap churn.
   - `/Maps/*/manifest.json`.
   - `/Archive/.nomad-zim/remap-pending.json`, which the PC tool `zim_engine.py:265` reads.
   - `/Workshop` notes, rendered as Markdown via `innerHTML` (6.3 reviews the renderer).
4. **Unbounded community writes, even with uploads off.**
   - Unlimited files of up to 256 KB in `/.chat`, `/.whiteboard` and `/.search-index.json`.
   - A crafted `/.chat/log.jsonl` (after a delete) is replayed into chat history at every boot, and a huge one slows boot.
   - Visitor `/save`s can fill the 8-slot config queue, so the admin's settings save fails with "Write queue full" (`cfgFailed`).
5. **Fail-open default.** A card whose `/.system-ui.json` is missing, corrupt or larger than 4 KB, or a card unreadable at boot, runs with visitor uploads on.
6. **Per-page switch bypass.** With the master switch on and "Files" off, `POST /upload?dir=//Files` (or `dir=/Files.`) still writes into `/Files`.
7. **Document-script delivery** (6.3's issue). A visitor uploads a PDF or EPUB into `/Files`, and every later reader opens it in `pdf.html` or `epub.html` (`files.html:264-267`).

## 4. Design

### 4.1 Write classes (pure, in `NomadGuard.h`)

| Class | Paths | Who may write |
|---|---|---|
| **Never** | the card root, `/config/**` (any spelling, `nomadReadBlocked`) | nobody, through a file route |
| **Interface and layout** (unchanged rule) | `/.system-*`, 8.3-alias look-alikes, `isInterfacePath` (root files with an extension, `/assets`, `/EmulatorJS`), `isActiveContent` anywhere, root entries except `/.whiteboard` | `checkAdminAuth()`: a signed-in admin, or anyone on a Nomad with no password (until 6.1) |
| **Visitor-offered** | see the verb table below | anyone, while that page's switch is on, if the verb and name are allowed |
| **Everything else** | Movies, Shows, Music, Books, Games, Maps, Archive (including `.nomad-zim`), Translate, Workshop, any other folder, every dot-component path, upload parts | a **signed-in** admin only (a password is set and the request carries its session) |

Visitor verbs (`NomadWriteVerb`):
- `NV_CREATE`: `/upload`, `/upload-status`, `/upload-cancel`.
- `NV_SAVE`: `/save`, which can replace a file, so it is treated as an overwrite.
- `NV_DELETE`, `NV_RENAME`, `NV_MKDIR`.

| Page (`nomadVisitorPage`) | Folder (canonical) | Verbs | Names | Switch |
|---|---|---|---|---|
| `gallery` | `/gallery/**` | CREATE only | no dot component, none of `" * : < > ? \|` | uploads master and not in `ulOff` |
| `files` | `/files/**` | CREATE only | same | same |
| `cookbook` | `/cookbook/**` | CREATE, SAVE, DELETE | same, and extension `md markdown txt json cook` (`cookbook.html:401` `RECIPE_RE`) | same |
| `games` (whiteboard) | `/.whiteboard`, `/.whiteboard/wb_<id>.json` | MKDIR on the folder only; SAVE and DELETE on layers only | `<id>` is 1–16 of `[a-z0-9_-]` | the Games page is not hidden (`g_hiddenMask`) |

How refusals are reported:
- A verb the page doesn't offer gives `NW_ADMIN` (401). For an owner on a password-less Nomad it gives `NW_SET_PASSWORD` (403, "Set an admin password…").
- Switch off gives `NW_GUESTS_OFF` (403).
- A wrong name or type gives `NW_TYPE` (**400**). The uploader already treats 400 as a per-file skip (`nomad-utils.js:1179`), so one bad file doesn't abort the batch.

Prototype, compiled and run against `tools/guardtest` (226 passing, 0 failing). The full prototype is in `…/scratchpad/g62/fw/NomadGuard.h` and `…/scratchpad/g62/guardtest_proto.cpp`; that folder may be gone, and the sketch below is authoritative.

```cpp
enum NomadWriteVerdict : uint8_t { NW_OK = 0, NW_BAD_PATH, NW_NEVER, NW_ADMIN, NW_GUESTS_OFF,
                                   NW_TYPE,            // a visitor page, but not a name/kind visitors may add
                                   NW_SET_PASSWORD };  // no password set: nobody can be told from a visitor
enum NomadWriteVerb : uint8_t { NV_CREATE = 0, NV_SAVE, NV_DELETE, NV_RENAME, NV_MKDIR };
static const int NOMAD_WB_LAYER_MAX = 32 * 1024, NOMAD_WB_MAX_LAYERS = 32,
                 NOMAD_RECIPE_MAX = 64 * 1024, NOMAD_ZIM_MAX_PARTS = 64;

// Takes canonicalPath() output, so every spelling SdFat opens maps to one page and one switch.
static inline const char *nomadVisitorPage(const String &c) {
  if (c.startsWith("/gallery/")) return "gallery";
  if (c.startsWith("/files/")) return "files";
  if (c.startsWith("/cookbook/")) return "cookbook";
  if (c == "/.whiteboard" || c.startsWith("/.whiteboard/")) return "games";
  return nullptr;
}
// helpers: nomadHasDotComponent(c) ("/." anywhere), nomadVisitorNameOk(c) (no " * : < > ? |
// and no dot component), nomadExtOf(c), nomadIsRecipe(c), nomadIsWhiteboardLayer(c),
// nomadVisitorSaveMax(c) (32768 for a layer, 65536 for a recipe, else 0). Use only the
// String calls guardtest's stand-in has: charAt, length, substring, startsWith, indexOf,
// lastIndexOf, == (no endsWith, no !=).

static inline NomadWriteVerdict nomadWriteVerdict(const String &raw, NomadWriteVerb verb,
                                                  bool admin, bool signedIn, bool visitorOn) {
  if (!isCleanWritePath(raw)) return NW_BAD_PATH;
  const String c = canonicalPath(raw);
  if (c == "/") return NW_NEVER;
  if (nomadReadBlocked(raw)) return NW_NEVER;
  const bool adminOnly = isSystemPath(raw) || hasShortNameAlias(raw) || isInterfacePath(raw) ||
                         isActiveContent(raw) || (isRootEntry(raw) && !(c == "/.whiteboard"));
  if (adminOnly) return admin ? NW_OK : NW_ADMIN;        // unchanged rule; 6.1 owns "no password"
  if (signedIn) return NW_OK;
  const NomadWriteVerdict refuse = admin ? NW_SET_PASSWORD : NW_ADMIN;
  const char *page = nomadVisitorPage(c);
  if (!page) return refuse;
  bool verbOk, nameOk;
  if (!strcmp(page, "games")) {
    verbOk = (c == "/.whiteboard") ? verb == NV_MKDIR : (verb == NV_SAVE || verb == NV_DELETE);
    nameOk = verb == NV_MKDIR || nomadIsWhiteboardLayer(c);
  } else if (!strcmp(page, "cookbook")) {
    verbOk = verb == NV_CREATE || verb == NV_SAVE || verb == NV_DELETE;
    nameOk = nomadVisitorNameOk(c) && nomadIsRecipe(c);
  } else {                                               // gallery, files: add only
    verbOk = verb == NV_CREATE;
    nameOk = nomadVisitorNameOk(c);
  }
  if (!verbOk) return refuse;
  if (!visitorOn) return NW_GUESTS_OFF;
  return nameOk ? NW_OK : NW_TYPE;
}
```

Other changes in `NomadGuard.h`:
- `nomadWriteStatus`: `NW_TYPE` gives 400 and `NW_SET_PASSWORD` gives 403. `nomadWriteMessage` gains "Visitors can't add that kind of file here" and "Set an admin password in the admin panel to change that from the web".
- `isCommunityPath()` narrows to `/.whiteboard` only. It is still used by `nomadMakesRootFolder` (`ino:6443`).
- `isInterfacePath`, `isActiveContent` and `isProtectedWritePath` are **unchanged**, so the updater's `nomadUpdatablePath` (`NomadUpdate.h:48-52`) is unaffected.

Why `admin` and `signedIn` are separate:
- With a password set, `admin == signedIn`. Without one, `admin` is true and `signedIn` is false.
- That lets the interface class keep its exact current meaning, while media and metadata need a real session.
- So even on a password-less Nomad, a visitor can no longer write `/Archive/.nomad-zim/**` or delete films.

### 4.2 Wiring (`NomadGuardWeb.h`, sketch)

```cpp
struct NomadGuardHooks {
  bool (*isAdmin)(AsyncWebServerRequest *request);   // checkAdminAuth
  bool (*passwordSet)();                            // isAdminAuthRequired: an admin can be told from a visitor
  bool (*visitorPageOn)(const char *page);          // the admin's switch for one visitor page
  bool (*staMode)();
};
// nullptr hooks fail closed: no password known means not signed in; no switch hook means off.
struct NomadWriteRoute { const char *url; NomadWriteVerb verb; const char *p1; const char *p2; };
static const NomadWriteRoute kNomadWriteRoutes[] = {
  { "/delete", NV_DELETE, "filename", nullptr }, { "/rename", NV_RENAME, "oldname", "newname" },
  { "/mkdir", NV_MKDIR, "dirname", nullptr },    { "/save", NV_SAVE, "filename", nullptr },
  { "/upload-cancel", NV_CREATE, "path", nullptr },
};
static inline NomadWriteVerdict nomadGuardDecide(const String &path, NomadWriteVerb verb, bool admin) {
  const char *page = nomadVisitorPage(canonicalPath(path));
  const bool on = page && g_nomadGuardHooks.visitorPageOn && g_nomadGuardHooks.visitorPageOn(page);
  return nomadWriteVerdict(path, verb, admin, admin && nomadGuardPasswordSet(), on);
}
```

- `nomadUploadAllowed` uses `NV_CREATE`.
- In the sketch, `guestWritesOffFor()` (`ino:2337`) is replaced by:

### 4.4 Default off, and migration (sketch)

- `g_guestWritesOff = true`.
- `g_uiConfigJson` starts as `UI_CONFIG_DEFAULT`:

```json
{"v":2,"hiddenPages":[],"downloadsDisabled":false,"uploadsDisabled":true,"watchOff":false,"marksOff":false,"dlOff":[],"ulOff":[],"motd":""}
```

- A pure decision, host-tested:

```cpp
// fromFile: read at start-up. Anything before v2 (the old template shipped uploads on, older
// firmware saved whatever the switch showed) is read as off; *reset says it had said on.
// From the admin's POST a missing key is off.
static inline bool nomadUiUploadsOff(bool fromFile, int version, bool hasKey, bool saysOff, bool *reset) {
  if (reset) *reset = false;
  if (fromFile && version < 2) { if (reset) *reset = hasKey && !saysOff; return true; }
  return hasKey ? saysOff : true;
}
```

- **Shared builder.** The POST's "rebuild from known keys" (`ino:7511-7529`) moves into `static void uiConfigBuild(JsonVariantConst in, bool fromFile, JsonDocument &out, bool *reset)`, which is used by both the POST and the boot load.
  - It writes `"v":2` and sets `uploadsDisabled` from `nomadUiUploadsOff(fromFile, in["v"] | 0, in["uploadsDisabled"].is<bool>(), in["uploadsDisabled"] | true, reset)`.
  - It adds `"ulReset":true` **in RAM only** when `*reset` is set. The POST never writes it, so it is never saved.
  - In ArduinoJson 7, `StaticJsonDocument` already allocates on the heap, so using `JsonDocument` changes nothing.
- **`loadUiConfigFromSD()`** keeps the default unless the file opens, is between 1 byte and 4095 bytes, and parses as an object. Otherwise it logs "UI config unreadable, visitor uploads stay off". It then stores `uiConfigBuild(…, true, …)` output, not the raw text, so pages always see explicit keys.
- **`refreshUiFlags()`** uses `| true` for `uploadsDisabled`, and sets `g_guestWritesOff = true` on a parse error.
- **No card write at boot.** The migrated config lives in RAM until the admin next saves the Pages card. That save writes v2.
- **Template.** `SD_Card_Template/.system-ui.json` becomes `{"v":2,"hiddenPages":[…unchanged…],"downloadsDisabled":false,"uploadsDisabled":true,"motd":""}`.

### 4.5 ZIM part validation (`NomadZimServe.h getArc`, pure check in `NomadGuard.h`)

```cpp
// stem/suffix of one part: suffix -1 for name.zim, 0..675 for name.zimaa..zimzz
static inline bool nomadZimPartName(const String &raw, String &stem, int &suffix) {
  if (raw.length() == 0 || raw.charAt(0) != '/') return false;
  if (!isCleanWritePath(raw) || nomadReadBlocked(raw) || hasShortNameAlias(raw)) return false;
  const String c = canonicalPath(raw);
  if (!c.startsWith("/archive/")) return false;
  const String name = c.substring(9);
  const int n = name.length();
  if (n < 5 || name.indexOf('/') >= 0 || name.charAt(0) == '.') return false;
  if (name.substring(n - 4) == ".zim") { stem = name.substring(0, n - 4); suffix = -1; }
  else if (n > 6 && name.substring(n - 6, n - 2) == ".zim") {
    const char a = name.charAt(n - 2), b = name.charAt(n - 1);
    if (a < 'a' || a > 'z' || b < 'a' || b > 'z') return false;
    stem = name.substring(0, n - 6); suffix = (a - 'a') * 26 + (b - 'a');
  } else return false;
  return stem.length() > 0;
}
// 1..64 parts: one .zim alone, or one archive's split parts in strictly rising order
struct NomadZimPartCheck { String stem; int first = -2, last = -2, n = 0; bool ok = true; };
static inline void nomadZimPartAdd(NomadZimPartCheck &k, const String &raw) { /* see prototype */ }
static inline bool nomadZimPartsOk(const NomadZimPartCheck &k) { return k.ok && k.n >= 1; }
```

The rules in `nomadZimPartAdd`:
- More than `NOMAD_ZIM_MAX_PARTS` (64) parts makes the list bad.
- A bad name makes the list bad.
- The first part sets the stem and the first suffix.
- Every later part must have `suffix >= 0`, `first >= 0`, the same stem, and `suffix > last`.

In `getArc()`, right after `paths = partsOf(idx)` (`:254`):

```cpp
// The manifest is a file on the card, and these are opened here, on the zim task, where no

for (auto &p : paths) {

}

```

- `getArc` gains a `bool *bad = nullptr` parameter.
- `lookUp()` (`:504`) answers a bad manifest with 404, "This archive's index on the card is damaged. Rebuild it with Nomad-Card-Tools." It is still counted in `s_missing`.
- `/api/zimserve` (`:716`) adds `"badParts"`. There is one `Serial.printf` per archive open.
- Validation runs **at the point of use**, because the card can be edited on a PC or in USB mode, not only through `/save`.
- `\u0000` handling: `jsonStr()` (`:153`) can decode `\u0000` into a NUL byte. The strlen check refuses such names, so the validator and `open()` always see the same C string.

### 4.6 Trusted-card-file inventory and decisions

"Signed-in" below means "signed-in admin only".

| File / tree | Trusted by | Decision |
|---|---|---|

**Rejected alternatives**
- **Extend the denylist** (add `.nomad-zim`, `.previews` and so on). Rejected: every new file the tools add would be visitor-writable by default.
- **Distinguish create from overwrite** with an `exists()` check in the middleware. Rejected: it means a card read on the network task for every write. `/save` is treated as an overwrite instead, and only cookbook and whiteboard get it.
- **Ownership tracking**, so visitors could delete their own uploads. Rejected: it needs card metadata writes (see §10).
- **Count whiteboard layers in RAM.** Rejected: the count drifts when the card is edited elsewhere.
- **Move the ZIM manifest under `/.system-*`.** Rejected: it breaks the card tools and `nomad-zim.js` for no gain over §4.5.
- **Add `.wasm` to `isActiveContent`.** Rejected: that class is open to password-less owners, while the allowlist already makes `/Translate` signed-in only.
- **Persist the migration at boot.** Rejected: it is an unneeded card write, and leaving the file alone keeps rollback trivial.

## 5. Power, memory and performance budget

| Change | CPU | Internal RAM | PSRAM / flash / card | Radio / idle |
|---|---|---|---|---|
| Guard v2 | 0 on GET and streaming. Per guarded write, about +1 `canonicalPath` and some compares (≈5–20 µs; it already folds about 8 times) | transient Strings ≤ ~300 B per write request, freed before the handler. No change per GET. | flash ≈ +2 KB | none |
| `/save` bounds | `uxQueueSpacesAvailable` O(1). A whiteboard layer adds 1 `exists()`, plus a directory walk of ≤32 entries (≈6 sectors, ≈1–3 ms) only on a tab's first save | ≤32 transient `File` objects, one at a time | card: fewer writes (caps) | none |
| Default off and migration | once at boot: parse ≤4 KB JSON, ≈1 ms | ≈2–3 KB transient at boot, freed | flash <1 KB. **No** card or NVS writes. | none |
| ZIM part check | per archive open (not per request): ≤64 × a few short String operations, <50 µs, on the "zim" task (12 KB stack; adds about 50 B of stack) | transient ≤ ~1 KB | flash <1 KB | none |
| Web UI | phone only | — | card +~2 KB of page text | none |

No new tasks, timers, polling or radio traffic. The device does less card work, because there are fewer visitor writes and capped whiteboard writes.

**How to measure**
- Note `/api/health` `heap.heapFree`, `dmaFree` and `memLow` (the minimum free internal DMA heap since boot, `ino:~8335`).
- Run 200 guarded POSTs, for example `for i in $(seq 200); do curl -s -o /dev/null -X POST --data-urlencode filename=/Movies/x.txt --data-urlencode content=x http://192.168.4.1/save; done`.
- Re-read the same fields. `memLow` must not fall by more than 1 KB, and `counts.busyMemory` and `cfgFailed` must not grow.
- Watch `/api/zimserve` `badParts` and `lookupMs`.
- On a `NOMAD_BENCH` build, check the "zim" task's `stackFree` (`NomadBench.h:1041`). It should change by less than 100 B.

## 8. Compatibility, rollout and rollback

**New firmware with the old card UI**
- Pages read `/api/ui-config`, which now always carries an explicit `uploadsDisabled`, so buttons hide correctly.
- There is no banner, and the cookbook works only while the cookbook switch is on.
- An old Whiteboard keeps retrying on 507 with backoff (at most once every 15 s per phone, answered quickly).
- Old `chat.html` uses `/api/chat`, as it already does today.

**Old firmware with the new card UI**
- v2 `uploadsDisabled` has the same meaning under old `refreshUiFlags`.
- The old guard is weaker, but nothing breaks.
- The `admin.js` default (`uploadsDisabled:false`, `:1629`) still matches old firmware.

**Rollout**
- Ship step 1 as a hotfix if 6.6/U allow; steps 2–4 together in one firmware; step 5 through the signed interface channel (6.6).
- Interface updates never touch `/.system-ui.json` (it is a system path), so existing cards rely on §4.4's migration.

**Rollback**
- Old firmware reads v2 files fine.
- If old firmware then saves the Pages card, it writes v1. Going forward again resets uploads to off, with the banner. That is the conservative outcome.

## 11. Open decisions for the owner

1. **Migration of existing cards.**
   - **Recommended:** every config before v2 is read as uploads off, with a one-time admin banner. The old template shipped `false`, so an "explicit" false almost never reflects a choice.
   - Alternative: respect `uploadsDisabled:false` in admin-saved v1 files (those with `"v":1`) and reset only template-shaped files.
2. **Password-less owners and media folders** (until 6.1).
   - **Recommended:** require a password to change media from the web (`NW_SET_PASSWORD`).
   - Alternative: keep today's behaviour for `admin && !signedIn` while the master switch is on.
3. **Visitor documents before 6.3 ships.**
   - **Recommended if 6.2 ships first:** refuse visitor uploads of `pdf epub cbz cbr cb7` and docview types (`files.html:245`) with `NW_TYPE`, behind `#define NOMAD_VISITOR_NO_DOCS 1`, removed when 6.3 lands.
4. **Whiteboard limits.** **Recommended:** 32 layers × 32 KB, tied to the Games page being shown.
5. **Cookbook.** **Recommended:** visitors may edit and delete recipes while the cookbook switch is on (that is the feature). Alternative: create-only.
6. **Gallery and Files.** **Recommended:** add-only (no visitor delete or rename).
