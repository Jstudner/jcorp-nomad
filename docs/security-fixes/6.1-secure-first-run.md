# 6.1 Secure first run: hotspot credentials and admin password

> **Read [README.md](README.md) first.** Its global power rules apply here, and its cross-workstream decisions override this doc where they differ: **D6** (the admin record moves to NVS via 6.5's `NomadSecrets.h`, so BOOT recovery clears it there) and **D7** (`/auth/setup` issues 6.3's cookie sessions once 6.3 lands).

> Today every Nomad starts as WiFi `Jcorp_Nomad` with password `password`, and the README publishes it. Until the owner sets an admin password, **everyone on the WiFi is admin**: they can change the hotspot, make the unit join their own network on every boot, lock the owner out, park it in ROM download mode, or replace `index.html`/`admin.js`. This fix does three things. Each board makes its own WiFi password with the radio on, stores it once, and shows it on the screen as text and as a QR code. "No password" now means "nobody is admin": the first admin password can only be set with an 8-digit code that appears on Nomad's screen when someone asks for it, so a guest who joins first can't take the unit. A forgotten admin password is recovered by holding BOOT for 10 s within 2 minutes of plugging in, which shows a reset code. What users see: new and migrated units show "WiFi / Password" on the screen until the owner has signed in, and the admin page starts with a one-time "Set up Nomad" page. A card still holding `password` gets the board's own password at the first boot (the screen shows it). Existing admin passwords keep working.

## 1. Scope (in / out)

**In:** default and fallback hotspot credentials (generation, entropy, storage, display, migration); removing "no password = admin"; the first-claim flow with a screen code (`/auth/setup-code`, `/auth/setup`, a firmware-embedded `/setup` page); admin password rules (client-side for the v2 flow, server-side for the legacy plain path); turning the password off is no longer possible; BOOT-button recovery; a `nomadAdminPasswordSet()` helper for 6.5; README Quick Start; admin page changes for all of the above.

**Out:** login lockout tuning and per-IP throttle abuse (future fixes, §10). Gating WiFi Mode on a set password, and whether an unclaimed unit may stay in WiFi Mode (6.5). Admin token storage and session lifetime (6.3). Guest upload policy (6.2). Protecting the PBKDF2 key on the air from people who know the WiFi password (future: PAKE, §10).

## 3. Threat or failure being fixed (concrete scenarios)

1. **Published hotspot password.** Anyone in range (a neighbour, a car park, the next table) joins any unit nobody has reconfigured. Today that also makes them admin (scenario 2). Phones that once joined any Nomad keep `Jcorp_Nomad`/`password` saved, so an evil-twin AP with those credentials is joined automatically.
2. **Guest claims admin first.** The owner shares the WiFi at a party before setting an admin password. A guest can then `POST /auth/password` and lock the owner out, `POST /api/wifi-mode {"action":"connect","persist":true}` (`ino:7671-7710`) so the unit joins the guest's AP on every boot, `POST /flash-mode` to leave it in ROM download mode until replugged, or use `/api/update/stage`+`commit` to replace `admin.js`, which persists past a reboot.
3. **Weak admin password.** Online: 4 characters is allowed, and the throttle (`NomadGuardWeb.h:153-201`) lets about 10 guesses a minute through across addresses, so a top-1,000 list falls in about two hours. Offline: anyone who knows the WiFi password and captured the owner's 4-way handshake can decrypt their traffic ([Wireshark](https://wiki.wireshark.org/HowToDecrypt802.11)). From a sign-in they get `nonce` and `proof = HMAC(PBKDF2(pw, salt, 10000), nonce)`. An RTX 4090 runs PBKDF2-HMAC-SHA256 at 8.87 MH/s for 999 iterations ([benchmark](https://gist.github.com/Chick3nman/32e662a5bb63bc4f51b847bb422222fd)), so about 0.9 MH/s at 10,000. Eight lowercase letters (2×10¹¹) fall in about 2.7 days. Ten random lowercase letters take about 5 GPU-years.
4. **Forgotten admin password.** The only recovery today needs a PC and a custom build.
5. **Recovery abused by a passer-by.** Any recovery gesture must be hard to trigger by accident, must be visible, and must not wipe anything by itself.
6. **Weak randomness.** A password made in `loadSettings()` would be made before Wi-Fi starts. ESP-IDF says that after the app starts, output is "pseudo-random only" until Wi-Fi/Bluetooth starts or `bootloader_random_enable()` is called ([ESP-IDF v5.5 RNG](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32s3/api-reference/system/random.html)).
7. **Setup-code guessing.** An attacker on the WiFi, or on the LAN in WiFi Mode, guesses the code without seeing the screen (budget in §4.3).

## 4. Design

### 4.1 Hotspot credentials

- **Format:** 12 lowercase letters in three dashed groups, e.g. `kmpx-rtqe-wnab`. The alphabet has 23 letters (no `i`, `l`, `o`), which gives 23¹² ≈ 2⁵⁴. Against WPA2 handshake cracking at about 2.5–2.7 MH/s per RTX 4090 (hashcat mode 22000, same gist), that is about 220 GPU-years. Letters type on a phone without changing keyboards except for the two dashes. The QR payload `WIFI:T:WPA;S:Jcorp_Nomad-7A3F;P:kmpx-rtqe-wnab;;` is 47 bytes. LVGL's `lv_qrcode_update` uses ECC MEDIUM and grows the version to fill the canvas ([lv_qrcode.c v8.3.10](https://raw.githubusercontent.com/lvgl/lvgl/v8.3.10/src/extra/libs/qrcode/lv_qrcode.c)), so this stays a version-4, 33-module, 4 px/module code at `QR_SIZE` 132: the same as today. iPhones on iOS 11+ join from the Camera app; older ones type the password from the screen.
- **One password per board, made once with the radio on.** `nomadDeviceHotspotPassword()` reads NVS `boot/appw`. If it is missing or invalid, it generates one with `esp_random()` and stores it (one NVS write per board, ever). It is called only in `startNetwork()` **after `WiFi.mode(WIFI_AP)`**: in core 3.3.3 `WiFiGenericClass::mode()` calls `espWiFiStart()` → `esp_wifi_start()` ([WiFiGeneric.cpp](https://raw.githubusercontent.com/espressif/arduino-esp32/3.3.3/libraries/WiFi/src/WiFiGeneric.cpp)), so the RNG is truly random at that point. *Rejected:* `bootloader_random_enable()` in `loadSettings` (I couldn't verify that `bootloader_random.h` links in an Arduino sketch, and it fights with ADC/Wi-Fi). Also rejected: a MAC-derived password (predictable) and a printed label (DIY builds have none). With one password per board, swapping or reformatting a card doesn't change the WiFi password guests already have.
- **When the card's password is replaced** (`g_apPwReplace`, set by `loadSettings`): the key is missing (a new card, or a pre-key old one), the value is exactly `"password"` (the published default, compared case-sensitively), or the length isn't 8–63. **Any other value is kept**: custom passwords and a deliberately open hotspot (`""`) stay as they are. The broader "published" blocklist (`nomadHotspotPasswordPublished`) applies only to *new* input (`POST /settings`, backup restore), so a migration never breaks an owner's own choice.
- **SSID:** a new card, or a card whose default password is being replaced *and* whose SSID is the default `Jcorp_Nomad`, gets `Jcorp_Nomad-XXXX`, where XXXX is the last 2 bytes of the softAP MAC in uppercase hex (the BSSID is broadcast anyway). Phones then see a new network instead of failing on a saved `Jcorp_Nomad`/`password`, and two Nomads in one room are told apart. Custom SSIDs are kept. (Owner decision 2.)
- **Fallback** (`ino:5471-5476`): if the radio refuses the saved name/password, start `nomadDefaultSsid()` + `nomadDeviceHotspotPassword()` (never `"password"`), set `g_apFallback = true`, and don't save.
- **Truth for the screen:** `static char g_apRunningPw[64]` holds what `softAP()` actually accepted. `mainApplyQr()` uses it, replacing the `"password"` literal at `ino:2708`, and the pill uses `WiFi.softAPSSID()` (`ino:6707`).
- **Struct default stays `"password"`** as a sentinel. If a stray `saveSettings()` runs before `startNetwork()` (for example the WiFi Mode cancel path at `ino:5390`), the next boot sees `"password"` and replaces it. A default of `""` would instead persist an **open** hotspot.
- **New-card write:** `loadSettings()` no longer calls `saveSettings(true)` at `ino:2053`. It sets `g_settingsCreateOnly = true`, and the replacement in `startNetwork()` saves with `saveSettings(g_settingsCreateOnly)`. That keeps the "never over a file that is there" rule. If the file was there but couldn't be locked or parsed (`g_settingsParsed == false`, not create-only), the board password is used for this boot and **nothing is saved**, so the owner's real file is never clobbered.
- **Showing it:** new persisted flag `settings.wifiPwNotice` (JSON `"wifiPwNotice"`, default `false`). It is set whenever Nomad picks the password, and cleared the first time a signed-in admin loads `GET /settings` (the Hotspot card then shows the password) or saves a hotspot password. In hotspot mode, while `!nomadAdminPasswordSet() || settings.wifiPwNotice || g_apFallback` ("join info wanted"):
  - the main-screen QR shows **even if `screenQr` is off**;
  - a **join strip** (§4.5) shows `WiFi  <ssid>` / `Password  <pw>` as text at the bottom of the screen, **above status pages**, so first-run indexing doesn't hide it;
  - brightness is at least 30% (`nomadScreenBrightness()`; low-power mode still caps at 30%), so a unit whose screen was turned off can still be set up.
- **New input:** `POST /settings` refuses `nomadHotspotPasswordPublished(pw, ssid)` with `400 {"error":"That WiFi password is published or easy to guess. Choose another."}` **before applying any field**. Open hotspot stays allowed behind the existing confirm (owner decision 5).

### 4.2 Admin: nobody is admin until a password is set

```cpp
// NomadAuth.h
bool nomadAdminPasswordSet() {            // 6.5 gates WiFi Mode on this
  return settings.adminPassword.length() > 0 && settings.adminPassword != "null";
}
bool isAdminAuthRequired() { return nomadAdminPasswordSet(); }   // kept: 6.6 calls it; after this fix
                                                                  // checkAdminAuth() implies it
bool checkAdminAuth(AsyncWebServerRequest *request) {
  return authFindSession(request) >= 0;   // no session, no admin: there is no "no password" pass any more
}
```
- Sessions come only from `/auth/login` (needs a set password), `/auth/setup` (sets one) and `/auth/password` (admin). `nomadAuthLoad()` (`NomadAuth.h:118`) uses `nomadAdminPasswordSet()`.
- `/auth/login` with no password → `409 {"error":"Not set up","setup":true}`.
- `/auth/password {"disable":true}` and `POST /settings {"adminPassword":""}` → `400 {"error":"The admin password can't be removed. Set a new one instead."}`.
- Legacy plain path (`/auth/password {"password"}`, `POST /settings {"adminPassword":"…"}`): refuse fewer than 10 characters, a value equal (case-insensitive) to the hotspot password or SSID, and `nomadHotspotPasswordPublished()` (string compares only). It still runs `authSetPlain` (PBKDF2 on async_tcp); that existing problem is listed in §10.
- `ino:3231` and `ino:8402`: `!(isAdminAuthRequired() && checkAdminAuth(request))` → `!checkAdminAuth(request)`, which is now equivalent. Update the comment at `ino:8399-8400`.
- `/auth/logout` (`NomadAuth.h:305`): `if (me < 0)` → 401.
- **While unclaimed, every admin route answers 401.** That includes restart, shutdown, USB/flash mode, updates, WiFi Mode, settings, brightness, uploads to admin-only paths and the logs. Only physical actions remain (BOOT tap = USB mode, unplugging). Guest features (media, chat, party, captive portal) are unchanged. *Rejected:* allowing "harmless" admin actions before claim. Each one is attack surface, and the owner can claim in under a minute.
- **Password rules (v2 flow, client-side).** The device only receives `{salt, iter, key}` and cannot check strength. The rules live in the pages (`/setup` and `admin.js`): at least 10 characters (owner decision 1), at most 64, not on a short common-password list (entries of 10+ characters from [SecLists Common-Credentials](https://github.com/danielmiessler/SecLists/tree/master/Passwords/Common-Credentials) plus `nomadnomad`, `jcorpnomad`, …, at most 60 entries), not one repeated character, not the SSID, and not the hotspot password. Composition rules are left out, following [NIST SP 800-63B-4 §3.1.1.2](https://pages.nist.gov/800-63-4/sp800-63b/authenticators/), which prefers length plus a blocklist and asks for 15 characters for single-factor use; see decision 1. Only the owner's own browser can get round these rules, and only to harm themselves, so a server check would add nothing. Hint text: "Four or more words in a row is easy to remember and hard to guess."
- **Weak-password nudge:** after a successful sign-in, `admin.js` runs the same rules on the typed password. If it fails them (for example an old 4-character password), it shows a banner "Your admin password is short or common. Change it under Admin password." without blocking.

### 4.3 First claim and reset: the screen code

State lives in `NomadAuth.h`, RAM only, never on the card. All of it is under `g_authMux`, except `g_setupFails`/`g_setupBurns`, which only async_tcp touches.
```cpp
#define SETUP_CODE_MS (10UL * 60UL * 1000UL)   // a code lasts 10 minutes
#define SETUP_TRIES 5                          // wrong codes before it is used up
static char g_setupCode[9];                    // the live code, "" for none
static uint32_t g_setupUntil = 0;              // millis() it goes, 0 = none
static bool g_setupIsReset = false;            // made by the BOOT hold: may replace a set password
static uint8_t g_setupFails = 0, g_setupBurns = 0;
static uint32_t g_setupNextAt = 0;             // no new code before this (after one was used up)
volatile bool g_setupScreenDirty = false;      // UiTask redraws the code / join info
```
| Route | Who | Behaviour |
|---|---|---|
| `GET /auth/challenge` | anyone | Unclaimed: `{"mode":"setup","code":<live>}`. Claimed: as today, plus `"reset":true` while a reset code is live. |
| `POST /auth/setup-code` | anyone | A code is live → `200 {"status":"shown","left":<s>}` (no new code, no screen change). Claimed → `409`. Inside `g_setupNextAt` → `429 {"wait":s}`. Otherwise make a code (`nomadMakeSetupCode(c, rnd32)`, RF is up), show it, log `info "Setup code shown on Nomad's screen (asked by <ip>)"`, `200`. Name chosen so that `/auth/setup` doesn't prefix-match it (`WebServer.cpp:336` matches `uri + "/"`). |
| `POST /auth/setup` body=`{"code","salt","iter","key","remember"}` | anyone | Claimed and no live reset code → `409`. Bad `salt`/`key`/`iter` (same checks as `NomadAuth.h:346-347`) → `400` (not counted as a guess). `nomadLoginWaitMs(ip)` → `429`. No live code → `410 {"error":"No code is showing. Ask for a new one."}`. `nomadCodeMatches()` then `nomadLoginResult(ip, ok)`. Wrong → `++g_setupFails`; at 5 the code is used up (`setupEnd(true)`), which hides it and sets `g_setupNextAt = now + min(60 s << (burns-1), 16 min)`; reply `401 {"error":"Wrong code","left":n}`. Right → `setupEnd(false)`, `g_setupBurns = 0`, `authStoreRecord(authRecordString(iter,salt,key))` (ends **every** session, saves), `g_mainPageDirty = true`, `statusNotice(SI_CHECK, ST_GOOD, "Admin password set", nullptr, 4000)`, log (`warning` for a reset), `200 {"status":"set","token":…}`, then `authSaveKept()` if `remember`. |
| `GET /setup` | anyone | The firmware-embedded page (§4.4), `Cache-Control: no-store`. |
| `GET /admin`, `/admin.html` | anyone | Unclaimed → `request->redirect("/setup")`. Check `nomadAdminPasswordSet()` first, so a claimed unit pays one length check. |

- **Code:** 8 digits, uniform (rejection above 4.2×10⁹), shown as `4829 1375`. The device does no crypto beyond `esp_random()` and a constant-time 8-byte compare. It is also printed on USB serial (`[Auth] setup code 4829 1375`). Whoever holds the USB cable can already reflash the board, and serial helps a unit with a broken screen.
- **Guessing budget:** 5 tries per code, the per-IP and global throttle shared with sign-in, and a used-up code blocks new ones for 60 s, doubling to 16 min. A patient attacker gets about 5 tries per 16 min ≈ 450 a day: P ≈ 4.5×10⁻⁶ per day, about 0.16% per year, and every new code lights the screen where the owner can see it.
- **Why on demand rather than always on screen:** both are equally safe against remote guests, who can't see the screen. On demand keeps the main screen unchanged, makes each code visible as an event, and gives it a 10-minute life. A guest standing at the screen counts as "physical possession", which is the stated trust anchor.
- **Expiry:** UiTask, which already runs every 200 ms (`ino:8540`), calls `nomadSetupExpireTick()` (one compare) and, when `g_setupScreenDirty` is set, redraws under `LvglLock`. No new task or timer.
- **Sniffing (residual):** `/auth/setup` and `/auth/password` carry the PBKDF2 key, which is equivalent to the password, and anyone with the WiFi password plus a handshake capture can read it. At first run the only people with the WiFi password are those who saw the screen. A PAKE/ECDH upgrade is in §10. The code itself is single-use, so sniffing it gains nothing.
- *Rejected:* trust on first use (the first phone wins, which is scenario 2). A BOOT press to claim (conflicts with USB mode, and a code gives a clearer link between phone and device). A claim file on the card (guest-writable folders per 6.2, and it needs a PC). Showing the code permanently.

### 4.4 The `/setup` page lives in the firmware

`firmware/JcorpNomadProject/NomadSetupPage.h`: `static const char kNomadSetupPage[] = R"NOMAD(…)NOMAD";`, about 8 KB, served with `request->beginResponse(200, "text/html", (const uint8_t*)kNomadSetupPage, sizeof(kNomadSetupPage)-1)`. That is the vendored progmem response (`ESPAsyncWebServer.h:732`), read from flash in chunks with no RAM copy. **Why in firmware:** a unit that was unclaimed under the old firmware ("everyone is admin", probably most units) and still has an old card UI could otherwise never claim, because updating the UI (6.6) needs admin. The firmware page works with any card. After the claim, old `admin.js` signs in through v2 as it does today.
- Self-contained: inline CSS in master.css's dark colours, no card assets. Same JS level as `admin.js` (async/await, `TextEncoder`: Safari 10.1 / iOS 10.3+), which the admin page needs straight after setup anyway. Copy `NomadCrypto` verbatim from `admin.js` (I checked it against Python `hashlib`; vectors in §7) between `/*CRYPTO-BEGIN*/…/*CRYPTO-END*/`, and the password rules between `/*RULES-BEGIN*/…/*RULES-END*/` (the same text as `admin.js`, checked by a test).
- Flow: `GET /auth/challenge`. A claimed unit with no reset code shows "Nomad is already set up" and a link to `/admin`. Unclaimed with no code: a button "Show the code on Nomad's screen" → `POST /auth/setup-code`. Then a form: Code (`inputmode="numeric"`, spaces allowed), New password, Confirm, "Keep me signed in" (ticked). On submit: rules → `salt = crypto.getRandomValues(16)`, `iter = 10000` → `pbkdf2` → `POST /auth/setup` (form `body=` JSON, like the other auth routes). Store the token exactly as `admin.js setAdminToken` does (`nomad_admin_token` in local or session storage; follow 6.3 if it changes). Then `GET /settings` with `X-Admin-Token`. If the new password equals `wifiPassword` or `wifiSSID`, show "Guests know the WiFi password. Choose a different admin password" and post `/auth/password {salt,iter,key,remember}`. Finally `location.replace('/admin')`.
- Messages: 401 "Wrong code (n tries left)", 410 "That code has gone. Ask for a new one.", 429 "Wait n seconds", 409 → link to `/admin`. A reset says "Reset the admin password" and "Other devices will be signed out."

### 4.5 Screen

It covers the people icon, count and status switches (cosmetic) while setup is pending, and the bar/footer of status pages.

- Pill: if `lv_txt_get_size(ssid, nomad_font_body) > 140`, use `nomad_font_small`. Check `Jcorp_Nomad-7A3F` in the preview.

### 4.6 BOOT button and recovery

Recovery has to start after reset (GPIO0 low at reset gives ROM download). The rule: **within 2 minutes of a power-on reset** (`esp_reset_reason()==ESP_RST_POWERON`, captured in `setup()` as `g_bootPowerOn`; replug or the board's RESET button, which should log `[BOOT] reset_reason=1 (POWERON)` (check on the board)), **hold BOOT 10 s**. A reset code then shows (`g_setupIsReset = true`, title "Admin reset", log `warning`). Nothing is wiped. The old password keeps working unless someone finishes `/setup` within 10 minutes, and finishing signs every device out, which the owner notices. A passer-by has to unplug the unit (stopping everyone's streams), hold the button 10 s, join the WiFi and type the code, while the screen counts down. The code page also shows the WiFi name and password, which covers a forgotten hotspot password with QR off. To make room for this, **every tap acts on release** (WiFi Mode already did this):

| Press (acted on) | Hotspot | WiFi Mode |
|---|---|---|
| < 40 ms | nothing (noise, as today) | nothing |
| 40 ms – 3 s (release) | USB mode | USB mode |
| ≥ 3 s, window closed (release) | USB mode | hotspot until unplugged |
| 3–10 s, window open (release) | nothing (hint hidden) | hotspot until unplugged |
| 10 s held, window open (at 10 s) | reset code | reset code |

From 3 s held: window open → hint `lvglSendStatus(SI_WARNING, ST_WARN, "Keep holding", "to reset the admin password", …, big = seconds left)`, updated each second (7 updates). In WiFi Mode the detail reads "Let go for the hotspot, keep holding to reset admin". WiFi Mode with the window closed → one hint, "Let go to start the hotspot". The pure logic below was compiled and run on a PC with the tests sketched in §7, and passed:

```cpp
// NomadSetup.h - first-run and reset rules that need neither the radio nor the screen,
// so tools/setuptest can run them on a PC. No Arduino here.
#pragma once
#include <stdint.h>
#include <string.h>
#include <ctype.h>
// The hotspot password Nomad makes: 12 letters in three groups of four, "kmpx-rtqe-wnab".
// No i, l or o (they read as 1, 1 and 0 on a small screen). 23^12 = 2^54.
static const char kNomadPwLetters[] = "abcdefghjkmnpqrstuvwxyz";
#define NOMAD_GEN_PW_LEN 14
static void nomadMakeHotspotPassword(char out[NOMAD_GEN_PW_LEN + 1], uint32_t (*rnd)(void)) {
  const uint32_t n = sizeof(kNomadPwLetters) - 1, limit = 256 - (256 % n);   // 23, 253
  int o = 0, letters = 0, left = 0; uint32_t pool = 0;
  while (letters < 12) {
    if (!left) { pool = rnd(); left = 4; }
    const uint32_t b = pool & 0xff; pool >>= 8; --left;
    if (b >= limit) continue;                          // no letter more likely than another
    if (letters && letters % 4 == 0) out[o++] = '-';
    out[o++] = kNomadPwLetters[b % n]; ++letters;
  }
  out[o] = '\0';
}
// The setup code: 8 digits, leading zeros kept.
static void nomadMakeSetupCode(char out[9], uint32_t (*rnd)(void)) {
  uint32_t v;
  do { v = rnd(); } while (v >= 4200000000u);          // 42 * 10^8: every code equally likely
  v %= 100000000u;
  for (int i = 7; i >= 0; --i) { out[i] = (char)('0' + v % 10); v /= 10; }
  out[8] = '\0';
}
// The code as typed: spaces and dashes ignored, then exactly 8 digits, compared in constant time.
static bool nomadCodeMatches(const char *want, const char *typed) {
  if (!want || strlen(want) != 8 || !typed) return false;
  char t[9]; int n = 0;
  for (const char *p = typed; *p; ++p) {
    if (*p == ' ' || *p == '-') continue;
    if (*p < '0' || *p > '9' || n >= 8) return false;
    t[n++] = *p;
  }
  if (n != 8) return false;
  uint8_t d = 0;
  for (int i = 0; i < 8; ++i) d |= (uint8_t)(want[i] ^ t[i]);
  return d == 0;
}
// New hotspot passwords that are published or guessed first. Whole value, any case.
static const char *const kNomadPublishedPw[] = {
  "password", "password1", "12345678", "123456789", "1234567890", "00000000", "11111111",
  "88888888", "87654321", "qwertyui", "qwerty123", "iloveyou", "jcorp_nomad", "jcorpnomad",
  "nomad123", "nomadnomad",
};
static bool nomadSameNoCase(const char *a, const char *b) {
  for (; *a && *b; ++a, ++b) if (tolower((unsigned char)*a) != tolower((unsigned char)*b)) return false;
  return *a == *b;
}
static bool nomadHotspotPasswordPublished(const char *pw, const char *ssid) {
  if (!pw) return false;
  for (const char *k : kNomadPublishedPw) if (nomadSameNoCase(pw, k)) return true;
  return ssid && *ssid && nomadSameNoCase(pw, ssid);
}
// The BOOT button, read in loop() every pass (see the table above). The reset window is the
// first 2 minutes after Nomad is plugged in.
enum NomadBtnEvent : uint8_t { NB_NONE, NB_USB, NB_HOTSPOT, NB_RESET, NB_HINT, NB_CANCEL };
static const uint32_t NB_PRESS_MS = 40, NB_LONG_MS = 3000, NB_RESET_MS = 10000;
struct NomadBtn { uint32_t downAt; bool done; uint8_t hintLeft; };
// with NB_HINT, *hintLeft = whole seconds still to hold for the reset (0: no reset on offer)
static NomadBtnEvent nomadBtnStep(NomadBtn &b, bool low, uint32_t now, bool staMode, bool resetWindow,
                                  uint8_t *hintLeft) {
  if (low) {
    if (!b.downAt) { b.downAt = now | 1; b.done = false; b.hintLeft = 0xff; return NB_NONE; }
    if (b.done) return NB_NONE;
    const uint32_t held = now - b.downAt;
    if (resetWindow && held >= NB_RESET_MS) { b.done = true; return NB_RESET; }
    if (held >= NB_LONG_MS && (resetWindow || staMode)) {
      const uint8_t left = resetWindow ? (uint8_t)((NB_RESET_MS - held + 999) / 1000) : 0;
      if (left != b.hintLeft) { b.hintLeft = left; if (hintLeft) *hintLeft = left; return NB_HINT; }
    }
    return NB_NONE;
  }
  if (!b.downAt) return NB_NONE;
  const uint32_t held = now - b.downAt;
  const bool done = b.done, hinted = b.hintLeft != 0xff;
  b = NomadBtn{};
  if (done || held < NB_PRESS_MS) return NB_NONE;
  if (held < NB_LONG_MS) return NB_USB;
  if (staMode) return NB_HOTSPOT;
  if (resetWindow) return hinted ? NB_CANCEL : NB_NONE;
  return NB_USB;
}
```

## 7. Tests and acceptance criteria

**Host (`bash tools/setuptest/run.sh`, plus `bash tools/guardtest/run.sh` unchanged):**

## 8. Compatibility, rollout and rollback

- **New firmware + old card UI:** setup goes through the embedded `/setup` (the `/admin` redirect). After that, old `admin.js` signs in with v2. Its "Remove password" button gets a 400 with a readable message.
- **Old firmware + new card UI:** `admin.js` keeps handling `mode:"none"` and the `/settings` fallbacks, so it works as before.
- **Release notes (U):** "If your hotspot password was `password`, it changes at the first start: read the new one on Nomad's screen. Units without an admin password ask for a code from the screen before the admin page opens. Your admin password, if you set one, is unchanged."
- **Rollback** (OTA rollback or reflash): settings stay compatible, because old firmware ignores `wifiPwNotice` and NVS `appw`, and the generated WiFi password stays. On an unclaimed unit, old firmware brings back "everyone is admin". An "Erase device" flash wipes `appw`, but the card's password still wins.

## 10. Pushed to future fixes

- PAKE (for example SPAKE2 or OPAQUE) or ECDH-wrapped key transport for `/auth/setup` and `/auth/password`, against sniffers who know the WiFi password. It needs pure-JS crypto on http pages (no `crypto.subtle` there) and a one-off device task.
- Removing the plain-password paths, or moving their `authSetPlain` PBKDF2 off async_tcp (`NomadAuth.h:204-209, 296`). This is an existing breach of the "no crypto on the network task" rule.
- Login lockout and throttle tuning, and lockout-abuse protection (out of scope here).
- WPA3-SAE / transition mode for the hotspot (iOS 13+ only; ESP32-S3 softAP support to verify).
- Claiming without a screen (a broken display): USB serial already prints the code; a card-file claim was rejected (§4.3).
- A persisted "the admin password was reset on <date>" notice in the admin page.
- Raising PBKDF2 iterations (phone cost against offline cracking).

## 11. Open decisions for the owner

1. **Admin password minimum:** 8 / **10 (recommended)** / 15 (NIST single-factor). Ten plus a blocklist resists offline cracking well enough, and remains typable for family use.
2. **Rename the default SSID** to `Jcorp_Nomad-XXXX` for new cards and for cards whose default password is replaced: **yes (recommended)**. If the preview shows it doesn't fit the pill even in small type, use `Nomad-XXXX`.
3. **Hotspot password format:** **12 letters, `xxxx-xxxx-xxxx` (recommended)**, or letters and digits (more bits, more keyboard switching), or spaces as separators (easier typing, more people will leave them out).
4. **Recovery gesture:** **10 s hold within 2 min of power-on (recommended)**, or a 10 s hold at any time (easier, but triggered more easily at parties).
5. **Allow an open hotspot** behind the confirm: **yes (recommended)**. The admin side is protected either way.
6. **Show the password as text with the QR after the claim:** **no (recommended)**, to keep today's layout. Old iPhones read it in admin.
7. **Board password in NVS**, so card swaps keep the same WiFi password: **yes (recommended)**.
8. **Minimum 30% brightness while unclaimed:** **yes (recommended)**. Otherwise a unit whose screen was turned off can't be set up.
9. **Code lifetime and length:** **10 min, 8 digits (recommended)**.
