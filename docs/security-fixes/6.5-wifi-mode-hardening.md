# 6.5 WiFi Mode hardening

> **Problem.** In WiFi Mode Nomad sits on a home network, and every web page that any browser on that network opens can reach it. Today: (1) there is no Host check, so a page served from `attacker.example` can point its name at Nomad's address (DNS rebinding) and then act as a Nomad page. With no admin password that means full admin; with one it still means guest reads of the card and guest uploads. (2) The card's lists, assets and media are sent with `Access-Control-Allow-Origin: *`, so any site that knows or guesses the address can read them. (3) The home WiFi name and password are stored in plain text in `/config/settings.json` on the removable card, which a BOOT tap exposes to any PC. (4) WiFi Mode can be turned on with no admin password. (5) SSDP answers spoofed and off-network M-SEARCHes with no rate limit, and DLNA is on by default on the home LAN.
> **Fix.** A front handler refuses any request whose Host is not Nomad's own address or name, and any write sent by another site, before a body byte is handled. All `*` CORS headers go (no Nomad page needs them). WiFi credentials move to the chip's NVS, with a one-time migration off the card. WiFi Mode needs an admin password and explicit consent for open networks. SSDP answers only its own subnet, through a token bucket, and DLNA on the home network becomes a separate switch that is off for new setups.
> **What users see.** Nothing changes for normal use at `192.168.4.1`, `nomad.local` or the screen's address. Other names are redirected to the address. The captive sign-in sheet still opens, now at `http://192.168.4.1/`. The WiFi Mode popup asks for an admin password first. After the first boot of the new firmware the card no longer holds the home WiFi password.

## 1. Scope (in / out)

**In:**
- Host allowlist (DNS rebinding) for every HTTP request, in both hotspot mode and WiFi Mode.
- The cross-site write rule tightened and applied before body and upload handlers.
- Removing `Access-Control-Allow-Origin: *` and the preflight routes.
- WiFi Mode credentials (`staSSID`, `staPassword`, `staPersist`) moved from the card to NVS, with migration and an export/import rule.
- An honest evaluation of flash and NVS encryption.
- WiFi Mode prerequisites: the admin password gate and open-network consent.
- SSDP subnet filter and rate limit; DLNA's default in WiFi Mode.
- Diagnostics counters.
- Documenting the residual risk of plain HTTP on the LAN.

**Out (owner):**
- Admin password strength, recovery, the default hotspot password, and where the admin record and hotspot password are stored: **6.1**. 6.5 provides the NVS store and recommends using it (section 9).
- Guest upload policy: **6.2**.
- Token storage and session lifetime: **6.3**.
- ZIM origin isolation: **6.4**.
- Update fetching: **6.6/U**.
- DLNA Browse stalling the network task: **section 10**.
- On-device TLS: excluded by the power/RAM constraint.

## 3. Threat or failure being fixed (concrete scenarios)

1. **Rebinding, WiFi Mode.**
   - A laptop on the home network opens an ad or a hostile page at `http://a.attacker.example`. Its DNS answers with the attacker's server first, then with Nomad's LAN IP (Singularity automates this).
   - Script calls to `a.attacker.example` now reach Nomad, with Origin == Host, so nothing refuses them.
   - With no admin password: `POST /api/wifi-mode` `forget`, `/settings`, `/auth/password`, firmware staging.
   - With a password: every list and file outside `/config`, plus uploads into open folders.
2. **Rebinding, hotspot with mobile data.**
   - `dnsCatchAll` is off by default, so a phone can keep using mobile data and its own DNS.
   - The same attack is possible if the phone routes 192.168.4.1 over WiFi. That depends on the Android or iOS version and is **unverified**. The Host check closes it either way.
3. **Direct cross-origin reads.** Any page a LAN user opens can call `fetch('http://192.168.1.50/api/archive-list')` and read the result, because of ACAO `*`. It can also scan 192.168.x.x/24 for Nomad, in roughly 254 requests.
4. **Writes through body handlers.** A cross-origin `text/plain` POST to `/api/mp/create`, `/api/party/*` or `/led/*` runs its body handler before the cross-site middleware. With no password, `/led/*` changes the LED. A page can also exhaust the 8 multiplayer rooms.
5. **Opaque-origin writes.** On old iOS (no `Sec-Fetch-Site` before Safari 16.4), a page loaded over mobile data can POST from a sandboxed iframe (`Origin: null`). The hotspot accepts that today.
6. **Card exposure of the home WiFi password.**
   - Anyone holding the device can tap BOOT, plug it into a laptop and open `config/settings.json`.
   - The same happens when the card is lent, cloned or read by Nomad-Card-Tools.
   - The SSID alone can locate the owner's home through public WiFi maps.
7. **WiFi Mode without a password.** Every device on the home network is admin.
8. **Forced fallback.** An attacker deauthenticates Nomad (the core enables PMF but does not require it) for 3 minutes. Nomad then restarts into the hotspot, whose default password is published. 6.1 fixes the password; 6.5 makes sure the joined attacker is only a guest (the admin password gate).
9. **SSDP reflection and amplification.**
   - A spoofed M-SEARCH (one packet of about 90 bytes) produces about 900 bytes aimed at a victim.
   - Floods also churn internal RAM (several String allocations per packet on `async_udp`). Every M-SEARCH on a busy home LAN gets answered.
   - DLNA advertises Nomad to every device on the network.
10. **Plain-HTTP admin token on a shared LAN.** This is the residual risk, documented in section 8.

## 4. Design

### 4.1 Pure rules in a new header: `NomadNetGuard.h`

`NomadNetGuard.h` uses no Arduino and no server code (only `<string.h>`, `<strings.h>` and `<stdint.h>`). `tools/guardtest` includes it. Like `NomadGuard.h`, it must be identical on every firmware line. This sketch was compiled and tested on the host (48 cases passing, `-Wall -Wextra -Werror`):

```cpp
// Names Nomad answers to besides its own address. None of them can be registered on the
// internet ("local", "lan", "home", "home.arpa" (RFC 8375) and the bare "nomad" are not
// delegated), so no web page anywhere can point one of them at Nomad and come back as us.
static const char *const kNomadOwnNames[] = {
  "nomad", "nomad.local", "nomad.lan", "nomad.home", "nomad.home.arpa", "www.nomad",
};
// Strict dotted decimal. Browsers send IPv4 hosts in this form already (the URL parser
// rewrites 0xC0.168.4.1 and 3232236545), so anything else is not a browser.
static inline bool nomadParseIPv4(const char *s, size_t n, uint8_t out[4]);
// ":80" (or no port) is fine; anything else is not us. Sets *badPort.
static inline size_t nomadStripPort80(const char *h, size_t n, bool *badPort);
// host: the Host header. self: the address this connection arrived on (the AP or STA IP).
static inline bool nomadHostIsOurs(const char *host, size_t n, const uint8_t self[4]) {
  if (n == 0) return true;        // HTTP/1.0 clients (old TVs) send none; a browser always does
  bool badPort; n = nomadStripPort80(host, n, &badPort);
  if (badPort) return false;      // Nomad listens on 80 only (a router port-forward is refused)
  if (n && host[n - 1] == '.') n--;                         // "nomad.local." is the same name
  if (n == 0) return false;
  uint8_t ip[4];
  if (nomadParseIPv4(host, n, ip)) return memcmp(ip, self, 4) == 0;
  for (const char *name : kNomadOwnNames)
    if (strlen(name) == n && strncasecmp(host, name, n) == 0) return true;
  return false;                   // includes "[v6]" literals: no IPv6 on this firmware
}
// A write some other page made the browser send. fetchSite/origin are nullptr when absent.
static inline bool nomadWriteFromElsewhere(const char *fetchSite, const char *origin,
                                           const char *host, size_t hostLen) {
  // Nomad's pages only ever write to themselves: anything but same-origin (or "none",
  // a typed address) came from somewhere else, same-site included
  if (fetchSite && strcasecmp(fetchSite, "same-origin") && strcasecmp(fetchSite, "none")) return true;
  if (!origin) return false;                                // old browsers, TVs, curl
  if (strncasecmp(origin, "http://", 7)) return true;       // "null", https://, file://
  bool b1, b2;
  const size_t on = nomadStripPort80(origin + 7, strlen(origin + 7), &b1);
  const size_t hn = nomadStripPort80(host, hostLen, &b2);
  return b1 || b2 || on != hn || strncasecmp(origin + 7, host, hn) != 0;
}
// SSDP: answer only Nomad's own network, and no faster than TVs need.
struct NomadSsdpGate {
  static const uint16_t kBurst = 12;        // a few TVs opening their source lists at once
  static const uint32_t kRefillMs = 250;    // then 4 answer packets a second
  uint32_t net = 0, mask = 0, lastMs = 0;   // lwIP byte order; bitwise tests don't care
  uint16_t tokens = kBurst;
  bool onOurNetwork(uint32_t remote) const {
    return mask && remote && ((remote ^ net) & mask) == 0 && (remote | mask) != 0xFFFFFFFFu;
  }
  bool take(uint32_t nowMs, uint16_t cost);   // refill by elapsed time, then spend cost
};
```

The captive hostname list stays in `NomadDNS.cpp`, unchanged. Only the six names above are added to the DNS answer list (shared via `kNomadOwnNames`, so DNS and HTTP agree); `nomad.home.arpa` is the one new name.

**Why captive names are not on the HTTP allowlist.**
- The Host check does not trust them. Probe hostnames (the old Apple domains `thinkdifferent.us`, `itools.info` and so on) are only safe while their owners keep them. A lapsed one would be a rebinding hole.
- Instead, every foreign Host is redirected to Nomad's address. WiFiManager does the same: a 302 to `http://<client().localIP()>` whenever Host is not the device's address.
- Captive detection still triggers, because every OS probe treats "not the expected answer" as a portal and the sign-in sheet follows redirects.
- The pages then load at `http://192.168.4.1/` (the same page as now: `/` on an iPhone User-Agent gives `appleindex.html`, `ino:7135-7139`).
- Nomad content is therefore never served under a name Nomad does not own.

### 4.2 Front handler: Host, cross-site and OPTIONS, refused before the body (`NomadGuardWeb.h`)

```cpp
static volatile uint32_t g_nomadHostRefused = 0, g_nomadCrossRefused = 0;
static char g_nomadLastBadHost[40];   // for /api/support only, sanitised on copy

static inline bool nomadHostRefused(AsyncWebServerRequest *r) {
  uint8_t self[4] = {0, 0, 0, 0};
  if (r->client()) { const IPAddress a = r->client()->localIP(); for (int i = 0; i < 4; ++i) self[i] = a[i]; }
  return !nomadHostIsOurs(r->host().c_str(), r->host().length(), self);
}
// replaces the body of today's nomadCrossSiteWrite (same name, same callers)
static inline bool nomadCrossSiteWrite(AsyncWebServerRequest *r) {
  const WebRequestMethodComposite m = r->method();
  if (m == HTTP_GET || m == HTTP_HEAD || m == HTTP_OPTIONS) return false;
  const AsyncWebHeader *fs = r->getHeader("Sec-Fetch-Site"), *o = r->getHeader("Origin");
  return nomadWriteFromElsewhere(fs ? fs->value().c_str() : nullptr, o ? o->value().c_str() : nullptr,
                                 r->host().c_str(), r->host().length());
}
// Asked first, as soon as the headers are in. Upload and body handlers act on chunks as they
// arrive, before any middleware, so this is the one place a refusal reaches all of them. A
// request it takes has its body skipped unread (isRequestHandlerTrivial() is true here).
class NomadFrontHandler : public AsyncWebHandler {
 public:
  bool canHandle(AsyncWebServerRequest *r) const override {
    if (nomadHostRefused(r)) { g_nomadHostRefused++; nomadNoteBadHost(r->host()); return true; }
    if (r->method() == HTTP_OPTIONS) return true;           // no preflight is ever granted
    if (nomadCrossSiteWrite(r)) { g_nomadCrossRefused++; return true; }
    return false;
  }
  void handleRequest(AsyncWebServerRequest *r) override {
    if (nomadHostRefused(r)) {
      const WebRequestMethodComposite m = r->method();
      const IPAddress self = r->client() ? r->client()->localIP() : IPAddress();
      if ((m == HTTP_GET || m == HTTP_HEAD) && self != IPAddress()) {
        // a name Nomad doesn't own: send the browser to the address (captive sheets, a
        // router's own name for Nomad, a mistyped name). Never any content under that name.
        AsyncWebServerResponse *res = r->beginResponse(302);
        if (!res) { r->send(421); return; }
        res->addHeader("Location", "http://" + self.toString() + "/");
        res->addHeader("Cache-Control", "no-store");
        r->send(res);
      } else nomadGuardSend(r, 421, "Misdirected request");
      return;
    }
    if (r->method() == HTTP_OPTIONS) {
      AsyncWebServerResponse *res = r->beginResponse(204);
      if (res) { res->addHeader("Allow", "GET, HEAD, POST, OPTIONS"); r->send(res); } else r->send(204);
      return;
    }
    nomadGuardSend(r, 403, "Cross-site request refused");
  }
};
```

- `nomadNoteBadHost()` copies at most 39 bytes. Any byte outside `[A-Za-z0-9.:-]` becomes `?`. It runs only on refusals.
- `installNomadGuard()` (`NomadGuardWeb.h:205`) also does `server.addHandler(new NomadFrontHandler())`. Its call moves from `ino:8397` to just before `server.addHandler(new NomadLimitHandler())` at `ino:6792`, so the front handler is the first handler. (The middleware is order-independent.)
- `nomadGuardMiddleware` step 2 and `nomadUploadAllowed` keep calling `nomadCrossSiteWrite`, as defence in depth.
- **Behaviour change:** `Origin: null` and `Sec-Fetch-Site: same-site` are now refused in both modes. No Nomad page sends either (section 2). The `staMode` hook stays in `NomadGuardHooks`, unused by this rule; 6.2 may keep using it.
- **Rejected:** applying the rule in middleware. It would run after body handlers (section 2).
- **Rejected:** answering foreign names with 421 for every method. That breaks captive sheets and router-assigned names for nothing: a cross-origin GET to the IP is no more than any page can already do directly.
- **Rejected:** a 302 that keeps the path. The pages it would reach are the same, it needs re-encoding of a decoded URL into a header, and the encoding risks header injection.

**Residual for GET routes with side effects.** A page that knows the IP can still trigger one cross-origin, uncredentialed GET (Nomad uses no cookies, so it carries no admin token). The rule for every route therefore stands: GETs change nothing a guest could not change anyway. The regression check is in section 7.

### 4.3 CORS removed

- Delete every header listed in section 2. Remove the `cors` parameter of `sendSdFile` (`ino:6199-6251`) and the `true` argument at `ino:6987`.
- Delete both `HTTP_OPTIONS` routes (`ino:6968-6975`, `:6991-6997`): the front handler answers OPTIONS.
- Update the comment at `ino:6981-6983` to: "same-origin fetches need no CORS; none is sent, so no other site can read the card".
- Same-origin requests never need `Access-Control-*` (Fetch standard). Cross-origin preflights now fail, which is the intent.
- **Rejected:** reflecting the request's Origin when it is one of Nomad's names. No Nomad page fetches across its own names, and every reflected header costs internal-RAM allocations on every reply.

### 4.4 WiFi credentials in NVS (`NomadSecrets.h`, new)

Data format, in NVS namespace `nomadsec` (names of 15 characters or fewer):

| key | type | meaning |
|---|---|---|
| `v` | u8 | 1 = this chip has done the card→chip move (done once per chip) |
| `sta_ssid` | string ≤ 32 | home network name (absent = none) |
| `sta_pass` | string ≤ 63 | its password (absent = open network) |
| `sta_auto` | u8 0/1 | join on every start (was `staPersist`) |

Reserved for 6.1 if it takes them: `adm_rec` (the `v2$…` admin record) and `ap_pass`.

```cpp
// NomadSecrets: what must not travel with the card. The chip's own NVS (namespace
// "nomadsec"), never the card: a card is lent, cloned, read by the PC tools, and a BOOT tap
// shows all of it to any computer. Written only when the admin changes WiFi Mode.
bool nomadStaLoad();                    // NVS -> settings.staSSID/staPassword/staPersist
bool nomadStaSave();                    // settings -> NVS; pass, then auto, then ssid (so a cut
                                        // part way leaves a set that fails to join -> hotspot);
                                        // empty value = remove(key); read back and compare
bool nomadStaForget();                  // removes the three keys
void nomadStaBoot(const String &cardSsid, const String &cardPass, bool cardAuto, bool cardHadSta);
```

Firmware changes:
- `loadSettings()` (`ino:2048-2112`) stops assigning `settings.sta*`. It copies the card values into locals and passes them to `nomadStaBoot()`, which is called from `setup()` right after `loadSettings()` (`ino:6677`). It is also called when the card has no settings file, so a fresh card in a configured device still joins.
- `nomadStaBoot`:
  - Begin read-only and read `v`.
  - If `v == 0` and the card's SSID is non-empty, copy the card values to `settings` and run `nomadStaSave()`.
  - Then set `v = 1` (once per chip; later card edits are ignored, which also closes "edit the card to make Nomad join my network").
  - Otherwise run `nomadStaLoad()`.
  - If the card held any sta key, set `g_staScrubCard = true`. `setup()` then calls `saveSettings()` once, which, with the sta lines removed from both writers (`ino:2420-2422`, `:2454-2456`), rewrites `settings.json` without them through the normal atomic writer.
  - Remove `/config/settings.json.bad` if present: it is unreadable by definition and may hold the password.
  - Log "WiFi Mode network moved from the card to Nomad".
- Writes:
  - `POST /api/wifi-mode` `connect`/`disable` (`ino:7697-7724`) and the cancel path in `startStationMode()` (`ino:5386-5391`) call `nomadStaSave()`.
  - `forget` calls `nomadStaForget()`.
  - A failed save returns 500 "Couldn't save the network on Nomad".
  - The non-secret part (`dlnaSta`) still goes through `saveSettings()`.
- Comment at `ino:5364`: "our copy lives in Nomad's own NVS (nomadsec), keep the core's copy out of it".
- **Export/import:** WiFi Mode credentials are never in a backup.
  - `BACKUP_SETTINGS` (`admin.js:2196`) gains only `dlnaSta`.
  - `POST /settings` keeps ignoring sta keys. Add a comment there saying so.
  - Moving the card to another Nomad no longer carries WiFi Mode. That is documented as intended: the network belongs to the device and the place.

**Flash/NVS encryption: not recommended.** Reasons:
- Flash encryption alone "may not prevent an attacker from modifying the firmware"; ESP-IDF says to pair it with Secure Boot. Secure Boot is exactly what LICENSING.md:30 ("Don't lock it down") forbids.
- Development mode keeps serial flashing. Anyone who can flash, the owner or a thief, can flash code that reads NVS through the normal API.
- Release mode ends serial flashing of new plaintext images.
- Both modes burn eFuses (`SPI_BOOT_CRYPT_CNT`), which is irreversible.
- Arduino's prebuilt bootloader has no flash-encryption support (unverified for core 3.3.3).
- HMAC-based NVS encryption needs no flash encryption, but it burns an `HMAC_UP` key, and the HMAC "is given out to the software". Any firmware flashed onto the chip can derive the same NVS keys.

The honest framing for README:
- NVS takes the secrets off the card. They no longer leave with it, show up in USB mode, end up in card images or reach the PC tools.
- They do not resist someone who has the device, a computer and `esptool read_flash` (the S3's USB-Serial-JTAG enters download mode without a button: `tools/flash-nomad.sh:11-16`).
- Older copies of `settings.json` may remain in the card's free space until they are overwritten. An owner who has lent out the card should change the home WiFi password or use a guest network.

### 4.5 WiFi Mode prerequisites

That function is declared before `#include "NomadAuth.h"` (`ino:2464`) and defined after `g_staMode` (`ino:2671`).

On an open network the plain-HTTP admin token is readable by anyone within radio range. With a password, the core already enforces WPA2-PSK as the minimum (Arduino `STA.cpp` `_minSecurity`), so an open evil twin with the same SSID is refused.

### 4.6 SSDP and DLNA (`NomadDLNA.cpp`)

- **New setting** `bool dlnaSta = false` in `AdminSettings`, loaded and saved in `settings.json`.
  - Effective state: `dlnaWanted() = settings.dlnaEnabled && !g_safeMode && (!g_staMode || settings.dlnaSta)`, used at `ino:5512` and `ino:7614`. That fixes the safe-mode bypass too.
  - **Migration:** if the key is absent and the card had a configured WiFi Mode, `dlnaSta = dlnaEnabled`, so existing TV setups keep working. Otherwise false.
  - `GET /settings` returns `dlnaSta`; `POST /settings` accepts it.
  - Admin "TV support" row (`admin.html:1159-1163`): a sub-row "Also on the home network (WiFi Mode)".
- **Network:** `void dlnaSetNetwork(IPAddress ip, IPAddress mask)` fills `NomadSsdpGate.net/mask`.
  - Call it in `startNetwork()`: STA uses `WiFi.localIP()/subnetMask()`; AP uses `softAPIP()` with 255.255.255.0.
  - Also call it in the existing new-lease block (`ino:8546-8559`). No new polling.
- **`onSSDPPacket` rewritten** so that dropped packets allocate nothing:
  - length 20–1024;
  - `memcmp(data, "M-SEARCH", 8)`;
  - `gate.onOurNetwork(remoteIP)`, which covers unicast and multicast alike;
  - a raw scan for the `ST:` header at a line start (case-insensitive, bounded, into `char st[64]`);
  - `cost` = 3 for `ssdp:all`, 1 for a known ST, 0 means ignore;
  - `gate.take(millis(), cost)`;
  - then the existing response Strings.
- Counters `s_ssdpAnswered` and `s_ssdpDropped`, exposed through `void dlnaStats(uint32_t&, uint32_t&)`.
- **Rejected:** a random MX delay before answering. It needs a timer or a task per answer. Immediate answers are what TVs get today.
- **Rejected:** a per-source table. The global bucket already caps output at 4 packets/s (about 1.2 KB/s) whatever the input.

### 4.7 Diagnostics and residual-risk text

- `/api/netdiag` (guest-readable, `ino:6859`) adds `hostRefused`, `crossRefused`, `ssdpAnswered` and `ssdpDropped`.
- `/api/support` `net` (admin, `NomadSupport.h:306-309`) adds the same counters plus `lastBadHost`, so the owner can see why a router name redirects.

README WiFi Mode text replaces "prefer hotspot / guest network / set the password first" with:
- WiFi Mode needs an admin password.
- Nomad answers only to its address, `nomad.local` and `nomad`/`nomad.lan`/`nomad.home`/`nomad.home.arpa`.
- **Residual: plain HTTP.**
  - Anyone on the same network who can capture traffic can copy the admin token while it is in use. That includes any WPA2-PSK member who captures the handshake, and ARP spoofers.
  - They can also answer `nomad.local` in place of Nomad (mDNS spoofing), then read the token stored for that origin.
  - The login itself never sends the password (challenge proof). A captured exchange still allows offline guessing at PBKDF2 with 10,000 rounds, which is why 6.1's strength rule matters.
  - A guest network, or client isolation, is still the better choice: a nicety, no longer the only safeguard.

**Browser protections, as of November 2026.**
- **Chrome:** shipped Local Network Access, a permission prompt for public→local requests (`fetch`, subresources, subframes).
  - Blink milestone 141 per the Intent to Ship; the Chrome blog says 142.
  - Its prompt is offered only to secure contexts.
  - It does not cover Android WebView, top-level navigations or WebSockets.
  - A 2026 evaluation finds it mitigates classic rebinding, but prompt fatigue remains.
- **Firefox:** rolling LNA out to desktop in versions 151–153; Android followed.
- **WebKit/Safari:** "Implement Local Network Access" (bug 250607) shows no shipped implementation, so every iOS browser and every older iPhone has no protection.
- **No browser** gates local→local requests: a page served by another device on the LAN.

Hence the server-side Host check.

## 5. Power, memory and performance budget

| Change | Internal RAM | PSRAM | Flash (code) | CPU / radio | Card / NVS wear |
|---|---|---|---|---|---|
| Front handler | 1 object, about 24 B (boot); counters and last-host buffer 48 B .bss; **0 per request** (char parsing, no String temporaries) | 0 | +~1.5 KB | Host check ≈ 0.5–2 µs per request at 240 MHz (≤15-char parse plus at most 6 `strncasecmp`); Origin check on writes only | none |
| CORS removed | **saves** 3 headers per `/media` reply (~123 B of text, ~6–9 small allocations per range reply) and 1 per list/asset reply; at 8 media slots ≈ 1 KB less at peak | 0 | −0.3 KB | less | none |
| NVS secrets | transient Strings ≤ 100 B during load/save | 0 | +~1 KB | load at boot < 2 ms; save 5–20 ms (up to ~100 ms on a page erase) on async_tcp, admin-initiated only | ≤ 300 B of the 20 KB `nvs` partition; ~250 B written per WiFi Mode change |
| Migration | — | 0 | +0.3 KB | once: NVS writes in `setup()`, < 100 ms | one `settings.json` rewrite, once per card |
| SSDP gate | 20 B .bss | 0 | +0.5 KB | per packet: compares only; **saves** ≥ 2 internal allocations (≤ 2 KB) per dropped packet; output ≤ 12 burst then 4 packets/s | none |
| `dlnaSta` off (new setups) | 0 | 0 | ~0 | in WiFi Mode, removes 4 multicast NOTIFY packets every 90 s (~1.3 KB) and answers to LAN discovery | none |

- No new task, timer, polling loop or periodic radio traffic. The screen shows one extra status, once per boot, only when the gate refuses. No LED change.
- Nothing runs on async_tcp for longer than one NVS commit.

**How to measure:**
- Under a 4-film load, `GET /api/health` (`heapFree`, `dmaFree`, `memLow`) and `/api/performance` should show `memLow` equal to or better than the previous build. That build is the baseline: same card, same 4 phones, 10 minutes.
- `/api/support` `net.*` counters during the tests in section 7.
- SSDP: `tcpdump -i <wlan> udp port 1900` while flooding. Expected: 12 answers in the first second, then 4 per second or fewer.
- Idle current: an inline USB meter for 10 minutes in WiFi Mode, `dlnaSta` on vs off. Expect a difference within meter noise (< 1 mA average): the radio is already always on (`setSleep(false)`, `ino:5367`).

## 8. Compatibility, rollout and rollback

- **Names.** People who reached Nomad by a router name (`nomad.fritz.box`, `nomad.localdomain`) are redirected to the IP. Sessions kept under the old origin (localStorage) need one new sign-in. A router port-forward stops working (intended).
- **Captive pages** now run at the IP origin, not the probe hostname. localStorage set inside captive sheets under probe names is not carried over (none is relied on).
- **Existing WiFi Mode users with no admin password** boot to the hotspot with a clear on-screen reason until they set one. The stored network is kept, so setting a password and restarting rejoins.
- **Existing WiFi Mode users with DLNA** keep TV discovery (migration). New setups default it off.
- **Firmware rollback** (`NomadFirmware` A/B, or a USB downgrade) to a build that reads `staSSID` from the card: the card has no sta keys any more, so the old build runs the hotspot (fail-safe). The owner re-enters the network there. The `nomadsec` keys are ignored by old builds and reused if the new build returns (`v=1`).
- **Old UI with new firmware:** the 409/400 errors show through the existing `alert()`. **New UI with old firmware:** missing fields mean "don't block".
- **Rollout order:** commits 1–3 are safe on their own. Commit 4 must precede 5 (the gate's error text points at the popup), and 6 can go any time.

## 9. Dependencies on other workstreams

- **6.1:**
  - Provides `nomadAdminPasswordSet()` and owns password strength. The offline-guessing risk in section 4.7 depends on it.
  - Owns the default hotspot password; scenario 8 depends on it.
  - Physical recovery must leave WiFi Mode gated: the boot gate covers this. Optionally 6.1 calls `nomadStaSave()` with `staPersist=false`.

- **6.3:**
  - Session lifetime and token storage; consider shorter idle limits in WiFi Mode and binding a session to the client IP that signed in.

## 11. Open decisions for the owner

1. **Foreign Host on GET:** a 302 to the address (WiFiManager's pattern) or 421. *Default: 302* (keeps captive sheets and router names working; adds nothing an attacker lacks).
2. **Captive pages served at the IP rather than under probe hostnames.** *Default: yes.* Fallback if a device's sign-in sheet breaks in testing: allowlist the captive list on the hotspot only, minus the legacy Apple domains whose ownership can't be confirmed.
3. **Existing WiFi Mode users without an admin password:** enforce at boot, or allow with a warning. *Default: enforce.*
4. **DLNA in WiFi Mode:** *Default: off for new setups, kept for existing configured users.*
5. **Refuse `Origin: null` and `same-site` writes on the hotspot too.** *Default: yes.*
6. **Open home networks:** *Default: allowed with explicit consent* (vs forbidden).
7. **Flash or NVS encryption.** *Default: no* (section 4.4). Revisit only if the GPL rule changes.
8. **Move the admin record and hotspot password to NVS (6.1's call).** *Default: admin record yes, hotspot password at 6.1's discretion.*
9. **Fixed name list vs admin-editable.** *Default: fixed* (any added name must be non-public; easy to get wrong).
