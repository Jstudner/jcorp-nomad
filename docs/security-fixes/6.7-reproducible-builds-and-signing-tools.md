# 6.7 Reproducible builds and signing tools

> **Read [README.md](README.md) first.** Its global power rules apply here, and its cross-workstream decisions override this doc where they differ: **D1** (`header` writes U's `NomadReleaseKeys.h`; no `NomadUiKey.h`), **D3** (the UI manifest asset is `ui-manifest-<version>.txt`), **D5** (`NomadFwTrailer.h` comes first in the shared verifier) and **D9** (build the card-tools zip from `tools/card-tools/` once 6.4 lands).

> **Problem.** Today the only advice for trusting a binary is "build it yourself with the versions in the README". That build is not repeatable. Versions are pinned only in prose (`README.md:175-185`). Nothing checks the archives the toolchain downloads. The binary carries the builder's home directory and the build time. The upstream 5.0 image, for example, contains `/home/<user>/.arduino15/...` four times plus `Nov 23 2026 10:00:48`, so two builds of the same commit never match. The `.nomadfw` packer and the key generator are not in the repo (`NomadFirmwareKey.h:4` names an outside script), and the ELF that crash dumps need is not kept. **Fix.** A pinned toolchain (`sketch.yaml`, plus `tools/build/toolchain.lock` holding the SHA-256 of every archive), a single `tools/build.sh` that builds both boards without machine paths or clock values, and a CI workflow that builds every change and, on a `v*` tag, builds twice in different places and requires identical bytes before it drafts the release. One Python tool, `tools/nomadfw.py`, generates keys, writes the key headers U and 6.6 specified, packs, signs and verifies `.nomadfw` files (byte-compatible with `fwCheckTrailer()`), and is cross-checked by a host C++ test that runs the firmware's own trailer code. **User-visible effect.** Anyone can rebuild a release and get the same SHA-256. `/api/support` shows the commit the device was built from, and that firmware's ELF hash matches the published `.elf`. Self-builders get `--no-ota` or their own key with one command. The device's behaviour and the `.nomadfw` format do not change.

## 1. Scope (in / out)
**In:** pinning (platform, tools, libraries, arduino-cli); the build script and its outputs; making the output path- and time-independent and defining how to verify it; CI (build, reproduce, draft release; no secrets); the key, header, pack, sign and verify tools and their interface for U; host tests; small firmware changes that serve the build (a build stamp and commit id, the trailer check moved into a host-testable header, an early refusal when there is no key, a `NOMAD_FW_NO_OTA` switch, a release-build guard); `flash-nomad.sh` built on the new script; deterministic zips for the card template and card tools.
**Out:** where artifacts are hosted, URLs, `firmware.json`, the publish process, key custody and the move off upstream's key (**U**); the UI manifest format and its generator (**6.6**, which calls these tools); moving the card tools' source into the repo (**6.4**); which keys the firmware trusts at run time (**U §4.4**, built on the header defined here).

## 2. Current behaviour (file:line)
- **Inputs exist only as prose.** `README.md:177-183` lists esp32 core 3.3.3, ArduinoJson 7.3.0, Async TCP 3.6.0, LVGL 8.3.10 and SdFat 2.3.0. `tools/flash-nomad.sh:41` holds the FQBN `esp32:esp32:esp32s3:CDCOnBoot=cdc,FlashSize=16M,PSRAM=opi,PartitionScheme=app3M_fat9M_16MB`. `:42-43,56-60` pass `-DLV_CONF_INCLUDE_SIMPLE -I<sketch>` and `-DBOARD_USB_C=1`. `:45-47` hard-code `~/.arduino15/.../3.3.3` and `esptool_py/5.1.0`. `:55` `NOMAD_LIBS` swaps in other libraries. `:66-70` flash 0x0/0x8000/0xe000/0x10000 with dio/80m/16MB and leave NVS and FAT alone. `build_opt.h` (SdFat defines) is copied in by the platform (platform.txt:110,128,149). `CMakeLists.txt` and `filelist.txt` are SquareLine leftovers that point at a `fonts/` folder that doesn't exist. arduino-cli ignores both.
- **Version.** `NomadUpdate.h:34-42` holds `#ifndef` defaults: `NOMAD_FW_VERSION "5.0"`, channel `"experimental"` and the nomadflash base. U moves the values to `NomadUpdateConfig.h` (U §4.4).
- **Board.** `NomadScreen.h:11-12` sets `BOARD_USB_C` to 0. `NomadFirmware.h:49-59` derives `NOMAD_BOARD_ID` (`s3-usba`/`s3-usbc`).
- **OTA format.** `NomadFirmware.h:4-8` describes it and `fwCheckTrailer()` at `:162-193` checks it. The checks run in this order: magic, size (`:166`), image SHA (`:167`), meta length (`:169`), signature length (`:172`), key present (`:173`), ECDSA verify of SHA-256 over `trailer[0:sigAt]` (`:175-181`), meta JSON (`:182-186`), board (`:187`), newer (`:188`). mbedTLS refuses DER with trailing bytes, so the length must be exact. I checked this against two real files (nomadflash `main`, 5.0, 2,218,928 bytes): meta `{"board":"s3-usba","version":"5.0","channel":"main"}` (52 bytes), signatures of 71 and 72 bytes, zero padding, and both verify under `NomadFirmwareKey.h` (key SHA-256 `9e956fde71ccad28…`).
- **Key.** `NomadFirmwareKey.h:8-18` is a 91-byte SPKI in rows of 12, followed by `NOMAD_FW_PUBKEY_LEN = 91`. `:40-45` swaps in `NomadFirmwareKeyDev.h` for `NOMAD_FW_DEVKEY`, and `firmware/JcorpNomadProject/.gitignore:2` ignores it. With `NOMAD_FW_PUBKEY_LEN == 0` the file is refused only after `fwBegin` (`:146`) has erased and written up to 3 MB (`:173`). The UI already handles this case: `admin.js:2380,2384` shows "This build can only be updated over USB".
- **Crash and build identity.** The ELF hash sits at image offset 0xb0 (platform.txt:167 `--elf-sha256-offset 0xb0`). `/api/support` reports it in full (`NomadSupport.h:248-251`) along with `built = __DATE__ __TIME__` (`:252`). The stored core dump keeps an 8-hex prefix (`:183`, `:315`). Decoding it needs that exact ELF (`:13-16`), which nobody keeps.
- **Clock floor.** `NomadClock.h:39-56` parses `__DATE__`/`__TIME__` as UTC.
- **What upstream's build embeds** (measured in the 5.0 image): the core prints `Compile Date/Time`, `Compile Host OS` ("linux") and the FQBN (core 3.3.3 `chip-debug-report.cpp:216-230`, from platform.txt:105 `-DARDUINO_HOST_OS -DARDUINO_FQBN`). Four absolute paths come from `__FILE__` in core `esp32-hal-rmt.c`, `esp32-hal-uart.c`, LVGL `qrcodegen.c` and the sketch's `src/zstd`. `__DATE__` appears twice. The `esp_app_desc` date ("Nov 4 2025") is fixed, because it comes from the precompiled IDF libraries. The USB-A and USB-C images, built 85 s apart, differ in only **80 bytes** (times, pin, board id, ELF hash, checksums). Everything else is already deterministic.
- **Merged image.** platform.txt:180 writes `*.merged.bin` padded to 16 MB. Writing it at 0x0 wipes the FAT and coredump partitions, and NVS too, because esptool fills gaps with 0xFF. The partition map is nvs 0x9000, otadata 0xe000, app0 0x10000, app1 0x310000 (3,145,728 bytes each), ffat 0x610000 and coredump 0xFF0000. The 5.0 app uses 2,218,416 bytes, 70.5% of its slot.

## 3. Threat or failure being fixed
- **F1 Unverifiable binaries.** No user can tell whether a published `.bin` or `.nomadfw` came from the tagged source. The GPL "matching source" promise (`LICENSING.md`) can't be checked.
- **F2 Silent drift.** A builder on core 3.3.13 or ArduinoJson 7.4 gets a different, untested firmware (README:178 calls mismatches "the single most common build failure"). The package indexes can be changed, so even a correct version number doesn't pin the bytes.
- **F3 Mislabelled signing.** A USB-C image signed as `s3-usba` passes every device check and leaves the screen dark (`NomadFirmware.h:47-48`). The packer is a private script, so nobody can review how it labels files.
- **F4 Key mistakes.** An ad-hoc keygen can print or commit a private key, or sign with a weak random nonce, which leaks the key.
- **F5 CI compromise.** If secrets sit in the build job, or actions are pinned only by tag, a hijacked action can sign whatever it likes.
- **F6 Undecodable crashes.** Without the exact ELF, the backtrace in `/api/support` cannot be decoded.
- **F7 Flash wear and confusion for self-builders.** A no-key build still erases and writes 3 MB before it refuses. Arduino's padded `merged.bin` erases the card-config FAT and the settings.

## 4. Design

### 4.1 Principles
1. Everything that changes the binary is in the tagged tree. The script passes only the board variant (`BOARD_USB_C`) and the commit id, and the commit id is derived from the tree. Release builds may not use `-DNOMAD_FW_VERSION`, `-DNOMAD_UPDATE_*` or bench flags.
2. Every download is pinned by SHA-256 before it runs.
3. Outputs contain no machine path, clock value or cached object.
4. The build job holds no secrets. Signing is a separate, deliberate step with a narrow interface (§4.6), and U decides where it runs.

### 4.2 Pinning

### 4.3 Reproducibility: causes and fixes
| Cause (evidence) | Fix |
|---|---|
| `__DATE__`/`__TIME__` in core `chip-debug-report.cpp:216`, `NomadClock.h:43`, `NomadSupport.h:252` | `SOURCE_DATE_EPOCH` = commit time (`git log -1 --format=%ct`). GCC uses it in UTC. arduino-cli passes its environment to the compiler (go-paths-helper `process.go:44-51`; builder `paths.NewProcess(b.toolEnv,…)`) |
| Absolute paths via `__FILE__`, and debug info in the ELF | `-ffile-prefix-map=<dir>=<name>` for the toolchain dir, source dir and build dir, outermost first: GCC prepends each map and uses the first match, so the **last** one given wins (`file-prefix-map.cc`). Directories are resolved with `realpath`; paths containing spaces, `=` or quotes are refused |
| ELF hash at 0xb0, image checksum, appended SHA-256 | These follow once the ELF is path-free (identical `.bin` implies an identical ELF) |
| `core.a` cached from an earlier build | `--clean` (arduino-cli `core.go:94-96` skips the archived core) |
| Host OS string and FQBN compiled in (platform.txt:105) | The canonical build host is Linux x86_64, with the FQBN fixed |
| arduino-cli version (`-DARDUINO=`, prototype generation), platform, libraries | The pins in §4.2 |
| Stray files in the sketch folder get compiled | Reproducible and release modes build from `git archive HEAD` |

ESP-IDF's own `CONFIG_APP_REPRODUCIBLE_BUILD` does the same thing (prefix maps, no dates) for IDF projects, but Arduino ships precompiled libraries with a fixed sdkconfig. Those libraries are identical for everyone who uses the same archive, so only our own compile needs these fixes.

**Verification procedure** (in the new `docs/building-and-verifying.md`):
1. `git checkout v5.0.1`
2. `tools/build.sh --release --docker --out /tmp/rebuild`
3. `cd /tmp/rebuild && sha256sum -c <release SHA256SUMS> --ignore-missing`. Every build output must match. The `.nomadfw` files don't appear in the build's sums.
4. `python3 tools/nomadfw.py verify nomad-5.0.1-s3-usba.nomadfw --image /tmp/rebuild/nomad-5.0.1-s3-usba.bin --trust firmware/JcorpNomadProject/NomadReleaseKeys.h` confirms that the signed file wraps exactly your build.
5. On the device, `/api/support` `elf` must equal `sha256sum nomad-5.0.1-s3-usba.elf`, and `build` names the commit.

**Known remaining differences:** a native macOS or Windows build differs (host OS string and toolchain binaries), so use `--docker` there. A different `SOURCE_DATE_EPOCH` changes the date strings. A dirty tree is refused in reproducible mode. `.map` files aren't shipped because they contain paths. When two builds differ, `tools/build/compare-dists.sh` prints `cmp -l | head` per file, runs `esptool image-info` on both, and suggests `diffoscope` for the ELFs.

### 4.4 `tools/build.sh`
```
tools/build.sh [--board s3-usba|s3-usbc|all] [--out DIR] [--build-dir DIR]
               [--reproducible | --release] [--docker] [--no-ota] [--expect-channel NAME]
               [--define NAME[=NUMBER]]... [--no-profile] [--print-plan]
```
- **Default (dev) mode:** builds the working tree incrementally (no `--clean`) with the profile, the maps and `SOURCE_DATE_EPOCH` applied. It is fast for `flash-nomad.sh`, and the output is not guaranteed identical. `--define` accepts only `NAME` or `NAME=<digits>` (`NOMAD_FW_DEVKEY`, `NOMAD_FW_BENCH`, `NOMAD_FW_BENCH_FAIL`), so nothing needs quoting. `--no-profile` keeps today's `NOMAD_LIBS`/installed-libraries route and labels the build "unpinned".
- **`--reproducible`:** refuses a dirty tree, exports `git archive HEAD` into `<build-dir>/src`, adds `--clean`, verifies the lock, and runs the leak, date and stamp checks. CI uses this on every push.
- **`--release`:** everything in `--reproducible`, plus no `--define`/`--no-ota`/`--no-profile`, `-DNOMAD_RELEASE=1`, a numeric version (`^[0-9]+(\.[0-9]+){1,3}$`, because `fwCompare` reads up to 4 numbers), and if `GITHUB_REF_NAME` or a tag on HEAD is `v*`, it must equal `v<stamp version>`. `--expect-channel stable` fails unless the compiled default channel is `stable`, which is 6.6's ask for main and tags.
- **`--docker`:** builds `tools/build/Dockerfile` (`FROM debian:trixie-slim@sha256:8aa5a7bf5a1955bddbe7d74fcdd0b91ab30e74362a8b73af672b0481b35b44a0` as resolved on 2026-11-26, with bash, python3, curl, ca-certificates and git) and runs the same script inside it, at `/toolchain` and `/work`, as uid 1000. The host computes the commit, `SOURCE_DATE_EPOCH` and the `git archive`, so git never runs on a mount owned by another user.

The core of the script, as a sketch:
```bash
TC=$(realpath -m "${NOMAD_TOOLCHAIN:-$HOME/.cache/nomad-toolchain}")   # arduino-cli + its data dir
export ARDUINO_DIRECTORIES_DATA=$TC/data ARDUINO_DIRECTORIES_USER=$TC/user \
       ARDUINO_UPDATER_ENABLE_NOTIFICATION=false LC_ALL=C TZ=UTC
export SOURCE_DATE_EPOCH=${SOURCE_DATE_EPOCH:-$(git -C "$REPO" log -1 --format=%ct)}
fetch_locked "$TC" < "$REPO/tools/build/toolchain.lock"   # curl, sha256sum -c, mv into staging
# the commit, for /api/support and the build stamp; a header in the build folder, never in the sketch
printf '#define NOMAD_FW_COMMIT "%s"\n' "$COMMIT" > "$B/gen/nomad_build_info.h"
MAPS="-ffile-prefix-map=$TC=/toolchain -ffile-prefix-map=$SRC=/nomad -ffile-prefix-map=$B=/build"
FLAGS="-DLV_CONF_INCLUDE_SIMPLE -I$SKETCH -I$B/gen -DBOARD_USB_C=$USBC $RELDEF $DEFINES $MAPS"
( cd "$B" && "$CLI" compile --profile nomad $CLEAN --build-path "$B/out" --warnings none \
    --build-property "compiler.cpp.extra_flags=$FLAGS" --build-property "compiler.c.extra_flags=$FLAGS" \
    --build-property "compiler.S.extra_flags=$MAPS" "$SKETCH" )   # prints "Sketch uses N bytes" for the log
```
After compiling, the script reads `runtime.platform.path`, `tools.esptool_py.path` and `build.flash_{mode,freq,size}` from `compile --show-properties=expanded`, and asserts dio, 80m, 16MB and `build.bootloader_addr=0x0` (boards.txt:1053-1057: QIO boot with a dio header, which matches `flash-nomad.sh:68`). It deletes the 16 MB `*.merged.bin` and writes the outputs. Names follow U's release-asset contract (U §4.3), `<v>` comes from the stamp, and everything is path-free:

| File | What |
|---|---|
| `nomad-<v>-<board>.bin` | app image (OTA slot, 0x10000) |
| `nomad-<v>-<board>-bootloader.bin`, `-partitions.bin`, `boot_app0.bin` | other USB parts |
| `nomad-<v>-<board>.elf` | for crash decoding; its SHA-256 equals `/api/support` `elf` |
| `nomad-<v>-<board>-merged.bin` | `esptool merge-bin`, raw, **no padding**: fresh installs. Fills 0x9000-0xDFFF with 0xFF, so **settings are erased** |
| `nomad-<v>-<board>-merged.hex` | `merge-bin --format hex`: one file that `esptool write-flash` writes **without touching NVS** (gaps stay unerased) |
| `nomad-<v>-<board>.flash_args` | `--flash-mode dio --flash-freq 80m --flash-size 16MB` plus offset/file lines, for `esptool … write-flash @file` |
| `nomad-<v>-<board>.nomadfw.unsigned` | §4.6, made with no key; U's owner step signs it |
| `build-info.json`, `SHA256SUMS` | below; sums cover every file above |

Every merge uses `--flash-mode keep --flash-freq keep --flash-size keep`.

`build-info.json` contains no paths and no wall clock, so it is reproducible too:

**Checks that fail the build:**
- `grep -aF` finds none of `$TC`, `$SRC`, `$B` or `$REPO` in the `.bin` or `.elf`.
- `date -u -d @$SOURCE_DATE_EPOCH '+%b %e %Y'` and `'+%H:%M:%S'` both appear in the `.bin`.
- `nomadfw.py info` finds exactly one stamp, with the expected board and commit.
- The image is ≤ 3,145,728 bytes, with a warning above 90%.
- No unlocked archive is in staging.

The script also writes `$B/tools.env` (paths to esptool and addr2line), outside `dist`, for `flash-nomad.sh` and `tools/build/decode-crash.py`.

**`flash-nomad.sh`** keeps its CLI. It calls `tools/build.sh --board s3-usb{a,c} --build-dir "$BUILD" --out "$BUILD/dist"` (dev mode) and flashes the four parts from `dist` with the same esptool flags as `:66-70`, taking `ESPTOOL` from `tools.env`. Profile installs no longer live at the paths hard-coded in `:46-47`.

### 4.5 Firmware changes (small; cannot be compiled here, so CI builds them)
1. **Commit and build stamp** in `NomadSupport.h`, above `supportJson()`:
```cpp
// the git commit this was built from: tools/build.sh writes nomad_build_info.h into its build
// folder (never into the sketch). An Arduino IDE build has none and says "unknown".
#if defined(__has_include)
#if __has_include("nomad_build_info.h")
#include "nomad_build_info.h"
#endif
#endif
#ifndef NOMAD_FW_COMMIT
#define NOMAD_FW_COMMIT "unknown"
#endif
// What this build is, in one string a PC can find in the .bin: tools/nomadfw.py reads it back,
// so a USB-A image can't be signed as a USB-C one by mistake, and the release tag is checked
// against it. The support file shows it, which also keeps the linker from dropping it.
static const char NOMAD_BUILD_STAMP[] = "NOMADBUILD1;board=" NOMAD_BOARD_ID ";version=" NOMAD_FW_VERSION
                                        ";channel=" NOMAD_UPDATE_CHANNEL ";commit=" NOMAD_FW_COMMIT ";";
```

```cpp
enum FwTrailerResult : uint8_t { FWT_OK = 0, FWT_NOT_OURS, FWT_SIZE, FWT_IMAGE_SHA, FWT_META_LEN,
                                 FWT_SIG_LEN, FWT_NO_KEY, FWT_BAD_SIG, FWT_META_JSON };

// t: the last 512 bytes; total: the file's size; imageSha: SHA-256 of everything before t.
// *signer: which key verified it. One mbedtls_pk_context at a time, as today.
template <typename K>
static FwTrailerResult fwParseTrailer(const uint8_t *t, uint32_t total, const uint8_t imageSha[32],
                                      const K *keys, size_t keyCount, int *signer, FwTrailerMeta *out);
```
The body is today's code. It loops `mbedtls_pk_parse_public_key`/`mbedtls_pk_verify` over the keys and returns `FWT_NO_KEY` when `keyCount == 0`. It copies board, version and channel with `snprintf` and treats any value of 24 characters or more as `FWT_META_JSON`. That is the one behaviour change: an over-long field is reported as "description unreadable", and only a key holder could produce one. I prototyped this function on the host against mbedTLS 3.6.4 and ArduinoJson 7.3.0. It accepts both upstream files, returns `FWT_BAD_SIG` for a flipped signature byte and `FWT_NO_KEY` with no keys. `fwCheckTrailer` becomes a `switch` that maps each result to the **existing** message string, then runs the board and version checks unchanged. ### 4.6 `tools/nomadfw.py` (Python ≥ 3.9 plus `cryptography`; one file; run with `python3 -I`)
| Command | Does |
|---|---|
| `keygen --name tunlezah-2026a [--dir ~/.nomad-keys] [--no-passphrase] [--dev fw\|ui]` | generates a P-256 key and writes `<name>.key.pem` (PKCS#8, AES-256, opened `O_CREAT\|O_EXCL`, mode 0600, never overwritten), `<name>.pub.der` and `.pub.pem`. It prints only the name, the id (first 8 bytes of SHA-256 over the DER, as hex: U's convention) and the full SHA-256. `--dev fw` writes an unencrypted throwaway key and `NomadFirmwareKeyDev.h`. `--dev ui` writes 6.6's `NomadUiKeyDev.h` |
| `header --format fw-single\|fw-release\|ui --pub NAME=FILE… [--placeholder] --out FILE` | `fw-single` is byte-identical to `NomadFirmwareKey.h:5-19`: rows of 12 `0x%02x`, no trailing comma, `_LEN`. I checked this by round-trip against the committed file. `fw-release` is U's `NomadReleaseKeys.h`: `NOMAD_FW_KEY0[]…`, `NOMAD_FW_KEYS[]` of `{ "name", KEYn, sizeof(KEYn) }`, `#define NOMAD_FW_KEY_COUNT n`, an id comment per key, and with `--placeholder` a 1-element dummy, count 0 and a `#warning`. `ui` is 6.6's `NomadUiKey.h` (`NomadKeyRef`, at most 2 keys, `NOMAD_UI_KEY_COUNT`, placeholder form). Every key must be a 91-byte uncompressed P-256 SPKI that loads with `load_der_public_key` |
| `keyinfo FILE` | id and SHA-256 of every key in a `.pem`/`.der`/header |
| `info APP.bin [--json]` | stamp, size and slot %, ELF SHA-256 (offset 0xb0), whether the appended digest is valid, IDF version. Standard library only |
| `pack --image APP.bin --out F (--unsigned \| SIGNER) [--channel C] [--trust H]` | builds the trailer: board and version from the stamp, channel from the stamp unless `--channel`. An image without a stamp (built before this change) needs explicit `--board`/`--version` |
| `sign IN.unsigned --out F SIGNER [--trust H] [--channel C] [--image REBUILT.bin]` | completes an unsigned file. `--image` refuses unless the image bytes equal the owner's own rebuild, so a compromised CI can't get its image signed |
| `verify F… [--trust H\|--pub FILE]… [--image BIN] [--board B] [--version V] [--json]` | mirrors `fwParseTrailer` code for code, then runs the extra checks |
| `sign-blob --in F --out SIG [--encoding der\|hex\|b64] SIGNER` | ECDSA-P256-SHA256 over the file bytes, for 6.6 and U. They define what gets signed |

`SIGNER` is one of:
- `--key PEM` (passphrase from `NOMAD_KEY_PASSPHRASE` or a prompt; the same variable works for `openssl -passin env:NOMAD_KEY_PASSPHRASE`)
- `--key-env VAR` (PEM text in a CI secret, if U chooses that)
- `--sign-cmd 'CMD … {in} … {out}'`: 6.6's convention. `{in}` is a file holding the exact bytes to sign and `{out}` receives a DER signature. It runs via `shlex.split` with no shell, in a 0700 temp dir that is then deleted. It covers `openssl dgst -sha256 -sign /abs/key.pem -out {out} {in}`, PKCS#11 tokens through `openssl dgst -provider pkcs11 -sign "pkcs11:…"`, and KMS wrappers that sign a digest and return DER.

Every signature is verified against `--trust` before anything is written (default: `NomadReleaseKeys.h` if present, else `NomadFirmwareKey.h`), and the key's name and id are printed. A local key signs with RFC 6979 deterministic nonces (`ec.ECDSA(hashes.SHA256(), deterministic_signing=True)`, available since cryptography 43, verified on 50.0.1), so the same key and image always give the same file. Older `cryptography` versions fall back to OpenSSL's random nonce and print a note. The private key is never printed, logged or put in an exception message.

**Trailer, unsigned file and checks:**
```python
TRAILER, SLOT = 512, 0x300000            # NomadFirmware.h:87; app0/app1 in app3M_fat9M_16MB
STAMP = re.compile(rb'NOMADBUILD1;board=([a-z0-9-]{1,23});version=([0-9]+(?:\.[0-9]+){1,3});'
                   rb'channel=([a-z0-9-]{1,23});commit=([0-9a-f]{12}(?:-dirty)?|unknown);\x00')
def trailer_head(image, board, version, channel):          # everything the signature covers
    meta = json.dumps({"board": board, "version": version, "channel": channel},
                      separators=(",", ":")).encode()      # same key order and bytes as upstream
    return (b"NOMADFW1" + struct.pack("<I", len(image)) + hashlib.sha256(image).digest()
            + struct.pack("<H", len(meta)) + meta)
def trailer(head, sig=b""):                                # sig b"" = .nomadfw.unsigned
    t = head + struct.pack("<H", len(sig)) + sig
    if len(t) > TRAILER: raise PackError("meta too long")
    return t + bytes(TRAILER - len(t))
```
`trailer_head` reproduces the upstream 5.0 trailer prefix byte for byte (checked). An `.unsigned` file is a complete `.nomadfw` with signature length 0. A device given one by mistake refuses it with "The firmware isn't signed." (`:172`). Before packing, `pack` and `sign` require:
- byte 0 is 0xE9, chip id 9 (ESP32-S3) at offset 12, and a valid appended digest
- more than 4,096 bytes and at most `SLOT` bytes
- exactly one stamp, whose board and version equal the meta
- board in {`s3-usba`, `s3-usbc`}, a numeric version, channel `[a-z0-9-]{1,23}`

`verify` reports the C++ codes (`not_ours`, `size`, `image_sha`, `meta_len`, `sig_len`, `no_key`, `bad_sig`, `meta_json`), then `board`, `version`, `image_header`, `digest`, `stamp` and `too_big`. Exit codes: 0 ok, 1 usage, 2 check failed, 3 signer failed. `--json` gives `{file,size,sha256,board,version,channel,signer,keyId}` for U's scripts. Dependencies: `tools/requirements-release.txt` pins `cryptography==50.0.2` and its `cffi`/`pycparser` with `--hash` lines (`pip-compile --generate-hashes`). Verifying works with any `cryptography`, including distro packages.

**PKCS#8 encryption note:** `cryptography` writes PBES2 with PBKDF2-HMAC-SHA256 at **2,048 iterations** (checked with `openssl asn1parse`), and it can't be tuned. `keygen` therefore requires a passphrase of at least 16 characters and says to use a random one from a password manager. U's custody (two encrypted copies on separate sticks) still holds.

### 4.9 Card template and card tools zips
`tools/build/detzip.py --root DIR --out F.zip [--prefix P/]` sorts entries, sets every date to `SOURCE_DATE_EPOCH` (clamped to 1980 or later), sets modes to 0644 (0755 for `*.sh`/`*.bat`), writes no extra fields and uses deflate level 9. It also writes `F.zip.files.sha256` (sorted `sha256  path` lines). Deflate output can differ between zlib builds (zlib-ng, for instance), so reproducibility is judged on the `.files.sha256` list, while the zip bytes match only inside the container. Until 6.4 moves the tools' source in, CI only records the SHA-256 and file list of `SD_Card_Template/Nomad-Card-Tools.zip` in `build-info.json`. Afterwards, CI rebuilds it from `tools/cardtools/` and fails if its file list differs from the committed zip's (U §9 asks for this).

### 4.10 Rejected alternatives
- **openssl CLI plus bash for packing:** byte layout in shell is fragile, it won't run on stock Windows, and parsing the result is harder. openssl is still accepted as a `--sign-cmd`.
- **PlatformIO or ESP-IDF builds:** a different build graph from the one users and the web flasher get, and a port of the build.
- **Keeping only a Python verifier:** it doesn't test the firmware's own code. The extracted header plus host C++ does, and the Python verifier is a second, independent implementation.
- **Padded or raw-only merged images:** padding wipes FAT and the coredump, and raw wipes NVS. The parts plus a hex file cover updates.
- **Container-only builds:** the maps make the path irrelevant, so plain Linux works too. The container is the canonical way to cross-check.
- **Signing in the tag workflow:** rejected per U's custody analysis (option A).

## 8. Compatibility, rollout and rollback
- The `.nomadfw` layout is unchanged, so older firmware accepts new files and the tools accept upstream files.
- Devices see only the new `/api/support` fields and the instant refusal on no-key builds.
- Arduino IDE builds still work (commit `unknown`).
- The `NomadClock` floor becomes the commit time in UTC instead of the builder's local time, which is more accurate.
- Roll out in §6 order. Steps 1–3 can merge before any firmware change, and step 4 needs one CI build.
- Rollback is reverting the commit. The tools and CI touch no device state, and no NVS key or card format changes.
- When moving to a newer core or library, edit `sketch.yaml`, run `lock.py`, and review the lock diff as one commit. Expect every byte to change.

## 10. Pushed to future fixes
- Byte-identical native builds on macOS and Windows. A `--build-property runtime.os=linux` override might neutralise the host string, but that is unverified.
- Building the toolchain and IDF libraries from source; Espressif's binaries remain trusted, by hash.
- SLSA or GitHub artifact attestations for the draft assets (U may adopt).
- On-device check that the incoming image's stamp matches its signed meta.
- Secure Boot, flash encryption and anti-rollback eFuses. These are irreversible, and they conflict with "anyone can put their own build on it" (`LICENSING.md`).
- Dependabot for the pinned actions.

## 11. Open decisions for the owner
- **O1 Tool language:** Python plus `cryptography` (**recommended**), or the openssl CLI.
- **O2 arduino-cli:** 1.5.1 (**recommended**), or 1.6.0 once it is a few months old.
- **O3 Canonical builder:** the Linux x86_64 container (**recommended**), with native Linux as an equal.
- **O4 Build stamp in the firmware:** yes (**recommended**). Without it, `pack` needs `--board`/`--version` typed by hand.
- **O5 Merged images:** ship `-merged.bin` and `-merged.hex`, clearly labelled (**recommended**), or parts only.
- **O6 Publish `.elf` per release:** yes (**recommended**; needed for crash decoding).
- **O7 `reproduce` job:** on every tag (**recommended**), or on manual runs only.
- **O8 Deterministic ECDSA (RFC 6979):** on (**recommended**).
- **O9 Host-test mbedTLS:** pinned v3.6.3 built from source (**recommended**), or apt's 2.28.
- **O10 Builds in CI:** both boards in one job (**recommended**, cheaper), or a matrix (faster).
- **O11 Card-tools zip:** keep the committed blob with a CI check until 6.4, then build it at release time (**recommended**).
