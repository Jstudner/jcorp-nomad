# 6.6 Signed interface updates

> **Read [README.md](README.md) first.** Its global power rules apply here, and its cross-workstream decisions override this doc where they differ: **D1** (no separate UI key: verify against U's shared `NOMAD_FW_KEYS` in `NomadReleaseKeys.h`), **D2** (the grammar line is `channels` with 1–4 names, checked against the runtime `nomadUpdateChannel()`), **D3** (`update/v1/<channel>/ui-manifest.txt` via a runtime `nomadUiManifestUrl()`, release asset `ui-manifest-<version>.txt`), **D4** (keep upstream's `#ifndef` defaults in `NomadUpdate.h` as dead code), **D5** (`nomadVerifyAnyKey` returns the matching key's index) and **D7**.

> **Summary.** Today the in-app interface updater writes whatever the admin's browser sends it.
> The browser gives the SHA-256 for each file (`NomadUpdate.h:165`, `:233`), and that hash comes from a manifest
> nobody verifies. The only thing it rests on is TLS between the phone and the update host. On top of that, every admin-page load in WiFi Mode fetches the manifest from the internet and then hashes about 40 MB of interface files on the card.
> **The fix.** The manifest becomes a signed text file. The phone only fetches it and forwards the bytes. Nomad checks
> the ECDSA P-256 signature against a public key compiled into the firmware. The check runs on a short-lived task, using the same mbedTLS
> code as the firmware updates. Nomad keeps the verified file list in PSRAM and accepts a staged file only if
> its path is in that list and the SHA-256 that Nomad computes itself matches the signed one. It commits only once every listed file is staged.
> It refuses a build older than the one it last installed, a manifest for another channel, and a manifest that needs newer firmware.
> Main builds follow the `stable` channel. "Check for updates" becomes something a signed-in admin clicks, with no automatic fetch.
> **What the user sees.** The Update card shows "Check for updates" instead of checking by itself. Afterwards it shows the signed build, its date and
> the list of changed files, as before. An update that fails verification is refused with a plain-English reason.
> The advice "re-copy the SD template instead of using the updater" can be withdrawn.

## 1. Scope (in / out)

**In:** the format of the signed UI manifest and how it is verified on the device, using `NomadSign.h`, which the firmware OTA shares. Also in:
- anti-rollback, the channel check and the minimum-firmware check
- the rewrite of the update routes and task in `NomadUpdate.h`
- deleting interface files that a release removes
- the config header `NomadUpdateConfig.h` (names only; U picks the values) and the default channel
- `admin.js`/`admin.html`: an explicit check, the new flow, and messages for old firmware
- the generator `tools/ui-manifest.py`
- the host tests in `tools/uitest/`

**Out:** where manifests and files are hosted, the URL layout, CORS on the host, the release process, key custody and the transition away from upstream's key. All of these belong to **U**. Also out: key generation, the pinned toolchain and the CI that runs the generator (**6.7**); admin token and session lifetime (**6.3**); the "no password = everyone is admin" default (**6.1**); the CORS and Host allowlist on the device (**6.5**).

## 2. Current behaviour (file:line)

- `NomadUpdate.h:34-42`: `NOMAD_FW_VERSION "5.0"`, `NOMAD_UPDATE_CHANNEL "experimental"` (also on main) and `NOMAD_UPDATE_BASE "https://nomadflash.jcorptech.net/update/v1/"`. `NomadFirmware.h:72-78` takes its base and channel from these.
- `NomadUpdate.h:46`: `NOMAD_UPDATE_MAX_FILES = 400`. **Measured on the current template:** 913 updatable files, 39.5 MB in total, 741 of them empty map glyph ranges, and 44 KB of path text. I listed them with the device's own `nomadUpdatablePath` rules compiled on the host. The hash POST caps its body at 32 KB (`:382`) and 400 paths (`:355`). If a manifest lists the whole template, the body is ignored, the hash result comes back empty, and the page re-stages all 913 files, empty ones included, one request each (`:204-228`).
- `NomadUpdate.h:161-198` `nomadStageBody`: the path, size and **sha256 are taken from the query string** (`:164-167`). The file is kept if the bytes match the *client's* hash (`:233`). `nomadUpdatablePath` (`:48-52`) is the only limit, so a signed-in admin request can put any content on any interface path.
- `NomadUpdate.h:321-331` `GET /api/update/env` answers *anyone* with the mode, firmware, channel and manifest URL.
- `NomadUpdate.h:397-419` commit holds `sdMutex` for the whole swap on the network task and feeds the WDT (`:278-280`). Every card request waits behind it.
- `NomadUpdate.h:68-117` hash task: internal 6 KB stack, internal 4 KB DMA buffer, priority 2 on core 1 (`:368`).
- `NomadUpdate.h:286-315` journal and boot recovery (`JcorpNomadProject.ino:6664`).
- `admin.js:1287` `NomadUpdate.init()` runs on every `DOMContentLoaded`. In WiFi Mode (`:1876-1881`) it fetches `env.manifest` from the internet (`:1883-1890`, no `referrerPolicy`). If a session token exists it then hashes every listed file on the card (`:1900-1905`). The manifest is trusted for `format === 1` alone (`:1891`). Files are staged with the manifest's own sha256 in the query (`:2011`). The bench override `?update=test&manifest=` is gated by `env.testMode` (`:1877-1881`). The page links to `tools/ui-manifest.py` (`:1851`), which is not in this repo.
- `NomadFirmware.h:162-193` `fwCheckTrailer`: SHA-256, then `mbedtls_pk_parse_public_key` and `mbedtls_pk_verify` against `NOMAD_FW_PUBKEY` (`NomadFirmwareKey.h:8-18`, 91-byte P-256 SPKI). It runs on `FwWriter` or `FwPull`, never on the network task. This is the model to follow.
- `NomadAuth.h:178-181`: `checkAdminAuth` returns true for everyone when no password is set (fixed by 6.1).
- `NomadGuard.h:162-171` `isInterfacePath`, `:218-236` `isCleanWritePath`, `:25-47` `canonicalPath`: these are the path rules the manifest must obey.

## 3. Threat or failure being fixed (concrete scenarios)

1. **Compromised update host or repository.** Someone gets into U's hosting account, pushes to the release files, or takes over the update domain. They publish a manifest whose `admin.js` hash matches a backdoored `admin.js`. Today every admin who clicks Update installs it, and the backdoor then runs in every later visitor's browser and in the admin's own session. *After the fix:* they also need the offline UI signing key.
2. **Rollback.** An attacker serves an *older* but genuinely signed manifest whose pdf viewer has a known script-execution bug (see 6.3). *After the fix:* Nomad refuses a build below the last one it installed (stored in NVS), unless the admin ticks "Allow older builds".
3. **Cross-channel replay.** A signed `experimental` manifest is served to a `stable` device. *After the fix:* the channel is inside the signed bytes and must equal the compiled channel.
4. **Mix-and-match or partial update.** A different file is swapped in under a listed path, or the update stops half way. *After the fix:* the device computes each file's hash and compares it with the signed one. Commit refuses until every needed file is staged.
5. **Stale vulnerable files.** A release removes a file, but the old copy stays on the card and is still served from the Nomad origin. *After the fix:* the signed manifest carries a remove list.
6. **Privacy, card wear and power.** Each signed-in admin-page load in WiFi Mode sends the phone's IP address and the Nomad's origin (as the Referer) to the update host. It then reads about 40 MB from the card. *After the fix:* nothing leaves the phone and nothing is hashed until the admin clicks.

**Not fixed here, stated so nobody over-trusts it.** Someone who holds the admin token can still write interface files through the admin file routes (`NomadGuard.h:279-286`: interface paths are admin-only, not update-only). That is 6.3's job, plus a possible "interface lock" (§10). A *freeze* attack is also not fully fixed: a host that keeps serving the last genuine manifest hides newer releases ([TUF](https://theupdateframework.github.io/specification/latest/) calls this a freeze attack). Nomad has no trusted clock, because `NomadClock.h:1-12` takes the time from phones, so manifests cannot expire. The UI shows the signed build date so the admin can compare it with the release page.

## 4. Design

### 4.1 Byte format: a signed text manifest, signature on the last line

Three options were considered:

| Option | Verdict |
|---|---|
| JSON with an embedded `sig` field (canonicalise, then verify) | **Rejected.** The device would have to re-serialise exactly as the signer did. ArduinoJson does not promise byte-identical number, escape or whitespace output. JSON with duplicate keys is undefined ([RFC 8259 §4](https://www.rfc-editor.org/rfc/rfc8259#section-4)): Python keeps the last value, and ArduinoJson's handling has changed between versions ([6.16.0 changelog](https://arduinojson.org/news/2020/08/01/version-6-16-0/)). That parser difference is a classic way round a signature check. Parsing 913 objects would also cost about 150 KB of ArduinoJson pool. |
| `manifest.json` plus a detached `manifest.sig` | **Rejected.** It takes two fetches, and a CDN can cache the two files out of step (new manifest, old signature), which causes spurious failures. The JSON parser-difference problem remains. |
| **One text file. Every byte before the last line is signed; the last line is `sig <hex DER>`** | **Chosen.** One fetch, and it is atomic. Nomad verifies the exact bytes received *before* parsing anything, so nothing is canonicalised. The parser is a strict line parser with no allocation per line, and it is simple to reimplement in Python and JS. The template's 913 files make **107,971 signed bytes**, about 13 KB gzipped (measured with a prototype generator in my scratchpad). |

A binary trailer like `.nomadfw` was not chosen. The phone has to read the list to download files, and text is easy to review in a release diff.

**Grammar.** "Format 2" keeps it distinct from the unsigned `format:1` JSON. `LF` is 0x0A. CR, TAB and NUL are refused, as is any byte outside 0x20–0x7E. Each line is at most 512 bytes.

```
"NOMADUI 2" LF
"channel " chan LF            ; [a-z0-9-]{1,24}; must equal NOMAD_UPDATE_CHANNEL
"build " u32 LF               ; 1..4294967295, decimal, no leading zero. Suggest YYYYMMDDNN (2026112601)
"version " token LF           ; <=15 chars, display only ("5.1")
"date " token LF              ; YYYY-MM-DD, display only, never used for expiry
"minfw " ver LF               ; digits and dots, <=15; firmware must be >= this
"boards " ("*" | board *(" " board)) LF    ; board = [a-z0-9-]{1,24}, <=8; matched against NOMAD_BOARD_ID
"base " token LF              ; <=200 chars; where the phone fetches files, relative to the manifest URL. Ignored by Nomad
"files " n LF                 ; 1..NOMAD_UPDATE_MAX_FILES (2048)
"removes " m LF               ; 0..NOMAD_UI_MAX_REMOVES (512)
n x ( "f " size " " sha " " path LF )   ; size decimal <= 64 MiB, no leading zero; sha = 64 lowercase hex
m x ( "d " path LF )
"end" LF
"sig " hex LF                 ; 16..144 lowercase hex = DER ECDSA-Sig-Value over SHA-256 of bytes [0, start of this line)
```

`token` is 0x21–0x7E. The **path** rules are applied identically by the device parser and the generator:
- it starts with `/`, is 2–255 bytes, and is printable ASCII (spaces allowed inside a component, e.g. `Noto Sans Medium`)
- it passes `nomadUpdatablePath()`
- `canonicalPath(p) == asciiLower(p)`, which rules out `//`, leading spaces, and trailing dots or spaces
- `f` lines are **strictly increasing by `asciiLower(path)`** compared bytewise. This catches duplicates that differ only in case, which FAT treats as the same file. `d` lines follow the same rule, and no `d` path may also be an `f` path.
- `size == 0` requires the sha of empty input (`e3b0c442…b855`)

v1 is ASCII-only, to avoid NFC/NFD path pitfalls. The generator fails loudly on anything else.

**Signature.** ECDSA P-256 over SHA-256, DER-encoded. This is exactly what `openssl dgst -sha256 -sign key.pem` produces and what `mbedtls_pk_verify(..., MBEDTLS_MD_SHA256, ...)` checks. Hex is used rather than base64 so that no decoder is needed on the device. Signatures are not reused as identifiers, so malleability does not matter.

### 4.2 Keys: a separate UI key, two slots

**Recommendation: a UI key separate from the firmware key.** The reasons:
- UI releases are more frequent, and the UI key may live closer to CI.
- A compromised UI key gives script in the browser, not code execution on the device.
- Either key can be rotated on its own.

Cross-use is impossible anyway, because the signed bytes start with `NOMADUI 2` and the firmware trailer starts with `NOMADFW1`. `NomadUiKey.h` holds **up to two** P-256 SPKI DER keys, so a successor key can ship in firmware before it signs anything. U decides custody, the values and rotation. 6.7's key tool writes the header in the same style as `NomadFirmwareKey.h`:

```cpp
// NomadUiKey.h - the public half (or halves) of the key interface updates are signed with.
// Written by the key tool (6.7). Public: commit it. Two slots so a new key can be shipped before it signs.
#pragma once
#include <stddef.h>
struct NomadKeyRef { const unsigned char *der; size_t len; };
static const unsigned char NOMAD_UI_KEY0[] = { 0x30, 0x59, /* ... 91 bytes ... */ };
static const NomadKeyRef NOMAD_UI_KEYS[] = { { NOMAD_UI_KEY0, sizeof(NOMAD_UI_KEY0) } };
static const int NOMAD_UI_KEY_COUNT = 1;
// until U has made a key: static const NomadKeyRef *const NOMAD_UI_KEYS = nullptr; static const int NOMAD_UI_KEY_COUNT = 0;
```

Bench builds use `-DNOMAD_UI_DEVKEY=1`, which includes `NomadUiKeyDev.h` (not committed, made by 6.7's tool). This mirrors `NOMAD_FW_DEVKEY` (`NomadFirmware.h:41-45`).

### 4.4 Shared verification: `NomadSign.h`

There is one verifier for firmware and UI. `fwCheckTrailer` (`NomadFirmware.h:176-180`) is refactored to call it, so both use "the same verification code path". A host backend lets `tools/uitest` run the identical call sites:

```cpp
// NomadSign.h - SHA-256 and ECDSA P-256 checks, for firmware (NomadFirmware.h) and interface updates.
#pragma once
#if NOMAD_SIGN_HOST_OPENSSL          // tools/uitest: same API on a PC, backed by OpenSSL
  ... nomadSha256 = SHA256(); nomadP256Verify = d2i_PUBKEY + EVP_PKEY_verify, returns 0 when good
#else
#include <mbedtls/sha256.h>
#include <mbedtls/pk.h>
static void nomadSha256(const uint8_t *p, size_t n, uint8_t out[32]) { mbedtls_sha256(p, n, out, 0); }
// 0: the signature is good. Only an EC P-256 key is accepted (belt and braces: the keys are compiled in).
static int nomadP256Verify(const unsigned char *key, size_t keyLen, const uint8_t hash[32],
                           const uint8_t *der, size_t derLen) {
  mbedtls_pk_context pk;
  mbedtls_pk_init(&pk);
  int rc = mbedtls_pk_parse_public_key(&pk, key, keyLen);
  if (rc == 0 && (mbedtls_pk_get_type(&pk) != MBEDTLS_PK_ECKEY || mbedtls_pk_get_bitlen(&pk) != 256)) rc = -1;
  if (rc == 0) rc = mbedtls_pk_verify(&pk, MBEDTLS_MD_SHA256, hash, 32, der, derLen);
  mbedtls_pk_free(&pk);
  return rc;
}
#endif
static bool nomadVerifyAnyKey(const NomadKeyRef *keys, int n, const uint8_t hash[32], const uint8_t *der, size_t derLen) {
  for (int i = 0; i < n; i++) if (nomadP256Verify(keys[i].der, keys[i].len, hash, der, derLen) == 0) return true;
  return false;
}
```

### 4.5 Parser and policy: `NomadUiManifest.h` (pure, host-testable like `NomadGuard.h`)

This header uses no card and no server, and works on plain `const uint8_t*` and `size_t`. Paths are checked by building a `String` and calling the guard functions; the host test builds it against `tools/guardtest`'s `String` stand-in. Move `nomadUpdatablePath` (`NomadUpdate.h:48-52`) here unchanged.

```cpp
static const size_t   NOMAD_UI_MANIFEST_MAX = 384 * 1024;   // ~3,500 files of headroom
static const uint16_t NOMAD_UPDATE_MAX_FILES = 2048;        // was 400: the template has 913
static const uint16_t NOMAD_UI_MAX_REMOVES   = 512;
static const uint32_t NOMAD_UI_FILE_MAX      = 64UL << 20;
enum NomadUiErr : uint8_t { UI_OK, UI_E_SIZE, UI_E_NOSIG, UI_E_SIG, UI_E_FORMAT, UI_E_PATH, UI_E_ORDER,
                            UI_E_CHANNEL, UI_E_OLDER, UI_E_FIRMWARE, UI_E_BOARD, UI_E_NOKEY };
struct NomadUiFile { uint32_t path; uint16_t pathLen; uint8_t state; uint8_t isNew; uint32_t size; uint8_t sha[32]; }; // 44 B
struct NomadUiDel  { uint32_t path; uint16_t pathLen; uint8_t present; uint8_t pad; };                              // 8 B
struct NomadUiHeader { char channel[25]; uint32_t build; char version[16], date[16], minfw[16], boards[200];
                       uint16_t nFiles, nRemoves; size_t bodyAt; };
enum : uint8_t { UI_F_SAME = 0, UI_F_NEED = 1, UI_F_STAGED = 2 };

// 1. Before anything is trusted: the last line must be "sig <hex>". Returns the signed length.
NomadUiErr nomadUiSplit(const uint8_t *b, size_t n, size_t *signedLen, uint8_t der[72], size_t *derLen);
// 2. (caller) nomadSha256(b, signedLen) and nomadVerifyAnyKey(NOMAD_UI_KEYS, ...). Nothing else is parsed until it passes.
// 3. Header in the fixed order of 4.1, each key once, nothing unknown.
NomadUiErr nomadUiParseHeader(const uint8_t *b, size_t signedLen, NomadUiHeader *h);
// 4. Body, into caller-allocated arrays (PSRAM on the device). Writes '\0' over each path's LF
//    (safe: the signature is already checked), so a path is (char*)b + e.path.
NomadUiErr nomadUiParseBody(uint8_t *b, size_t signedLen, const NomadUiHeader *h, NomadUiFile *f, NomadUiDel *d);
// 5. Policy. installed = last build this Nomad installed (0 = none).
NomadUiErr nomadUiPolicy(const NomadUiHeader *h, const char *channel, const char *fw, const char *board,
                         uint32_t installed, bool allowOlder);  // build >= installed unless allowOlder
int nomadUiVerCmp(const char *a, const char *b);               // the same rule as fwCompare (NomadFirmware.h:119-130)
```

The parser checks every rule in 4.1 and also these:
- `files`/`removes` counts equal the number of lines
- `end` is followed by nothing but the signature line (the cursor reaches `signedLen` exactly)
- every number fits its range, with no leading `+`, `-` or zero

Equal builds are accepted, so reinstalling or repairing the same build works.

### 4.6 Device flow and routes (`NomadUpdate.h` rewrite)

State lives in one `static UpdState g_upd`. Phase changes are guarded by a `portMUX`. The big arrays are in PSRAM (`heap_caps_malloc(..., MALLOC_CAP_SPIRAM)`, never with an internal fallback) and are freed on done, abort, failure or a lazy drop.

```cpp
enum UpdPhase : uint8_t { UPD_IDLE, UPD_VERIFYING, UPD_HASHING, UPD_READY, UPD_COMMITTING, UPD_DONE, UPD_FAILED };
struct UpdState {
  volatile UpdPhase phase = UPD_IDLE;
  uint8_t *text = nullptr; size_t textLen = 0;        // PSRAM: the verified manifest, paths point into it
  uint8_t *incoming = nullptr; size_t incomingLen = 0;// PSRAM: a POSTed manifest waiting for the task
  NomadUiHeader hdr; NomadUiFile *files = nullptr; NomadUiDel *dels = nullptr;
  volatile uint16_t done = 0, total = 0;
  bool older = false; uint32_t installed = 0;
  String result;            // JSON for GET /api/update/check, written by the task before the phase changes
  uint32_t lastUse = 0;     // millis(): lazy drop after NOMAD_UPD_IDLE_MS (60 min), checked on the next request
  int inFlight = 0;         // stage requests receiving right now (network task only)
};
```

| Route | Who | What |
|---|---|---|
| `GET /api/update/env` | **admin** (was anyone) | `{"mode","firmware","channel","manifest":NOMAD_UI_MANIFEST_URL,"uiFormat":2,"keys":NOMAD_UI_KEY_COUNT,"installed":{"build","version"}\|null,"phase"}` plus `"testMode":true` on bench builds |
| `POST /api/update/manifest[?older=1]` | admin | Raw body, ≤ 384 KB, collected into PSRAM by the body callback (the pattern of `:377-393`, but `MALLOC_CAP_SPIRAM` only and no `malloc` fallback). Returns 409 if a job is running or `inFlight > 0`; 503 if the memory is not there (below); 202 if accepted. Starts `JOB_CHECK`. |
| `GET /api/update/check` | admin | `{"state":"verifying"}`; `{"state":"hashing","done","total"}`; `{"state":"ready","build","version","date","channel","files":N,"changed":[i...],"added":[i...],"remove":[j...],"bytes":B,"installed"}`; `{"state":"committing","done","total"}`; `{"state":"done","replaced","removed","failed":[paths]}`; `{"state":"failed","code":"sig\|format\|path\|channel\|older\|firmware\|board\|nokey\|card\|memory","error":"<plain English>"}` |
| `POST /api/update/stage?i=I&path=P` | admin | Allowed only in `UPD_READY`. `I` is the index of the `f` line. `P` must equal that entry's path byte for byte, which catches a page that parsed the manifest differently. `Content-Length` must equal the *signed* size. Nomad writes `entry.path + ".nomad-new"`, using the **manifest's** spelling of the path, and hashes as the bytes arrive (the existing per-chunk code, `:193-197`). When the request ends it runs `memcmp(digest, entry.sha, 32)`. A match marks the entry `UI_F_STAGED` and answers 200 `{"staged":k,"need":n}`. A mismatch deletes the file and answers 422. An empty entry answers 200 and writes nothing, because the commit creates empty files. The client's `size`/`sha256` params are gone. |
| `POST /api/update/commit` | admin | Needs `UPD_READY`, `inFlight == 0`, and every entry that is `NEED` with size > 0 now `STAGED`. Otherwise 409 `{"error":"not all staged","missing":n}`. Starts `JOB_COMMIT` and answers 202. |
| `POST /api/update/abort` | admin | Not allowed while verifying, hashing or committing. If anything is staged it starts `JOB_ABORT`, which removes the `.nomad-new` files; otherwise it frees inline. Answers 200. |
| `POST/GET /api/update/hash` | — | **Removed** (replaced by the check job). |

All the mutating routes use `nomadUpdAdmin(r)`, which is `checkAdminAuth(r)` and, until 6.1 lands, `&& isAdminAuthRequired()`. That way nothing can be installed through the updater on a Nomad with no password (see §11).

**Memory pre-check** (in the manifest and commit handlers, before a task is created):
- refuse with 503 ("Nomad is short of memory right now; try again when fewer films are playing") if `heap_caps_get_free_size(MALLOC_CAP_INTERNAL) < 40 KB + 16 KB`
- refuse the same way if `heap_caps_get_largest_free_block(MALLOC_CAP_INTERNAL) < 9 KB`

**The worker.** It is one short-lived task per job, made with `xTaskCreatePinnedToCore(nomadUpdTask, "updWork", 8192, (void*)job, 1, NULL, 1)`:
- **Internal stack**, because it writes NVS at the end of a commit (cache off), like `FwWriter` (`NomadFirmware.h:232-235`).
- **Priority 1**, below `StreamingTask`, which is priority 2 on core 1 (`JcorpNomadProject.ino:8492`). So the CPU-bound ECDSA step never competes with streaming.
- The work happens in `nomadUpdWork(job)`, so every local is destroyed before `vTaskDelete(NULL)`. This is the existing idiom (`NomadUpdate.h:68-69`).

`JOB_CHECK`:
1. If an earlier manifest left files staged, remove their `.nomad-new` files (taking the lock per file), then free the old arrays.
2. Take ownership of `incoming`.
3. `nomadUiSplit` → `nomadSha256` → `nomadVerifyAnyKey`. If `NOMAD_UI_KEY_COUNT == 0`, fail with `nokey`. Time this with `esp_timer_get_time()` and log `[Update] signature checked in N ms`.
4. `nomadUiParseHeader`, then allocate `files[nFiles]` and `dels[nRemoves]` in PSRAM, then `nomadUiParseBody`.
5. Read `Preferences("nomadui", ro)` `"build"` to get `installed`, then call `nomadUiPolicy(hdr, NOMAD_UPDATE_CHANNEL, NOMAD_FW_VERSION, NOMAD_BOARD_ID, installed, older)`.
6. Hash each entry. Use the existing loop from `:70-117`: internal 4 KB DMA buffer, `sdMutex` per read, `vTaskDelay(1)` every 256 KB. **Skip the read** when the file is missing (`added`) or its size differs from the signed size (`changed`). Empty entries need only the size. Each `d` path is checked with `SD_MMC.exists`.
7. Build `result` (indexes, not paths: about 4.5 KB even when all 913 files are needed). Set the phase to `READY`, or to `FAILED` with a reason, then exit.

`JOB_COMMIT`:
1. Create an empty `.nomad-new` for every `NEED` entry of size 0 and mark it staged. This saves the 741 requests the current flow makes.
2. Write the journal (below).
3. `nomadSwapIn` each staged path, taking `sdMutex` **per file** rather than for the whole commit as `:402-412` does. Run `vTaskDelay(1)` every 16 files.
4. Remove each `d` path that is present.
5. Delete the journal.
6. If nothing failed: `Preferences("nomadui").putUInt("build", hdr.build)` and `putString("ver", hdr.version)`. That is one NVS write per successful update.
7. `webLogf("success", "Interface build %u installed: %d replaced, %d removed")`, free the PSRAM tables, set `DONE`.

`JOB_ABORT` removes the staged `.nomad-new` files and frees everything.

**Journal** (`NomadUpdate.h:286-315`): lines are `/path` (swap in, as now) or `-/path` (delete). `nomadUpdateRecover` gains one branch: for `-` + an updatable path, remove the path and its `.nomad-old`. Old firmware skips `-` lines because they fail `nomadUpdatablePath`, so a firmware rollback in the middle of a recovery is harmless.

**Anti-rollback store: NVS** (namespace `nomadui`, keys `build` (u32) and `ver`). The card is the alternative and was rejected because the file routes can reach it. NVS also does not travel with a card that is moved between devices, and the "Allow older builds" tick covers that rare case. Wear is one write per successful update, so a few writes a year.

**Lazy drop, with no timer.** Every `/api/update/*` handler first calls `nomadUpdTouch()`. If the phase is `READY`, `DONE` or `FAILED`, `inFlight == 0`, and `millis() - lastUse > 60 min`, it drops the state (using `JOB_ABORT` if anything is staged). The ~155 KB of PSRAM is otherwise held until the next update action or a reboot, which is harmless.

**Races closed.** A new manifest, an abort or a commit is refused while a stage request is in flight (`inFlight`, incremented at body index 0 and decremented in `nomadStageDrop`). This stops the old tables being freed under an open stage request. Handlers read `files[]` only in `READY`, which the task sets last, inside the critical section.

### 4.7 Web UI (`admin.js` 1847-2053, `admin.html` 1045-1053)

- **No outside fetch on load.** `init()` (still called at `:1287`) calls `adminFetch('/api/update/env')`, and only when `adminToken` is set. It then draws the card: "Interface build N (installed by this Nomad)", or "not installed by this Nomad yet". It also draws a **Check for updates** button (`#update-check`) and an "Allow older builds" checkbox (`#update-older`) under it.
  - In hotspot mode the button is disabled, with the title "Needs WiFi Mode on a network with internet", unless `env.testMode` and `?update=test`.

The default `strict-origin-when-cross-origin` policy would send the Nomad's origin to the host ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Referrer-Policy)).

  - Poll `/api/update/check` every 500 ms ("Checking signature…", "Checking files… n of m").

  - Require the parsed count to equal `files`. Build `pending` from `changed` and `added`, which are indexes into the parsed list.
  - Render as `render()` does today, adding the build date and "N file(s) will be removed".

  1. Skip size-0 entries.
  2. The query becomes `i=${i}&path=${encodeURIComponent(f.path)}`, without size or sha.
  3. Commit gets a 202, then the page polls until `done`. It then refreshes the replaced files' cache and reloads (keep `:2048-2051`).
- Add a **Cancel** button for `/api/update/abort`.
- File downloads use `credentials:'omit'` and `referrerPolicy:'no-referrer'`.
- Keep `fileUrl()` (`:1985-1990`), using `base` from the manifest.
- Keep the bench `?manifest=` override for bench builds only. It is now harmless, because the device verifies.

### 4.8 Generator: `tools/ui-manifest.py`

It needs only the Python 3.8+ standard library and the `openssl` CLI. Run it with `python3 -I`.

```
python3 -I tools/ui-manifest.py --template SD_Card_Template --channel stable --build 2026112601 \
   --version 5.1 --min-firmware 5.1 [--date YYYY-MM-DD] [--boards '*'] [--base files/] \
   [--previous old/ui-manifest.txt] [--removed tools/ui-removed.txt] \
   (--key key.pem | --sign-cmd 'cmd {in} {out}' | --unsigned) \
   [--trust firmware/JcorpNomadProject/NomadUiKey.h] [--copy-files] --out dist/ui
```

- **File selection** mirrors `nomadUpdatablePath`:
  - root files that have an extension and do not start with `.`
  - everything under `assets/` and `EmulatorJS/`
  - skip any component that starts with `.` (`.DS_Store`) and `*.nomad-new`/`*.nomad-old`
  - **fail** on any path that is not ASCII, looks like a `~N` alias, is not canonical, or is over 255 bytes
- **Sorting:** `sorted(paths, key=lambda p: p.lower())`, with the files read in binary.
- **`--date`** defaults to `SOURCE_DATE_EPOCH`, then the template's last git commit date. The body is then reproducible from the tree plus the arguments (6.7).
- **Removes** are the union of `tools/ui-removed.txt` (a new, cumulative file: one path per line, `#` comments) and, with `--previous`, every previous path that has gone. With `--previous` the generator also refuses unless `build > previous build`.
- **Signing:** `openssl dgst -sha256 -sign key.pem -out sig.der body`, or a 6.7/U `--sign-cmd` wrapper for a CI secret or a hardware token. The result is `body + b"sig " + der.hex().encode() + b"\n"`.
  - **Self-check:** it then parses its own output with the same grammar. If `--trust` is given, it pulls the DER bytes out of `NomadUiKey.h`, writes PEM, and runs `openssl dgst -sha256 -verify`. It refuses to write a manifest that the shipped firmware would reject.
- **Outputs:** `ui-manifest.txt`; `files/<path>` (with `--copy-files`, the layout `base files/` expects); and a printout of the file count, total bytes and the SHA-256 of the body.
- **Also** add `tools/ui-manifest.py serve DIR --port 8981`. It is a bench-only static server with `Access-Control-Allow-Origin: *`, for the `?update=test` flow.

## 5. Power, memory and performance budget

| Resource | Idle (no update) | Check (verify and hash) | Ready (waiting for the phone) | Commit |
|---|---|---|---|---|
| Internal RAM | +~250 B .bss (`g_upd`); the old hash `String`s are gone | 8 KB task stack + 4 KB DMA buffer + mbedTLS ECP bignums (estimate 2–4 KB: mbedTLS allocates internal RAM, because `MBEDTLS_INTERNAL_MEM_ALLOC` is the [IDF default](https://github.com/espressif/esp-idf/blob/v5.5/components/mbedtls/Kconfig) and the Arduino [lib-builder](https://github.com/espressif/esp32-arduino-lib-builder/blob/release/v5.5/configs/defconfig.common) doesn't override it) + short per-path `String`s. Peak ≈ 16 KB for ~5–10 s | 0 | 8 KB stack for ~5–30 s |
| PSRAM | 0 | 108 KB text + 913 × 44 B = 40 KB table + ~5 KB result ≈ **155 KB** (worst case 384 KB + 90 KB) | the same, until done, abort or a 60-min lazy drop | the same, freed at the end |
| CPU | 0 | One ECDSA P-256 verify. ESP32-S3 has no ECC block. IDF tests ECDSA timing only on ECC-hardware chips ([perf targets](https://github.com/espressif/esp-idf/blob/v5.5/components/idf_test/include/esp32s3/idf_performance_target.h)), and `MBEDTLS_ECP_FIXED_POINT_OPTIM` is off by default (Kconfig). CycloneCRYPTO measures 60–66 ms on the S3 ([Oryx](https://www.oryx-embedded.com/benchmark/espressif/crypto-esp32-s3.html)). Unverified forum reports put mbedTLS on the original ESP32 at about 0.9–2 s ([esp32.com](https://esp32.com/viewtopic.php?p=93602)). **Budget ≤ 2 s at priority 1, then measure.** SHA-256 runs in hardware at ≥ 90 MB/s (IDF S3 threshold), so hashing is card-bound. | 0 | rename-bound |
| Card | 0. *Saved:* the ~39.5 MB read that every signed-in WiFi-Mode admin-page load used to do | Reads only same-size files: ≤ 39.5 MB at roughly 5–10 MB/s (4-bit, 40 MHz) ≈ 4–8 s. Missing or resized files are not read | 0 | Same writes as today (staged files, renames, journal) + removes |
| Flash / NVS | +~8 KB code (estimate), −~2 KB from the old hash routes, +91–182 B of keys | 1 NVS read | — | **1** NVS write per successful update |
| Radio | No device-initiated traffic; no TLS on the device | The phone fetches ~108 KB (≈13 KB gzipped) | The phone downloads files | — |
| Per request | Non-update requests: 0 | — | stage: a bounds check + `strcmp` + the existing per-chunk SHA | — |
| Screen / LED | none | none | none | none |

**How to measure on the device:**
- Note `memLow` and `dmaFree` (`/api/health`, `JcorpNomadProject.ino:8335`) and `mem.psramMin` (`/api/support`, `NomadSupport.h:273-274`) before and after a check, with and without 3 films streaming.
- Serial lines: `[Update] signature checked in N ms`, `[Update] hashed F files (M MB) in T ms`, and `[Update] updWork stack left N` (from `uxTaskGetStackHighWaterMark`). If the stack has more than 3 KB spare, shrink it to 6 KB.
- Use the admin Card check MB/s figure to sanity-check hash time.
- A USB power meter over a check should show no step beyond a normal page load plus card reads.

## 7. Tests and acceptance criteria

**Host tests** (`bash tools/uitest/run.sh`, needs `c++`, `python3`, `openssl` and `libssl-dev`; 6.7 adds it to CI next to `tools/guardtest/run.sh`):
- **H1 golden.** Make a P-256 key in a temporary directory, run the generator on `SD_Card_Template`, then:
  - the C++ test runs split → verify (OpenSSL backend) → header → body → policy (`stable`, fw `5.1`, board `s3-usba`, installed 0), and it must give `UI_OK`
  - `files` must equal the number of updatable paths (913 today, computed by the test from the tree)
  - every empty entry must carry the empty sha
- **H2 tamper.** Flip one byte at a time in the magic, the channel, the build, a size, a sha, a path and the signature; append a byte after the sig line; sign with a second key. All must fail with `UI_E_SIG` or `UI_E_NOSIG`.
- **H3 structure.** Each crafted body is *validly signed* by the run-time key and must be refused:
  - CRLF line endings, a TAB, a NUL, a byte ≥ 0x7F, a line over 512 bytes, a missing final LF
  - headers out of order or repeated, an unknown header, `files` count wrong
  - unsorted entries, a case-only duplicate (`/Admin.js` and `/admin.js`)
  - a `d` path equal to an `f` path
  - refused paths: `/config/x`, `/.system-theme.json`, `/Movies/a.mp4`, `/assets/../config`, `/SYSTEM~1.JSO`, `/assets/a./b.js`, `//admin.js`, `/assets/x.js.nomad-new`
  - size 0 with a wrong sha, size over 64 MiB, a build with a leading zero, a build of 0, a build over u32
  - more than 2048 files, a sig of odd length, uppercase hex in the sig
- **H4 policy.** Check each case:
  - wrong channel → `CHANNEL`
  - build < installed → `OLDER`, and the same with `allowOlder` → OK
  - build == installed → OK
  - `minfw 5.2` on 5.1 → `FIRMWARE`
  - `boards s3-usbc` on `s3-usba` → `BOARD`
  - `boards *` → OK
  - check that `nomadUiVerCmp` agrees with `fwCompare` on a table of version pairs
- **H5 mbedTLS parity (optional).** `NOMAD_HOST_MBEDTLS=1 run.sh` links the system mbedTLS (`libmbedtls-dev`) instead of OpenSSL, to run the identical `mbedtls_pk_verify` call.
- `bash tools/guardtest/run.sh` still passes after the `host_string.h` move.

**On-device manual script** (bench build `-DNOMAD_BENCH=1 -DNOMAD_UI_DEVKEY=1`, WiFi Mode; copy the token from the browser's network tab; `M` is a manifest made with the dev key):
1. `curl -H "X-Admin-Token: $T" --data-binary @M -H 'Content-Type: application/octet-stream' http://nomad.local/api/update/manifest` gives 202. Poll `/api/update/check` and expect `ready` with sensible `changed`/`added`. The serial log shows the verify time and the stack left.
2. A one-byte-tampered `M` gives `failed`/`sig`. A validly signed `channel experimental` gives `channel`. A build below the installed one gives `older`, and with `?older=1` gives `ready`. `minfw 9.9` gives `firmware`.
3. Stage `i=0` with the bytes of file 1 → 422. `path` not equal to entry 0's path → 409. An index out of range → 409. Content-Length different from the signed size → refused. Stage before `ready` → 409.
4. Commit with one file unstaged → 409 `missing:1`. Stage the rest, commit → 202, then `done`. The card files match. `/api/update/env` `installed.build` equals the build. The `d` paths are gone.
5. Fresh-card case: delete `/assets/maps/fonts`, check and update from the phone. The empty glyph files reappear without 741 stage requests (count them in the browser's network tab).
6. Power cut mid-commit (bench `g_benchUpdGapMs`, `NomadUpdate.h:262-267`): after reboot the log reports "an interface update was cut short", files are consistent, and deletes are finished.
7. Run check and update while 3 phones stream films. No film stalls longer than its buffer, `memLow` stays ≥ 40 KB, `/api/support` shows no new resets, and `/api/health` `counts.busyCard` rises no more than it does during a normal admin session.
8. Abort after staging some files: the `.nomad-new` files are gone. Lazy drop (bench constant set to 1 min): PSRAM comes back (`psramFree`).
9. Privacy: with Safari Web Inspector or desktop devtools, loading `admin.html` in WiFi Mode makes **zero** requests to the update host. After "Check", the requests carry no `Referer` and no cookies.
10. Hotspot mode: the button is disabled and nothing is fetched. Old `admin.js` on new firmware: no card and no console errors beyond the 401. New `admin.js` on 5.0 firmware: the "update firmware first" message, and no `/api/update/stage` calls.

**Regression:**
- **R1:** firmware OTA. Uploading a valid `.nomadfw` installs. A tampered one gives "The signature doesn't check out". A pull still works.
- **R2:** streaming, the admin page, uploads, the file manager and chat are unaffected.
- **R3:** older iPhones (iOS 12 Safari): the check and update complete.

**Acceptance criteria:**
- The device refuses any file whose bytes do not hash to the signed sha for its path.
- No path outside the signed list can be written through `/api/update/*`.
- No commit happens until all needed files are staged.
- Older builds are refused unless ticked. The channel and `minfw` are enforced.
- `/api/update/env` and every mutating route need an admin.
- No outside request is made before the admin clicks "Check".
- Main builds report `channel: stable`.
- The signature verify runs off the network task and takes ≤ 2 s.
- Internal RAM peak ≤ 16 KB during a check. PSRAM is freed after done or abort.
- One NVS write per successful update.
- All host tests pass.

## 8. Compatibility, rollout and rollback

- **Rollout (first fork release with 6.6):**
  1. U publishes the UI public key in `NomadUiKey.h`.
  2. The firmware ships with it.
  3. The template ships with the new `admin.js`.
  4. U publishes the signed `ui-manifest.txt` and files at `NOMAD_UI_MANIFEST_URL`.
  5. The release notes say: "after updating firmware, copy the new SD template once. From then on use Check for updates."
- Upstream cards and devices on firmware 5.0 keep pointing at upstream's host (`NomadUpdate.h:41`). The fork cannot change that; the fork's README tells them to move to the fork's firmware first.
- **UI rollback = roll forward.** U republishes the old files under a *new, higher* build number, so no device needs "Allow older". "Allow older builds" stays as an escape hatch for an admin.
- **Firmware rollback** (OTA auto-rollback to an older image): the new `admin.js` sees no `uiFormat` and refuses to update. A `-` journal line left for old firmware is skipped safely. The `nomadui` NVS namespace is ignored by old firmware.
- **Disable switch:** `NOMAD_UI_KEY_COUNT 0` builds a firmware that refuses all UI updates (`nokey`) without other changes.

## 10. Pushed to future fixes

- **Offline signed bundle** (one `.nomadui` file with the manifest and files), uploaded the way `.nomadfw` is, for hotspot-only owners.
- **Interface lock:** admin file routes refuse interface paths unless a "developer mode" toggle is on, so only signed content can become the UI. This would close the token-theft persistence route left by 6.3.

## 11. Open decisions for the owner

1. **Separate UI key or the firmware key?** *Recommend separate, with two slots* (4.2).
2. **Format.** *Recommend the signed text file* (4.1) over JSON plus a detached signature.
3. **Where to store anti-rollback.** *Recommend NVS* `nomadui/build` (one write per update) over a card file.
4. **Check button in hotspot mode.** *Recommend WiFi Mode only*, as today.
5. **Require a set admin password for the update routes until 6.1 lands.** *Recommend yes.*
6. **"Allow older builds" checkbox.** *Recommend keeping it*, unticked by default and logged.
7. **Custom manifest URL in production builds.** *Recommend no.* It stays bench-only, and rollback is done by rolling forward.
8. **Delete files a release removes** (`removes`). *Recommend yes*, using an explicit cumulative list, never pruning unknown files (owners keep their own root files).
9. **Lazy-drop timeout.** *Recommend 60 min.*
10. **A firmware-embedded "rescue" update page for cards with the old `admin.js`.** *Recommend no* (it costs about 10 KB of flash). Use a one-time template copy instead.
